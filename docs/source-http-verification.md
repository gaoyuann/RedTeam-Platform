# 源码发现的 HTTP 验证第一版

本版复用平台已有的逐漏洞执行器，连接源码发现、保存的载荷、验证输入、实际 HTTP 请求和结果证据。它只验证指定响应差异，不将请求成功解释为漏洞利用成功。现有 CScan 扫描、Assistant 收集和 Python 改写仍保留。

本地生成程序另已接入 Python/C/C++ 隔离执行，见 [载荷与本地验证执行](source-code-execution.md)。本文“未接入本地程序/脚本”的限制专指这条面向真实部署入口的 HTTP 验证路径；本地模拟结果不代替真实目标结果。

## 用户操作

1. 从扫描发现列表选择漏洞，打开逐漏洞测试窗口。
2. 在“漏洞与测试”页点击“设置测试入口”，设置靶场程序的 HTTP/HTTPS 运行入口及部署版本。源码下载地址不是程序运行入口；地址必须已在任务授权范围内。缺少执行环境的原因显示在准备按钮附近。本地 C/C++、TCP 或任意脚本的验证执行尚未接入，不能通过填写一个 HTTP 地址代替。
3. 点击“准备本次测试”（也可展开“高级设置：方案与载荷”后点击“生成本漏洞验证载荷”）。优先向模型提供本漏洞已保存的载荷；没有时根据源码发现的证据生成。此过程无需等待 Assistant 收集成功，也不请求测试目标。
4. 页面展示已保存的正常对照请求、验证请求、预期响应特征、生成依据、版本和来源。缺少条件时直接显示缺少什么，不生成占位请求。
5. 点击“开始测试”，核对本次目标及操作。执行器发出两次请求，结果在“测试结果与历史”中查看。

用户不需要审查代码后手工判定成功，但仍需提供真实运行入口、版本并确认测试范围。模型不能保证每条源码发现都能生成可用输入；不能支持的发现会保留具体缺失条件。

## 接口与实际执行位置

- `POST /api/pipelines/:id/verifications/:verificationId/source-runtime`：`expected_revision`、`runtime_target`、`runtime_version`。保存到当前扫描的参数；同一扫描有活动验证时拒绝修改。
- `POST .../source-payload`：`expected_revision`。调用已配置的结构化模型，传入本漏洞证据和已保存载荷；保存带版本及指纹的计划。既有 `/prepare` 保留兼容旧客户端。
- `POST .../start`：继续使用现有确认、版本指纹和请求去重规则。
- 执行链：`findingVerificationRunner → executionEngine → target-request`。工具在当前平台后端进程所在机器运行，不在 Qt 客户端、不在 CScan Assistant 中执行。云端后端可访问的靶场不一定能被本地后端访问；Cloudflare 登录本身不会为本地后端建立靶场网络路由。
- 结果沿用 `finding_verification_attempts`、`execution_steps`、`evidence_records`、`finding_verification_assessments`，冻结的输入保存在 `finding_verification_plans.content.source_payload`。查看已保存输入与历史结果不需要重新连接 CScan。

扫描及原始载荷收集仍依赖 CScan/PentAGI；这一版的输入生成依赖配置的模型服务，执行及判定不调用 PentAGI。已有任意脚本不会直接执行，而是适配成当前执行器支持的请求。

## 判定、失败和限制

- 只接受同源、授权范围内的 GET/HEAD/POST；请求参数有长度限制，每次请求超时 10 秒、响应上限 64 KiB，计划总时限 30 秒，每漏洞最多 3 次尝试。保存新计划不重置次数。
- 完整正常响应不含指定特征，而完整验证响应包含该特征：**指定响应差异已复现**。两次完整响应均不含：**本次未复现**。
- 对照也含特征、连接失败、超时、非完整响应、认证失败或证据关联不符：**证据不足**。不把退出码 0 或 HTTP 200 当成安全影响成立。
- 运行入口、版本或源码发现变化后，旧输入不能继续执行。生成时也检查并发修改；重复执行请求沿用原尝试，不重复发起调用。失败保留原载荷和历史结果。
- 不支持原生 C/C++ 程序启动、任意 Python 执行、多阶段登录/清理、浏览器脚本执行或蓝屏演示。本版也不能凭 HTTP 文本证明 XSS 已在浏览器执行、内存破坏或远程代码执行。
- 模型输出的判据仍可能不适合真实漏洞。自动结果只对应页面明确展示的响应差异目标，不能外推成完整漏洞验证结论。

## 验证

`backend/test/source-verification-preparation.test.js` 使用内存数据库、固定模型回复和真实本地 HTTP 服务，覆盖无载荷生成、已有载荷适配、实际执行、正负结果、失败、证据拒绝、版本失效、尝试上限和重复请求。固定模型回复不是线上模型质量验收。

`npm run test:source` 覆盖源码扫描和收集回归；`node --test test/finding-verification.test.js` 覆盖既有执行流程（包括超时/取消）；Qt 检查 `ui-finding-payload-artifacts` 验证入口可见与兼容旧发现。真实靶场验证另行针对明确授权的运行入口开展。
