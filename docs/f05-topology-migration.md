# F05 拓扑探测与节点操作：本地实现说明

## 数据与关系

- 拓扑仍从当前任务的扫描结果按需投影，复用 F04 的任务扫描归属规则；F03 的 `task_assets`、`task_services`、`task_entries`、`task_checks` 为节点补充稳定资产 ID、服务、入口与检查状态。只有资产清单但没有扫描结果的主机也能显示，状态按清单标记，不补造连接。
- 节点、服务、边保留结构化 `provenance`（扫描任务、结果记录、工具和采集时间）。手工节点/关系标记 `manual`；编辑已有关系标记 `manualOverride`，图上使用橙色点线。路由观测、目标响应、应用请求、任务请求和同网段逻辑归属维持不同语义。同网段归属即使有扫描来源，仍是逻辑推断，不代表实体交换机或物理布线。
- 节点详情显示入口、检查覆盖、候选发现和验证引用。源码验证仅在记录的 `run_id` 等于任务当前 `run_id` 时显示为本次结论；其他结果标为历史。没有逐发现关联的验证记录时显示“本次未记录”，不把扫描候选认定为已验证漏洞。

## 节点扫描接口

`POST /api/topology/from-pipeline/:id/node-scans`

请求字段：`node_id`、`scan_type`（`topology_scan` 或 `port_scan`）、`request_id`（8 至 128 位字母、数字、横线或下划线）。返回关联的 `scan_task_id`、服务端解析的目标和状态。新建返回 201；相同请求号或同节点的待执行/运行中扫描返回 200。相同请求号对应不同节点或扫描类型时返回 409。

服务端从当前任务投影中重新定位节点，只接受 F03 资产、主目标或有主机发现证据的节点。目标地址由服务端确定；随后用 F02 的结构化范围、排除项和执行位置校验。Qt 创建记录后调用现有 `POST /api/scan-tasks/:id/execute`；执行器会再次校验范围。重新扫描创建新记录，保留历史结果。未获得目标网段明确授权时，节点扫描不会扩大为整段 LAN 发现。

迁移 `031_topology_node_scans.js` 增加 `topology_request_id` 和任务内唯一索引，用于重复请求保护。迁移只扩展表结构，不改写旧记录。旧任务若没有结构化范围，服务端仅以原主目标作保守范围；无法解析原目标时仍可查看拓扑，但节点扫描会给出限制原因。

## 环境与归档迁移

网络位置、直连网段与下一跳来自执行时采集的接口、路由和探测响应。不同 IP、掩码、执行机或经过网关的目标应重新生成拓扑；无证据的跳点及物理连接保持未知。IPv4 局域网自动发现仍受范围和 4096 地址上限约束；IPv6 可显示主机与路由证据，尚不自动扩展 IPv6 邻居发现。

新归档写到 Qt 的 `QStandardPaths::AppDataLocation/topology_data`，不依赖可执行文件所在目录。启动或打开任务时可读取旧版可执行文件旁的 `data/topology_data`，同一任务的旧归档读取后写入新目录；旧文件不删除。拓扑页面“编辑”菜单支持 JSON 导出、导入，以便同一任务在另一客户端迁移手工布局和备注。导入核对任务 ID、节点 ID 及连线引用，并标为本机人工归档。新扫描完成时，已保存的手工图不会被自动覆盖；主动点击“更新拓扑”并确认后才用服务端最新证据替换。服务端扫描和验证结果仍以当前任务为准。不同任务或后端任务 ID 发生变化时，应重新投影，不能直接把旧任务验证状态搬入新任务。

## 下一步探测方案（建议，尚未实现）

当前 `nmapTopology.js` 按 Nmap 的人类可读文本用正则提取主机、端口和跳点；`scanExecutor.js` 还解析 `nmap --iflist` 文本。Nmap 官方明确推荐程序读取 [XML 输出](https://nmap.org/book/output-formats-xml-output.html)，其中有主机状态与响应原因、IPv4/IPv6/MAC 地址、端口状态及 traceroute 跳点。文本格式随版本变化会使节点归属和跳点解析不稳定。建议按以下顺序替换：

1. **先做采集适配层**：新运行同时保存 Nmap 原始 XML 与规范化观测记录。观测记录至少含 `pipeline_id`、扫描运行/工具调用 ID、执行位置、目标、探针类型、观察值、时间、原始结果 ID、解析器版本及完整性。XML 采用禁用外部实体的流式解析；取消或超时时保留已完整解析的 `<host>`，并记录未闭合片段和解析失败，旧文本结果继续走兼容适配器。上线前用同一批隔离输出逐项对账，不能因换格式丢失 F04 的部分结果。
2. **按探测位置选策略**：单主机或 URL 只探测授权主机及入口；明确授权的直连网段才做受预算约束的 `-sn`，利用本地 ARP/IPv6 ND 响应；跨路由目标只记录目标响应和 traceroute 路径，不能把执行机本地网段当作目标 LAN。Nmap 官方也说明 `-sn` 的默认探针和权限差异，见[主机发现文档](https://nmap.org/book/man-host-discovery.html)。执行机/容器的接口、路由、权限和可用探针按运行时采集并记录，不配置固定 IP、固定 `/24` 或固定“网关”。
3. **图由观测投影**：资产/服务归属、同网段成员、路由响应、应用请求和手工关系采用独立边类型。每条边保留原始观测与执行位置；无响应、缺失 TTL 或只存在路由配置时显示未知。需要真实物理连接时，另接有授权的交换机邻居/端口证据适配器；Nmap 路径本身不证明网线连接。
4. **按环境做迁移验收**：用不同前缀、双网卡、NAT/代理、跨网段、IPv6、无原始套接字权限、部分输出及旧记录作为固定样本；比较采集、解析、入库、API、Qt 五层的节点和边数量，并核对失败与取消后的可用部分。真实设备验收须记录扫描实际所在位置与权限。

这部分属于后续执行引擎与解析器的接口变更，须和 F03/F04 协调；本地分支当前未切换 Nmap 输出格式。

## 页面交互修正

“生成拓扑”现在仅在页面按钮、状态文字和进度字段显示忙碌，不再打开模态进度窗口；生成错误也留在页面状态区。单击节点、异步结果返回和场景重绘会保留仍存在的节点选择；刷新后节点 ID 变化时按资产 ID、IP、主机名顺序恢复同一节点的详情。页面销毁时先断开场景选择信号，避免清理图元时回调已销毁的属性控件。覆盖这些行为的 Qt 测试使用本地延迟 HTTP 响应，不执行真实扫描。
