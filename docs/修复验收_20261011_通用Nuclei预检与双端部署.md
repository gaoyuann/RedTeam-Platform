# 通用 Nuclei 预检修复与双端部署

## 1. 原始失败

- 执行编号：`run_5df39126-7aa`。
- 时间：2026-10-11 12:49:15—12:49:55，北京时间。
- 预案：`web_vuln_exploit`。
- 目标：`http://192.168.1.111:8765`。
- 12 项预检中 11 项通过，仅 `nuclei_templates` 失败；执行步骤与尝试记录均为 0。
- Nuclei 参数为 `-severity medium,high,critical`，未指定模板 ID。此前修复仅约束指定 ID 的预案，通用预案仍校验整套模板库。
- 原镜像为 Nuclei `v3.3.7`。实测把严重级别与协议筛选直接加到 `-validate` 命令仍会解析无关模板，并遇到 DSL、正则和 code 引擎错误。
- 新版的 `-tl` 还会列出未启用的能力模板，并输出清单标题；需要兼容标题、排除未显式启用的 code、headless、file、DAST、自包含与全局匹配器能力，而不是把这些模板当作本次运行必需资源。
- 模板库部分目录由此前容器下载产生，为 `root:root`、`0700`。服务器后端以 `aistation` 运行，无法读取这些目录，也无法在 root 所有的模板根目录写入大清单。

## 2. 修复策略

1. 使用 Nuclei 自身的 `-tl` 元数据筛选生成实际模板清单，复用严重级别、标签、模板 ID、协议、排除项及显式路径等选择参数，不把目标 URL 或攻击参数传给清单命令。
2. 预检逐个检查 Nuclei 步骤，不再合并各步骤 ID 后误做全库校验。
3. 使用具体清单执行严格编译校验，执行器使用同一清单；显式指定的必需模板先单独严格校验，不能被其他筛选参数掩盖。
4. 大清单写为挂载模板目录下的 `.redteam-selections/<sha256>.txt`，避免命令参数超过操作系统限制；写入采用临时文件加原子替换。
5. 没有匹配模板、必需模板缺失、所选模板编译失败时继续阻断，不回退到全库，不关闭校验，不自动删除损坏模板。
6. 固定 Nuclei `v3.11.1`，下载归档 SHA-256 为 `ea63d4ae232808cd7c6bc00d0142428e231fab59dae01042246097d195835ab6`。容器构建文件同步固定版本和校验值。
7. 保留默认禁用能力的边界，不自动开启 code、headless、file、DAST 或自包含模板。清单按路径排序，确保重复解析后的清单文件标识稳定。
8. 容器模板下载改用后端 UID/GID，并设置可写的临时 HOME，避免再次产生 root 独占目录。现有库的修复先在隔离副本验证，部署时备份完整权限信息，再将库归属调整为后端用户并只补充所有者读/遍历权限，不向其他用户扩大权限。

未改预案步骤或关闭可选步骤预检，未新增生产执行记录，也未触发完整攻击测试。
