## 实施顺序

### 1. 执行身份与持久化（P0）

- 动态步骤使用单调递增编号，不再取数组末项编号；明确原始/动态来源及步骤 ID。
- 增加数据库迁移记录执行尝试，重试保留每次参数、退出码、错误与时间，步骤表只保存最后结果。
- 证据关联尝试 ID，持久化完整决策参数和 Guard 拦截结果，避免只留下动作名称。
- 修改参数时清空编译缓存，让 `adjust` 的新参数确实参与下一次执行。
- 验收：连续插入、多工具分组、重试后编号不重、尝试不丢失，证据与执行次数可核对。

### 2. 工具结果和运行状态（P0）

- 宿主/容器执行以退出码和超时状态判断，不因横幅或进度输出判成功。
- 对明确的工具错误输出（包括退出 0 的无效 URL）标记失败；无发现与执行失败分开。
- stdout 和 stderr 同时进入证据和 ReAct；超时/中止明确失败，禁止靠 stdout 掩盖。
- ReAct stop 只表示停止决策；失败或未完成必选步骤不能被转为成功。摘要分开记录手动中止、AI 停止、超时和未执行数。
- 完成状态先落库再广播，减少评分/报告读取旧状态的竞态。
- 验收：Hydra 非零退出、SQLMap 超时、Arjun URL 错误均失败；正常空结果不误判；AI 停止不冲销必选失败。

### 3. 字典与命令契约（P1）

### 4. 认证、上下文与可观测性（P1）

- 工具级审计包含尝试、退出码、耗时与脱敏参数；参数中的常见令牌/认证字段被遮盖。原始工具输出和模型决策仍可能含敏感信息，不承诺对任意自由文本完全脱敏。
- 验收：离线模拟登录/CSRF/重定向/会话传递；上下文非空；非当前任务事件不显示；重复事件只显示一次。

再次检查时没有只依赖编译结果，而是重新审计执行入口、预检、ReAct 决策、终态广播和前端历史回放，并补充修复以下问题：
