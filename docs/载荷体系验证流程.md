# 载荷体系验证流程

> 验证"载荷能够生成 → 载荷经过加工 → 变成利用攻击程序"完整链路，
> 同时验证后端 API、Qt 前端、ReAct 引擎的载荷集成。

## V3: AI 载荷生成验证

### V3.2 审核载荷

```bash
# 获取上一步生成的载荷 ID

  -H "Authorization: Bearer $TOKEN" \
```

## V6: 对抗演示 Playbook 端到端验证

### V6.1 载荷生成→编码→攻击 完整链路

这是老师要求的核心演示："载荷能够生成 → 载荷经过加工 → 变成利用攻击程序"

```bash
# 1. 确认演示 Playbook 存在
curl -s "http://localhost:3002/api/playbooks/payload_generate_and_exploit" \
  -H "Authorization: Bearer $TOKEN" | jq '.data | {id, name, steps: (.steps | length)}'
# 期望: id="payload_generate_and_exploit", steps=4

# 2. 创建执行（需要 Docker 中 rt-exploit 镜像含 msfvenom）
curl -s -X POST http://localhost:3002/api/runs \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{
    "playbook_id": "payload_generate_and_exploit",
    "target": "192.168.1.100"
  }' | jq '.data.run_id'
# 期望: 返回 run_id

# 3. 观察执行过程
# Step 1: nmap 扫描目标端口（payload_id: port-scan）
# Step 2: msfvenom 生成反向 shell 载荷（payload_id: evasion-shellcode-encrypt）← "载荷能够生成"
# Step 3: msfvenom 编码加工载荷（payload_id: evasion-shellcode-encrypt）← "载荷经过加工"
# Step 4: 验证加工后载荷文件 ← "变成利用攻击程序"
```

## 快速一键验证脚本

```bash
#!/bin/bash
# quick-verify-payload.sh — 快速验证载荷体系核心功能
set -e

  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"admin123"}' | jq -r '.access_token')

echo "=== V1.1 载荷列表 ==="
TOTAL=$(curl -s "$BASE/api/payloads" -H "Authorization: Bearer $TOKEN" | jq '.meta.total')

echo ""
echo "=== 验证完成 ==="
```
