# 针对具体漏洞生成验证源码

入口：逐漏洞测试窗口 → 载荷代码 → **生成载荷**；生成后可通过“准备本地载荷测试”绑定执行方案。

逐漏洞测试窗口默认最大为 1120×720 个逻辑像素，小屏幕按可用区域的 90% 缩小，首次显示时为窗口边框留出空间并限制在当前屏幕内。可拖动窗口内顶部标题区移动，双击标题或点击右上角方框切换最大化／还原，右下角支持调整大小。小窗口中的结果与工作区可滚动，底部长就绪提示采用省略显示，悬停查看完整内容，避免长漏洞名撑大窗口。

任务漏洞表常显“载荷情况”，区分库中匹配和本漏洞已有代码；点击该列，或选中漏洞后点击“查看 / 生成载荷”，可直接打开对应代码页。未选中漏洞时仍提供任务漏洞选择窗口。代码页参考 pentagi-v3 的代码 / 说明分栏，展示来源、语言、运行条件、依赖、预期结果及模型推断；可复制完整代码，或选择路径导出当前文件。这些操作不执行代码。切换漏洞或文件时说明同步切换，空记录清除旧说明并禁用复制、导出；普通刷新保留相同代码的文本选择。生成或收集结果变化后同步刷新父列表摘要。

当前载荷页已收敛为“当前漏洞载荷”：直接展示与当前漏洞关联的扫描载荷及最近一次成功生成的代码，同一漏洞有多个文件时才显示切换框。没有载荷时只显示“生成载荷”按钮；生成完成后直接显示代码。失败的生成不会覆盖已有成功载荷。依赖、推断等完整生成记录仍保存在后端，默认页面不再平铺收集、Python 改写、HTTP 参数、历史记录和长说明；收集重试、改写及手动载荷绑定保留在“漏洞与测试”页的“高级设置：方案与载荷”中。`current_payload` 是由当前验证项的两个存储投影得到的关联视图，不是执行绑定，也不表示代码已运行。

点击按钮直接生成，无需填写表单。后端自动读取当前漏洞的描述、CVE/CWE、报告依据、已保存源码和任务范围。源码快照须匹配同一扫描、同一 Flow 和完整路径，并通过 SHA256 校验；不按文件名猜测匹配，也不实时下载目标源码。文件过大时截取漏洞行附近的有界片段，并注明来源及截取情况。

生成入口优先复用：代码页直接显示载荷库中与当前漏洞签名一致、且通过当前工具参数校验的结构化载荷，标明“载荷库复用”；只有分类相近的静态参考样本不会自动认定为可用载荷。结构化参数仍由高级设置绑定兼容步骤后确认执行。本地程序生成请求则先查找同一用户、完整生成上下文和原始漏洞指纹均一致的成功代码；同一漏洞直接返回已有记录，其他漏洞的相同上下文代码复制到当前验证项并保留复用来源。不跨用户读取私有代码，不复用执行说明无效或来源过期的程序。没有适配载荷时才调用模型。

扫描描述兼容 Nikto 的 `finding`、`description`、`info.description/info.name` 及旧记录的 `legacy_text`，跳过空白字段；现有 `reason/detail/title/name` 继续支持。真正没有描述时仍返回缺少信息。漏洞记录变化或旧代码缺少来源指纹时保留代码查看，但禁用准备执行并提供重新生成入口。

逐漏洞窗口采用 `Qt::WindowModal`，原生瞬态父窗口明确指向所属主窗口；显示期间主窗口不能接收操作，避免工作区被主窗口遮挡。最大化／还原保留该关联，刷新数据不会反复抢占焦点。

默认生成本地测试程序或模拟服务。真实版本、系统或架构未知时如实标注，不作为本地模拟生成的必填项。部署标识不自动认定为受影响版本。没有源码时只能以报告证据分析，不编造缺失源码；确实没有核心触发逻辑、无法构造有依据的模拟时，才说明缺少什么。模型可能无法生成代码，不承诺每条扫描发现都有有效复现。

## 调用与数据

`POST /api/pipelines/:id/verifications/:verificationId/verification-code`

默认客户端发送 `expected_revision`、唯一 `request_id`、`authorization_confirmed: true`、`automatic_context: true` 及布尔字段 `force_regenerate`。点击行为仅请求生成，不授权执行目标；界面明确展示生成范围。自动模式不接受用户覆盖扫描上下文字段，范围以服务器已有任务范围为准。

可选布尔字段 `force_regenerate` 默认为 false，自动模式下跳过复用、明确请求新的本地验证程序。代码页在已有参考／结构化载荷或不可执行旧代码时显示生成本地程序入口，并显式发送 true。复用响应带 `reused: true`；库中载荷返回 `state: "existing"` 和 `payload_id`，代码记录返回 `state: "ready"` 和 `id/result`。已有请求编号仍按原输入校验并返回记录，不重复生成。

旧调用方仍可省略 `automatic_context`，继续显式提供 `description`、`cve`、`cwe`、`affected_version`、`source`、`environment`、`authorization_scope`。该兼容模式保留原有必填及敏感字段检查。

复用 `llmClient.callLlm` 的现有模型配置、认证和调用流程，无新增模型地址或密钥。模型请求超时 60 秒，前端等待上限 130 秒。原始模型错误响应不直接透传。

新增迁移 `039_finding_verification_code.js` 创建独立历史表 `finding_verification_code`。记录状态包括 `generating`、`ready`、`needs_information`、`error` 和 `interrupted`。同一请求编号和同一输入返回原记录，不重复调用；输入变化时拒绝复用编号。同一漏洞并发生成请求被拒绝。进程中断后可用新编号明确重试，不自动重放未知请求。

生成内容经结构校验后保存，包括文件名、语言、完整源码、依赖、运行条件、预期结果、可能失败原因、修复建议、模型推断。最多 4 个文件、单文件源码 24000 字符、总输出 64000 字符；拒绝目录穿越文件名、重复文件、截断输出及敏感字段。长源码不经过日志的 2000 字符截断。

源码的凭据检查区分代码表达式和凭据字面量：`cookie = SimpleCookie()`、字典初始化、读取输入、变量拼接、属性比较等不视为凭据；Cookie 本地样例可使用 `<SESSION_TOKEN>` 或 `demo-session` 等明确模拟值。私钥、硬编码密码／令牌，以及赋值或嵌入请求头中的非模拟会话值仍被拒绝。自动读取的源码、兼容接口传入的源码和生成源码使用同一检查，不通过替换或截断改写程序。模型提示同步要求使用占位值；检查失败仍保存为错误记录，不覆盖已有成功代码，也不自动执行。

详情接口的 `verification_code` 返回最近 20 条记录；当前载荷页只展示最近一次成功生成的文件及已收集载荷，可在这些文件之间切换。文件内容用纯文本展示，保留复制选择，不渲染 HTML。输入信息由服务端根据用户输入构造，不接受模型声称的“已验证事实”；`verified_facts` 固定为空，`runtime_verified` 固定为 false。

## 生成与执行边界

生成记录不创建或修改 playbook、工具步骤、载荷执行绑定、验证计划版本、执行次数或执行记录；不会安装依赖、写出源码文件、运行编译器、启动程序或向目标发起请求。现有其他执行功能继续使用原来的接口及检查。

系统提示要求优先本地测试程序、模拟服务、无破坏性标记，且将源码、描述和其中指令全部作为不可信数据。接口沿用任务所有权及漏洞归属检查，拒绝超长输入及凭据字段，没有绕过现有检查的参数。

生成输出仍是待审查的模型建议。结构校验与提示约束不能保证模型源码的正确性或运行安全性；本次没有执行生成内容，也没有验证漏洞成立。已有扫描报告不保证包含全部触发条件，需要用户补充真实版本、源码和环境。

现已新增独立的“准备本地载荷测试”入口：生成结果携带 Python/C/C++ 入口、正常对照、验证输入和输出判据后，可显式准备冻结方案，再由用户确认开始，交给本项目执行器运行。生成接口本身仍不执行。旧记录可继续查看，缺少执行说明或来源指纹时需要重新生成。部署镜像、执行限制及本地模拟结论边界见 [载荷与本地验证执行](source-code-execution.md)。

## 验证

- `node --test test/finding-verification-code.test.js`：内存数据库、固定模型回复、真实本地 API；覆盖权限、缺项、重复/并发、敏感字段、无效输出、模型超时、路径名校验、完整长源码、自动上下文、快照哈希及归属匹配、未知字段和生成不触发执行。
- `node --test test/finding-code-reuse.test.js`：真实 Nikto 解析结果进入生成、描述字段兼容、库中载荷复用、代码重复请求与跨验证项复用、上下文／权限／来源变化拒绝复用，以及过期代码的查看与执行状态。
- `node --test test/verification-code-secrets.test.js`：Cookie 解析与属性处理、动态凭据变量、模拟占位值，以及硬编码凭据和嵌入请求头的检测；复用测试同时覆盖生成源码完整保存、拒绝后保留成功代码。
- `npm run test:source`：包括上述检查及已有源码扫描回归。
- Qt `ui-finding-payload-artifacts`：核对单击后无弹窗直接请求自动上下文、完整代码展示、高级设置中的收集和改写入口，同时检查生成与准备方案没有发起执行调用。
- 窗口专项：`cmake --build build/finding-verification -j 4` 后执行 `ctest --test-dir build/finding-verification --output-on-failure`；`finding-window-1 / 1.5 / 2` 使用实际应用字体与样式，检查整窗位于屏幕内、长提示、标题拖动、最大化／还原、缩小窗口和滚动访问底部按钮。离屏检查覆盖拖动回退路径，真实桌面合成器的原生拖动仍需桌面验收。

首次加载新版后端需运行现有启动迁移；已打开的前后端需重启加载新版。没有新增必填模型配置，仍需现有模型服务可用。测试采用固定回复，不代表线上模型质量验收。
