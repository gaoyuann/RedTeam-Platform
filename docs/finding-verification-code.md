# 针对具体漏洞生成验证源码

入口：逐漏洞测试窗口 → 载荷代码 → **生成载荷**；生成后可通过“准备本地载荷测试”绑定执行方案。

当前载荷页已收敛为“当前漏洞载荷”：直接展示与当前漏洞关联的扫描载荷及最近一次成功生成的代码，同一漏洞有多个文件时才显示切换框。没有载荷时只显示“生成载荷”按钮；生成完成后直接显示代码。失败的生成不会覆盖已有成功载荷。依赖、推断等完整生成记录仍保存在后端，默认页面不再平铺收集、Python 改写、HTTP 参数、历史记录和长说明；收集重试、改写及手动载荷绑定保留在“漏洞与测试”页的“高级设置：方案与载荷”中。`current_payload` 是由当前验证项的两个存储投影得到的关联视图，不是执行绑定，也不表示代码已运行。

点击按钮直接生成，无需填写表单。后端自动读取当前漏洞的描述、CVE/CWE、报告依据、已保存源码和任务范围。源码快照须匹配同一扫描、同一 Flow 和完整路径，并通过 SHA256 校验；不按文件名猜测匹配，也不实时下载目标源码。文件过大时截取漏洞行附近的有界片段，并注明来源及截取情况。

默认生成本地测试程序或模拟服务。真实版本、系统或架构未知时如实标注，不作为本地模拟生成的必填项。部署标识不自动认定为受影响版本。没有源码时只能以报告证据分析，不编造缺失源码；确实没有核心触发逻辑、无法构造有依据的模拟时，才说明缺少什么。模型可能无法生成代码，不承诺每条扫描发现都有有效复现。

## 调用与数据

`POST /api/pipelines/:id/verifications/:verificationId/verification-code`

默认客户端只发送 `expected_revision`、唯一 `request_id`、`authorization_confirmed: true` 和 `automatic_context: true`。点击行为仅请求生成，不授权执行目标；界面明确展示生成范围。自动模式不接受用户覆盖扫描上下文字段，范围以服务器已有任务范围为准。

旧调用方仍可省略 `automatic_context`，继续显式提供 `description`、`cve`、`cwe`、`affected_version`、`source`、`environment`、`authorization_scope`。该兼容模式保留原有必填及敏感字段检查。

复用 `llmClient.callLlm` 的现有模型配置、认证和调用流程，无新增模型地址或密钥。模型请求超时 60 秒，前端等待上限 130 秒。原始模型错误响应不直接透传。

新增迁移 `039_finding_verification_code.js` 创建独立历史表 `finding_verification_code`。记录状态包括 `generating`、`ready`、`needs_information`、`error` 和 `interrupted`。同一请求编号和同一输入返回原记录，不重复调用；输入变化时拒绝复用编号。同一漏洞并发生成请求被拒绝。进程中断后可用新编号明确重试，不自动重放未知请求。

生成内容经结构校验后保存，包括文件名、语言、完整源码、依赖、运行条件、预期结果、可能失败原因、修复建议、模型推断。最多 4 个文件、单文件源码 24000 字符、总输出 64000 字符；拒绝目录穿越文件名、重复文件、截断输出及敏感字段。长源码不经过日志的 2000 字符截断。

详情接口的 `verification_code` 返回最近 20 条记录；当前载荷页只展示最近一次成功生成的文件及已收集载荷，可在这些文件之间切换。文件内容用纯文本展示，保留复制选择，不渲染 HTML。输入信息由服务端根据用户输入构造，不接受模型声称的“已验证事实”；`verified_facts` 固定为空，`runtime_verified` 固定为 false。

## 生成与执行边界

生成记录不创建或修改 playbook、工具步骤、载荷执行绑定、验证计划版本、执行次数或执行记录；不会安装依赖、写出源码文件、运行编译器、启动程序或向目标发起请求。现有其他执行功能继续使用原来的接口及检查。

系统提示要求优先本地测试程序、模拟服务、无破坏性标记，且将源码、描述和其中指令全部作为不可信数据。接口沿用任务所有权及漏洞归属检查，拒绝超长输入及凭据字段，没有绕过现有检查的参数。

生成输出仍是待审查的模型建议。结构校验与提示约束不能保证模型源码的正确性或运行安全性；本次没有执行生成内容，也没有验证漏洞成立。已有扫描报告不保证包含全部触发条件，需要用户补充真实版本、源码和环境。

现已新增独立的“准备本地载荷测试”入口：生成结果携带 Python/C/C++ 入口、正常对照、验证输入和输出判据后，可显式准备冻结方案，再由用户确认开始，交给本项目执行器运行。生成接口本身仍不执行。旧记录可继续查看，缺少执行说明或来源指纹时需要重新生成。部署镜像、执行限制及本地模拟结论边界见 [载荷与本地验证执行](source-code-execution.md)。
