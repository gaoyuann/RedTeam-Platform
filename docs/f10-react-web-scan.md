# F10：ReAct Web SQL 检测（第一轮）

本功能面向明确授权的 DVWA 教学环境。沿用现有任务、扫描结果和后续验证模块；新增扫描阶段的受限 ReAct 调度。只有显式选择“AI SQL 检测（DVWA / GET）”才运行，历史任务默认行为不变。

## 用户流程

1. 创建 Web 任务，填写明确的 HTTP/HTTPS 应用入口及测试范围，选择 AI SQL 检测。
2. 启动时输入本次临时登录信息。任务不保存账号密码；登录不访问安全等级设置接口，也不重置靶场。
3. 扫描从实际页面发现链接、GET 表单和参数，由模型选择读取入口或检查一个参数，服务端校验后执行。
4. 扫描结果上方显示持久化的决策过程，候选行的位置列显示“工具检测阳性”或“证据不足，需复核”。展开记录查看参数、技术、工具运行 ID 和证据引用。
5. 模型失败、登录失败或覆盖不完整均明确记录。后续验证仍走原有方案与确认流程，不自动累计验证成功数。
6. 已结束的 AI 任务可点击“重新扫描（新任务）”。新任务关联原任务，启动时重新输入认证。停止未确认时拒绝重试；旧扫描证据不覆盖。

## 支持范围与默认值

- DVWA 登录；GET 查询参数与 GET 表单；sqlmap 的布尔、报错和联合查询检测。
- POST、密码表单、动态令牌表单、重复参数、上传及其他漏洞类型首轮不支持。
- 对空白 GET 文本字段 `id` 使用固定正常对照 `1`，入口元数据标记 `normal_control_1`；其他无默认值字段标记条件不足。此规则由服务端实施，不由模型生成。
- 页面入口只来自实际观察。模型不能直接提供目标 URL、命令或任意工具参数。
- 最多 12 次模型决策、20 次页面请求、5 次 SQL 检测，总时限 10 分钟；单次模型 30 秒，工具 120 秒。登录、跳转、认证前置检查也计入页面请求预算。
- 页面请求预算不是 sqlmap 内部 HTTP 请求次数上限。sqlmap 单线程、level 1、risk 1、BEU、无重试、不跟随跳转；不枚举或导出业务数据，不执行系统命令。
- 每次工具调用独立临时目录，禁用复用旧会话。容器运行不自动拉取镜像。工具未确认停止时保留受保护目录并阻止相同目标再次启动，需运维核对；普通结束仅删除本次生成的目录。

## API 与数据

创建／更新任务继续使用现有接口，新增配置：

```json
{"scan_parameters":{"web":{"version":1,"mode":"react_sqli","auth_mode":"dvwa_ephemeral"}}}
```

该模式强制 `require_approval=true`、`auto_execute=false`。扫描配置在任务启动后冻结。模式只支持 HTTP/HTTPS 应用入口，不能混用程序／源码模式。

`POST /api/pipelines/:id/start` 新增 `authentication` 对象（`username`、`password`），仅任务所有者可以提供并启动。认证不进入配置、审计正文、扫描参数、模型上下文或事件。后台只在运行期保存，结束和重启后不可复用。

`POST /api/pipelines/:id/retry-web-scan` 接受 `request_id`；幂等创建状态为 `created` 的关联新任务，不自动启动。独立扫描 API 不接受新智能模式。

`GET /api/pipelines/:id/results?view=scans` 新增 `web_scan_process` 和 `web_scan_process_truncated`，过程独立于漏洞筛选，最多返回最近 100 条；全部历史仍在扫描记录中。`scan:agent_step` 沿用现有扫描资源所有者／管理员事件权限。断线后以持久化记录恢复。

迁移 `036_web_scan_entries` 为 `task_entries` 增加默认 `{}` 的 `metadata`。入口身份区分 URL、方法、链接／表单及参数集合，元数据不保存输入值或令牌。未安装迁移时拒绝新模式，旧结果继续读取。

过程类型 `web_agent_step`、`web_scan_summary` 属于信息；`web_observation` 属于资产观察。SQL 候选输出版本化规则、无查询值 URL、GET 方法、参数位置、技术列表、检测状态、工具运行和证据引用。同一参数多个技术合并为一条发现。

工具证据保存经过筛选的参数检测结论与技术片段，另存原输出 SHA-256 供来源核对，不保留原始敏感响应或完整 sqlmap 输出。完整报告阳性标记 `tool_positive`；明确结束且未检出为 `not_detected`；其余为 `inconclusive`。工具检测阳性不写入后续验证尝试、系统确认或攻击成功字段。

sqlmap 参数参考其[官方 Usage](https://github.com/sqlmapproject/sqlmap/wiki/Usage)。实际部署工具版本与镜像可用性仍须部署前核验。

## 中断和限制

取消会传递给模型、页面请求和工具。活动智能扫描取消后，父任务等待子扫描收束；停止不明时保留显式异常及工具活动标识。重启后不恢复会话、不重放检测，运行中工具标记停止未确认。

当前仍使用现有后续分析／预案生成流程，扫描候选可通过现有单条验证入口继续准备；没有新的自动验证成功逻辑。扫描计划结束不表示覆盖全部 DVWA 模块，也不承诺某一安全等级下一定检出。

本地自动测试使用内存数据库和模拟模型、工具及页面；不代表真实 DVWA 或真实模型验收。实际测试需要另行确认目标 URL、协议／主机／端口／路径、排除路径、时段及工具范围，不自动设置低安全等级以获取阳性结果。

## 代码复查后的补充边界（2026-10-22）

- 本次扫描是独立会话，不继承浏览器中的 DVWA `security` Cookie。必须观察到服务器给该会话设置的有效等级；等级缺失、变化或 Cookie 路径不适用时停止。页面中点击 low 并不保证扫描会话也是 low。系统不自动降级。
- 首轮保守拒绝路径中的百分号编码，避免编码别名绕过排除路径。含 `<base>` 的相对链接、禁用／分组／多选歧义的选择控件按未支持处理，不猜测浏览器提交语义。
- 入口身份和检测去重包含完整正常请求的哈希；不同正常值不会沿用另一请求的已检查状态。公开 URL 不含查询值，同一参数候选仍由既有实例归并规则处理。
- 入口路径或参数名称含已知认证秘密时不参与检测；候选写入统一脱敏。工具 Cookie 仍通过本机进程参数传递，因此测试主机进程信息和容器管理权限必须限于可信操作人员；这不是长期凭据存储机制。
- 明确的 `all tested parameters do not appear to be injectable` 结束语允许带 `[CRITICAL]` 标签，但必须同时满足正常退出、停止确认、无超时／取消／其他错误、无注入技术报告和完整结束标记。其他错误仍为证据不足。
- 服务重启后的缺失计数显示“未知”，不显示零次。停止未确认的任务仍禁止删除或重试；运维须先核对实际工具进程。
- 完整容器参数测试使用模拟进程；尚未证明实际镜像中 sqlmap 的每一个网络请求都符合范围。正式检测前应在隔离环境以脱敏访问记录核对请求路径与排除项；不把参数配置等同于网络隔离保证。

## 派发与启动计数

`web_scan_summary.checks` 保留为 SQL 派发尝试次数（同时用于预算），不再标为实际执行次数。新增 `checks_started`（已确认启动次数，有任一启动未知时为 null）、`checks_not_started`（明确未启动次数）和 `checks_start_unknown`（启动未知次数）。页面分别显示派发尝试与工具启动；旧记录缺少启动计数时显示“未知”，不回填猜测值。

`scan_evidence.tool_started` 和 `scan_tool_runs.outcome.tool_started` 保存运行器的三态启动结果：true / false / null。它表示运行器进程启动情况；容器模式不能仅据此保证容器内 SQL 工具已正常工作，仍须结合退出状态、报告及停止确认判断。工具明确未启动时检查标记 not_checked，保留失败/停止证据，不发布候选；新的扫描摘要未确认任何启动时，父任务不继续分析或生成预案。已启动但超时仍属于尝试未完成，不能当阴性。无需新增数据库列或迁移，历史记录保持原状。

## 通用调度纠正后的定位

新建运行态任务的默认入口已转向通用 ReAct 调度，见 [通用扫描调度说明](react-scan-orchestration.md)。本文件描述的 react_sqli 为历史任务兼容及已有专项能力，不能再用它代表整个平台扫描入口；其真实 DVWA 验收不能自动证明通用调度与所有能力已通过。
