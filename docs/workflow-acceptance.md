# 主界面流程复核与验收

## 流程与方案关系

任务管理、顶部功能模块使用同一个任务上下文。主界面直接展示扫描、方案、执行和结果；任务管理双击恢复该任务的当前阶段，不再打开独立操作流程。

已知目标可直接进行脆弱性扫描；未知网段可先进行资产／拓扑探测，再从节点发起目标扫描。拓扑不是已知目标扫描的前置门槛。此关系与本机参考项目 `pentagi-v3` 的 `HomeOverviewPage.cpp`、`TopologyPage::requestScanForNode` 和 `VulnerabilityScanPage` 一致：节点扫描是入口衔接，目标扫描仍可独立创建 Flow。本轮只阅读参考项目，未修改其代码或提示词。

普通整体任务沿用重构前的扫描、分析、来源预案、任务草稿、提审、批准冻结版本、执行、评估和报告。最接近 Ribbon 重构前的 `e929057` 已使用 ReAct 扫描调度；原流程适配不等于改回固定扫描器顺序，也没有修改模型提示词或把异常检查当成成功。

| 操作范围 | 入口与用途 | 执行及结果 |
| --- | --- | --- |
| 整体任务方案 | 方案范围选择“整体任务方案”；依据任务扫描与分析编制 | 审批冻结版本后执行，保留原任务运行与证据 |
| 逐漏洞验证方案 | 从扫描发现或“逐漏洞验证方案”打开具体发现 | 各自保存方案版本、载荷关联和尝试记录；无需先完成整体预案 |
| 生成载荷代码 | 具体发现的“载荷代码”页 | 生成只保存；本地隔离测试须另行准备、确认和执行，不证明部署目标存在漏洞 |
| 步骤载荷 | 高级方案与载荷中选择步骤，查找或生成、预览、绑定 | 绑定后修订方案版本；执行证据记录是否实际消费，重复请求不重复执行 |
| 报告 | 当前任务测试结果 | 汇总扫描和逐漏洞尝试；没有整体 Run 时仍可生成任务汇总，不把子 Run 冒充整体 Run |

## 扫描失败与展示修复

- Nikto 2.1.6 正常标题、目标信息、TLS 信息和请求统计不再计入未解析异常。Hostname 证书差异仍作为发现解析；未知输出仍保留为未解析内容。批量和流式解析保持一致。
- 真实已有输出只读回放得到 16 条解析记录、0 条未解析行，工具自报 16 条；未改写历史任务及证据。
- 创建任务时校验 URL 主机格式，拒绝把分号等字符误作主机和端口分隔符；不自动修改用户输入或历史地址。
- 主任务不再只显示孤立的红色“失败”徽标，改为显示具体未完成原因。扫描页展示工具错误；当前类型筛选隐藏其他扫描结果时提示切换类型或查看全部记录。切换任务清理旧提示。
- 有结果不代表全部检查完成；超时、模型动作无效和停止未确认继续保留真实状态。不能通过隐藏提示宣称扫描成功。

## 验证范围

`backend/test/intelligent-loopback-workflow.test.js` 使用内存数据库及临时本机 HTTP 服务，普通流程和历史 intelligent 流程均经过真实 HTTP 探测、实际 curl、审阅批准、证据、报告和导出。模型答复及容器选择受控，不验证真实模型质量。

`backend/test/workflow-live-tools.test.js` 是显式启用的实际工具验收：使用现有 Docker 工具镜像和临时本机目标，经过真实 Nikto 扫描、扫描结果接口、逐漏洞方案生成、载荷生成与复用、手动绑定、真实 HTTP 验证请求、Python 载荷代码生成、隔离容器正常／验证两次运行、证据、任务报告与导出。模型答复为固定样例；工具、解析、生成结果校验、数据库、编译执行入口及报告逻辑均使用实际实现。该验收不使用正在运行平台的数据库，不停止现有靶场、不重建工具镜像。

```sh
cmake --build build --target RedTeam-Platform RedTeam-Platform-Batch16Checks -j4
cd backend
npm test
REDTEAM_LIVE_TOOLS=1 node --experimental-test-module-mocks --test test/workflow-live-tools.test.js
# 回到仓库根目录；完整界面检查逐档执行，避免同时启动多个渲染实例
ctest --test-dir build -R '^ui-context-1$' --output-on-failure
ctest --test-dir build -R '^ui-context-1.25$' --output-on-failure
ctest --test-dir build -R '^ui-context-1.5$' --output-on-failure
```

实际工具验收需现有 Docker 工具镜像；普通 npm test 默认跳过该项，不自动下载镜像。首次编写验收时修正了接口调用的响应状态和报告关联方式：启动返回 202，新建报告返回 201；任务汇总报告使用当前快照的整体运行编号，不能传入子验证运行编号。未为通过测试放宽生产校验。

## 尚存边界

受控样例通过不等于真实模型已稳定：现场任务曾出现 Arjun 超时、SQL 调度连续无效动作；本轮未修改调度默认值、预算或提示词，也未宣称上述真实模型问题已解决。动态令牌／登录表单仍需原有高级会话与只读模板条件。代码生成及本地模拟成功不能作为真实漏洞利用成功结论。

前后端修复均需加载新版本。编译成功不会替换正在运行的旧进程；客户端退出重开、后端按原启动方式加载新代码后才生效，历史失败记录不自动变成成功。
