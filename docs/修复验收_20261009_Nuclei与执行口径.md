# 2026-10-09 Nuclei、AI 执行展示与评分口径修复验收

## 范围

本轮只处理可低风险落地的问题：Nuclei 模板准备/预检、AI 决策展示序号、评分页口径说明。没有重新执行靶场攻击、调用真实大语言模型、重启云笔电或服务器服务，也没有修改历史运行结果。

## 已落地修复

### Nuclei 模板

- 新增 `backend/src/services/nucleiTemplates.js`，预检和实际 `runTool('nuclei', ...)` 复用同一份模板检查与准备逻辑。
- 不再把“目录存在”或“目录非空”当作模板可用；现在要求目录内至少有可读的 `.yaml`/`.yml` 文件且包含有效根级 `id:`。
- 对显式 `-id`、`--id`、`-template-id`、`--template-id` 参数检查指定模板 ID 是否存在；缺失时先更新，再重新验证。
- 空目录、缺少可读根级 `id:` 的 YAML、下载命令退出成功但没有产生模板、下载失败都会阻断 Nuclei 预检/执行，失败不会被缓存为“已检查”。
- 使用 Nuclei v3.3.7 的更新目录参数 `-update-templates -ud <目录>`；原扫描执行器中的旧重复实现已删除。宿主机模式把容器模板路径转换为宿主实际目录。
- 只有预案中含 Nuclei 步骤时才准备模板；其他预案显示“跳过”，不会因为未安装模板而被误阻断。
- 同时发起的模板准备会共用一次下载；某个调用被取消不会取消其他等待调用。

最近一次失败的直接原因是服务器挂载的 `data/nuclei-templates` 目录为空，容器内 Nuclei 因无模板输入退出。部署本修复后，下一次含 Nuclei 的预检会先下载并验证模板；如果服务器无外网、代理或镜像不可用，会在预检阶段给出明确失败，而不是运行到扫描步骤才报“no templates”。

### AI 执行与分析

- 决策卡片标题改为“第 N 次执行 · 步骤编号 X: 工具”。`N` 使用 ReAct 调用次序，`X` 保留数据库稳定步骤编号，因此动态插入、回退和重试不再看起来像“跳号”。
- 同一稳定步骤再次执行会显示“重试 N”；切换运行记录或清空面板会重置计数。
- `parallel` 动作展示为“工具组插入（顺序执行）”，避免把当前顺序调度误读为真实并发。

### 评分口径

- 评分接口新增 `executionScope`：评分基础、预案步骤数、最终执行步骤数、AI 新增步骤数和尝试次数。
- 评分页在固定步骤明细前说明范围：固定预案步骤构成步骤分；AI 新增步骤不增加固定步骤分，但有效证据仍可计入 MITRE 覆盖。
- 固定明细表头改为“步骤编号”，避免将稳定编号理解为实际执行次序。
- 本轮**没有改变**固定步骤总分、MITRE 上限、等级、原有 `breakdown` 行数或报告兼容性。以“10 个预案步骤、17 个最终步骤、18 次尝试”的样例为例，仍是 10 行固定评分，仍为 `92/120`、`76.7%`。

## 当前失败规则

`backend/src/services/executionState.js` 仍采用严格终态：

- 人工中止：`ABORTED`。
- 超时、任一必选步骤失败、或任一必选步骤未执行：`FAILED`。
- 仅可选步骤失败：不阻断整体 `COMPLETED`，但执行详情/证据应保留该失败。
- 重试以最终步骤结果判定；同一稳定步骤的早期失败、后续成功不会把最终步骤误判为失败。
- AI 的 `stop` 只停止决策，不能把未完成或失败的必选步骤改成成功。

因此，“只要有一个步骤失败，整个预案攻击就失败吗”的当前答案是：**必选步骤是，纯可选步骤不是**。该规则本轮不放宽，避免流水线、报告或教学评估把未完成攻击误报为成功。

## 部署提示

1. 先备份服务端数据库和配置，再部署后端与重新构建的 Qt 客户端；本轮没有自动部署。
2. 含 Nuclei 的新运行首次会在预检阶段准备 `data/nuclei-templates`。该目录仍不纳入 Git；服务器需允许 Nuclei 更新源访问或配置可用代理。
3. 部署后在已授权的隔离教学目标上执行一次含 `-id dvwa-default-login` 的预案，确认预检显示可读模板与指定 ID，且评分页显示执行范围说明。
4. 不要将模板、工具输出、会话文件、模型密钥或真实目标信息提交到仓库或 issue。
