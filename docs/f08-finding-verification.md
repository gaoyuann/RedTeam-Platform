# F08 逐漏洞攻击测试

本功能使用 Qt Widgets、现有执行器及 F04/F06/F07 数据，围绕稳定的 `scan_results.id` 保存单条发现的方案、载荷关联、执行尝试和结论。原始发现尚未跨工具去重，记录数不等于漏洞实例数。实际环境与独立最终验收仍需另行记录，功能实现不自动关闭 #51。

## 全局预案与逐漏洞测试

全局预案为可选批量编排，原入口、编辑、审批和执行功能保留。逐漏洞测试可直接从漏洞列表开始，不要求先生成、审批或执行全局预案；任务范围、权限、方案版本和本次执行确认仍需通过。主流程或其他验证仍在运行、实际停止未确认时，原并发保护继续生效。

执行验证页默认展示逐漏洞记录与活动摘要。主预案的未执行、失败原因、审批信息和指标收在可展开的“主预案详情”中，不作为逐漏洞列表的整页空态或失败状态。父任务、父 Run 和历史记录均不改写。

现有“执行验证”节点仅投影当前活动：无记录时灰色“待执行验证”；有活动子测试时显示“逐漏洞测试进行中”及数量；无活动子测试、但主 Run 仍在运行时显示“主预案执行中”；其余已有记录时使用蓝色信息样式“已有 N 次测试记录”。节点的记录数是现有逐漏洞尝试总数加已关联的主 Run（有则计一），不属于目标达成数或任务完成数，不改变报表、统计接口或历史口径。`queued/running/cancelling` 均计入活动；完成、失败、中止和停止未确认分别展示原状态，不把异常推断为验证成功。

漏洞窗口保留“攻击测试方案”：方案组织本次目标、步骤、载荷绑定与判据；载荷是步骤使用的具体输入。摘要先展示“测什么、做哪些操作、使用哪些载荷、如何判断”，随后可查看入口、每步输入、预期证据、范围前提和预算。载荷匹配与生成仍只在原窗口准备候选，须手动绑定；缺少适用方案、所需载荷或平台判据时明确显示缺口。查看摘要、切换历史和普通关闭均不触发执行，人工意见不替代系统结果。

“如何判断”说明当前方案冻结的平台规则及版本、证据要求和能力限制；手动填写的 `success_criteria` 单列为“方案填写的判据（不改变系统规则）”。填写“HTTP 200 即通过”不会改变目录索引的系统判据。没有受支持的契约、规则版本或对应步骤，或契约与规则绑定不一致时，摘要提示判据缺口，不以填写内容推断自动判定能力。

单条与批量执行共用有尺寸边界的确认窗口。完整摘要、步骤输入、载荷、范围前提和预算在只读纯文本区域滚动查看，确认和取消按钮保留在底部；默认取消。取消、关闭、Esc 或默认回车不创建执行尝试，明确确认后仍须通过原版本、指纹及服务端校验。

## 使用流程

1. 在任务扫描结果中双击单条漏洞，或勾选多条后点击“打开勾选的漏洞”。信息、资产和错误不进入新的攻击测试；旧记录重新归为信息时仍可查看历史及取消已有调用。
   扫描结果表支持“全选当前列表”，范围为当前筛选下已加载的可选漏洞（包含折叠分组），不包括信息、端口、错误或尚未加载的记录。计数显示“已选 X / 可选 Y 条”；半选时再次点击全选，全部选中时点击取消当前列表勾选。加载更多后新增记录默认未选。同任务刷新和筛选切换保留已有 ID 的选择，但打开操作只处理当前列表；离开或切换任务清空选择。
2. 主页面自动读取推荐 Playbook，**不会自动调用模型、选择方案或执行工具**。展开“查看推荐方案 / 更换方案”，查看来源、适用依据、条件和步骤，点击“使用此方案”。没有合适候选时可搜索分页浏览其他方案，或点击“AI 生成新方案”。
3. 当前方案展示来源：内置定向方案、内置/人工模板、历史 AI、本次 AI 生成或基于方案 AI 调整。选择、生成、调整均保存独立草稿版本；人工编辑内容须点击“保存方案调整”。旧快照缺少来源时显示“历史来源未记录”，不猜测。
4. 在“本次载荷与步骤关联”查看每步是无需独立载荷、工具内部输入、待选载荷还是已绑定。候选显示名称、AI/载荷库来源、已有/本次新生成、适用条件及请求位置/方法/输入。静态教学样本标为参考，不能作为可执行载荷。
5. **每次绑定都须手动选择载荷和目标步骤**。先复用、后生成的载荷准备操作只保存候选与准备事件，不自动绑定。工具不一致、版本过期、参考样本或范围不符时拒绝绑定；绑定、更换、解绑都会产生新草稿，使旧确认失效。解绑后需要重新选择载荷的步骤不能启动。
6. 核对具体入口、步骤实际输入、前提、判据、清理方式及预算。点击“开始测试”只做一次完整确认；服务端事务校验展示版本/指纹，记录确认并创建尝试，随后执行器进行运行环境预检。模板缺少判据、预期证据、变量或清理说明时允许保留草稿并显示缺口，不能执行。
7. 左侧点击行用于查看，复选框用于批量；显示“已勾选 N 条，其中 M 条就绪”。批量按钮明确数量并列出未就绪项，统一确认后按顺序运行；每条派发前再核对已确认的版本及条件，发生变化则停止队列。
8. “测试结果与历史”顶部固定展示所选尝试的对象、验证目标、执行状态和系统验证结果；意见单独保留，不覆盖主结果。下方“证据与判据”查看关键观察和逐项判据，“人工意见与历史”可选填写意见并查看完整历史。人工意见不替代系统结果；如需补充意见，勾选证据、明确选择意见、填写依据后保存，不填证据编号，不展示原始 JSON 或完整输出。没有结构化关键数据时如实提示。

单条与批量共用启动/取消处理。等待详情时取消使旧回调失效；等待启动响应时取消会在响应返回后再次取消，关闭/销毁窗口也保留明确的取消意图。普通关闭只停止尚未派发的客户端队列，已提交运行继续，重新打开可查看或停止。队列不在客户端退出后自动恢复。

## 方案与载荷来源

推荐复用既有 Playbook 匹配器的发现类型、工具能力、目标兼容和条件判断，但只提供当前发现，不把整个任务的其他漏洞作为证据。文字相似不能证明适用。列表分为定向候选、待补条件、相关参考；权限、任务所有者、冻结快照和工具可用规格均在服务端检查。

034 新增三个可重复的内置定向模板：防护响应头、Cookie 属性、目录索引。模板前提、已有判据与清理条件被保留；旧模板没有的内容留空并显示阻断原因，不用“请填写”代替真实条件。旧模板的静态载荷引用保留为参考，不变成独立步骤输入；原本需要结构化载荷的步骤则等待手动绑定。

模型方案实例可直接返回顶层 steps，也可使用明确无冲突的 `{type,schema:{...}}` 实例包装；不递归搜索任意嵌套可执行内容。有限格式纠正带上上一条回答。生成或调整失败保留原版本和历史，错误归为方案准备结果，不产生攻击执行或漏洞结论。AI 可以建议载荷，但不能为新步骤静默绑定；AI 调整只能保留目标、工具、步骤输入、变量及载荷版本均未改变的原有用户绑定；变化后须重新手动绑定。

HTTP 入口从同任务、同主机已观察到的地址关联具体发现路径，保留协议与端口。缺少入口、多个端口/协议不唯一、路径越界时显示待补条件，不猜测或自动探测。普通 Nikto GET/POST/HEAD/OPTIONS 方法枚举属于信息，读取旧记录时重新归类，不改写原始扫描证据；包含其他方法或额外风险描述的记录仍保留候选。

载荷准备事件记录生成/复用，绑定事件记录步骤及版本。“本次新生成”来自当前验证项中对应版本的生成事件；再次换任务或验证项复用显示已有载荷，AI 来源仍保留。匹配、已关联和实际消费分别表示：可供选择、进入计划、执行器确认已启动的具体调用消费。被阻止/跳过或未启动工具时不报告已使用载荷。

## 自动判定与人工复核

判据由平台代码维护，在方案保存时根据当前发现、准确入口与对应 GET 步骤冻结 ID/版本。模型不能指定任意自动判据。仅同漏洞、同尝试、同方案指纹、同入口的成功完整响应参与判断；失败、中止、超时、截断、重定向、认证页、证据缺失或错配返回条件不足。

| 判据 | 自动判断范围 |
| --- | --- |
| 防护响应头 | 成功的完整 HTML 中 X-Content-Type-Options 缺失；或 X-Frame-Options 与有效 CSP frame-ancestors 同时缺失。明确的 DENY/SAMEORIGIN、CSP 'none'/'self' 为替代控制；其他复杂/模糊值交人工判断。 |
| Cookie 属性 | 扫描明确点名且本次响应设置的同名 Cookie 缺 HttpOnly；Secure 仅在 HTTPS 下判断。同名不同属性、未设置该 Cookie、属性采集截断或缺少完整性标记时返回条件不足。只保存名称与布尔属性，不保存 Set-Cookie 的值。 |
| 目录索引 | 完整 HTML 同时有与当前目录相符的 Index of 标题、父目录导航和同目录文件/子目录链接。单个关键词和 HTTP 200 不成立；403/登录页不当成修复或安全证明。 |

自动结论仅描述本入口配置缺陷或目录暴露，不推导代码执行、越权或敏感数据泄露成功。默认文件和管理登录页面没有通用自动漏洞结论；本轮未支持的其他效果类型显示能力或证据缺口，人工意见不能补足系统判据。

执行状态与系统结果独立：`completed/failed/aborted/unknown` 表示执行情况；版本化 `result.status` 表示是否达成冻结目标。人工意见不参与系统状态选择或目标达成计数，原自动记录、意见和证据保留。左侧“最新系统结果”属于最新尝试，右侧属于当前选择的尝试；新草稿与其他尝试不改变历史执行的目标或状态。

| 系统结果 | 条件 |
| --- | --- |
| 目标已达成 `achieved` | 服务端冻结的目标与平台注册规则适用；工具确实启动；同目标、尝试、版本、步骤及载荷版本的完整证据与已保存的自动判断一致，满足正向判据。 |
| 目标未达成 `not_achieved` | 适用操作完整结束，证据充分，并满足该规则支持的明确负向判据；不意味着漏洞不存在或已修复。 |
| 证据不足 `inconclusive` | 已有相关操作，但契约、规则、证据、归属、完整性或停止证明不足；异常、取消、截断不能当成目标未达成。 |
| 未开展适用验证 `not_performed` | 尚未执行、预检阻止操作，或只进行了页面可访问性检查而未开展适用效果验证。 |
| 等待结果 `pending` | 新契约对应操作仍在排队、运行或取消处理中。 |

系统成功必须连同目标名称展示：当前三个规则只证明响应头配置、Cookie 属性或目录暴露，不升级为其他安全影响。HTTP 200、退出码 0、人工填写 true、过程日志关键词均不能独立产生系统成功。

目录索引判据按版本执行：已有冻结 v1 方案保留标题路径严格比较的原语义；新保存的方案采用 v2，接受目录标题 `/docs` 与请求目录 `/docs/` 末尾一个斜杠的等价差异。不同目录、大小写、重复斜杠和编码路径分隔符不等价，外域链接不能满足同目录条目判据。未知规则版本返回条件不足，不能按最新规则静默判断。模板标识保持不变，规则版本独立冻结，无需数据库迁移。

旧记录的自动判断和人工意见保留为原始历史。缺少新验证契约时，系统不会追溯生成成功；页面请求步骤与关联观察可确定时显示“未开展适用的效果验证”，否则显示“历史目标未明确，证据不足”。再次执行旧计划前须保存新版本并重新确认。

## 数据与接口

033 保存验证项、计划版本、尝试及人工复核；034 为加法迁移，新增 `finding_payload_events` 和 `finding_verification_assessments`，并注册三个定向模板。计划快照增加服务端来源、父版本、步骤关联与判据元数据。父任务原有 Run 不覆盖，重试新建 Run，版本历史保留。

接口前缀 `/api/pipelines/:id/verifications`，有效用户必须是任务所有者或管理员；所有发现、步骤、载荷和证据引用再次核验归属。已有 confirm/execute 接口继续兼容。

| 方法/相对路径 | 用途与主要输入 |
| --- | --- |
| GET /，POST / | 列出验证项，或以 finding_id 幂等创建 |
| GET /:verificationId | 来源、计划历史、readiness、入口依据、载荷可读预览/事件、尝试/自动判断/人工复核 |
| GET /:verificationId/sources | 推荐；mode=all、q、offset、limit 用于浏览搜索，返回 items/total |
| POST /:verificationId/template | 兼容旧调用，读取模板草稿 |
| POST /:verificationId/select-template | playbook_id、expected_revision；使用模板并保存草稿 |
| POST /:verificationId/generate | expected_revision、mode=new/adjust、可选 instruction；两次模型调用上限 |
| POST /:verificationId/plans | expected_revision 和业务字段；人工保存新版本 |
| GET /:verificationId/payloads/:payloadId | 当前发现可见候选的预览、来源及步骤兼容性 |
| POST /:verificationId/payloads/prepare | expected_revision、step_id；先复用后生成，仅准备，不绑定 |
| POST /:verificationId/payloads/bind | expected_revision、step_id、payload_id、version；手动绑定或替换 |
| POST /:verificationId/payloads/unbind | expected_revision、step_id；解除绑定保存新草稿 |
| POST /:verificationId/preflight | revision；检查结构、范围、版本与缺条件，不发目标请求 |
| POST /:verificationId/start | revision、fingerprint、request_id、confirmed=true；事务确认并创建尝试 |
| POST /:verificationId/confirm，/execute | 保留旧两阶段调用，仍使用版本和幂等检查 |
| POST /:verificationId/cancel | 停止派发，请求取消；等待实际停止确认 |
| POST /:verificationId/reviews | attempt_id、conclusion、evidence_ids、note；人工复核 |

API 和 AI 方案草稿可提交 `objective_draft={label,category}`：label 为非空且最多 200 字的具体目标，category 仅允许 `accessibility/configuration_exposure/effect`。服务端保留该草稿并纳入版本指纹，但只有平台注册的适用规则才能授予自动判定能力；草稿不能指定 capability 或规则。已有适用规则的目标仍由规则定义。

新方案由服务端生成 `verification_contract` 并纳入指纹：包含 `schema_version`、检查对象与发现引用、目标及类别、步骤操作、能力说明、平台注册判据的 ID/版本、所需证据和负向支持能力、限制。客户端或 AI 不能伪造能力；保存新版本时重新推导，旧冻结快照不改写。当前仅接入既有三类规则，不新增效果工具或利用载荷。

详情与统计共用系统结果投影：

- `attempts[].summary.result`：`schema_version=1`、`status`、`reason_code/reason`、`object/objective`、`criterion`、实际步骤启动与证据引用 `operations`、`observed_facts`、支持结论的 `evidence_ids`、逐项 `checks`、`unverified` 和 `limitations`。先核对来源与目标，再判定执行、证据及规则；没有已保存自动判断时 GET 不创建新的判断。
- `human_opinions` 独立返回意见、依据、证据编号、复核人员与时间。保存意见不会改变 `result`；原 `reviews`、`assessments` 保留。
- 旧 `conclusion/method/note` 保留结构，但只由系统结果兼容映射；无法安全映射的状态为 `pending`。原人工优先的计算结果放在 `legacy_summary`，注明“历史口径，仅供参考”。新版 Qt 若未收到有效 `result`，显示“旧版接口，无法确认系统结果”，不得人工优先回退。
- `evidence[].criteria` 继续返回目录冻结规则版本和只读派生判据，不覆盖已保存判断；未知或缺失字段为“无法判断”。
- 当前统计声明 `result_schema_version=1`、`result_policy=system_evidence_only`；人工意见单独计数，不进入系统目标达成实例数。扫描、拓扑和新报告使用系统结果；旧冻结报告保持原内容并标注历史统计口径。

任务执行接口 `GET /api/pipelines/:id/execution` 增量返回 `verification_runs`，包含独立的逐漏洞执行计数和最近记录（默认最多 100 条，`has_more` 表示还有历史）。每条记录保留发现、验证项、尝试和子 Run ID、方案版本、系统结果及工具/证据计数；不包含原始响应。没有主 Run 时仍可显示这些子执行，不能用子 Run 替换主任务 Run 或将主预案标为完成。任务详情的 `summary.finding_verifications` 仅提供计数。

子执行投影核对任务/扫描归属、执行人、范围、冻结方案指纹及尝试链接；不可靠记录计入 `invalid_source_count`，不混入有效执行列表。读取不创建或修复记录。Qt 双击记录以 GET 打开指定历史尝试；关闭窗口只刷新仍匹配的任务上下文，迟到响应不会恢复旧任务。执行结束的 `pipeline:verification` 通知沿用任务所有者的事件分发。

这些字段使用现有方案 JSON 和只读投影，不需要数据库迁移。新旧前后端应配套加载；发布不自动重启服务或重跑目标。

400 输入/引用不合法，401 登录失效，403 权限，404 不存在/归属不符，409 版本/活动调用/缺条件/次数冲突；模型连接错误 502，有限纠正仍失败 422。原始模型/凭据内容不作为公共错误回显。

服务端计划最多 20 步，尝试上限 1–3 次、时长 1 秒–15 分钟；窗口默认两次、五分钟。执行固定步骤，不开放自由 ReAct 扩展。unknown 表示实际停止未确认，阻止重试及自动恢复，重启不会重放。

## 验证与交付

测试包含内存数据库迁移/旧记录兼容、单条发现推荐、方案来源、生成与复用事件、手动绑定与撤销、载荷变更、幂等确认启动、三类判据正反例、真实执行器与本机 HTTP 服务的 Cookie 脱敏、未启动工具不报告消费，以及人工意见不影响系统结果。Qt 包含完整方案→载荷预览→手动绑定→一次确认→模拟执行→判定/复核→回填动线，原有取消/版本/草稿竞态继续回归。

## 本机手动验收

先核对当前任务和执行状态，再启动本机程序。`scripts/start.sh` 会停止匹配的已有客户端和占用后端端口的 Node 进程，因此有活动调用或正在使用的客户端时不要重复运行。该脚本不负责构建前端。

开发模式使用仓库内 `backend/src/server.js`、系统 `node` 和 `build/frontend/RedTeam-Platform`。数据库连接读取 `DB_PATH`，未设置时使用仓库 `data/redteam.db`；`REDTEAM_DATA_DIR` 不覆盖数据库路径。前端服务器选择优先级为 `--server`、`REDTEAM_SERVER`、保存的 `server/url`、默认本机地址。如果 `scripts/bin/RedTeam-Platform` 存在且可执行，脚本会改走便携模式，须重新核对路径。

在仓库根目录、确认无活动调用后，由操作者启动：

```bash
DB_PATH="$PWD/data/redteam.db" PORT=3002 REDTEAM_SERVER=127.0.0.1:3002 bash scripts/start.sh
```

验收建议使用专门的测试任务，保留所有旧尝试及证据。前五项可检查准备过程；点击确认执行需要已明确授权的目标与操作范围。

1. 从任务工作台进入扫描结果，双击一条漏洞，应打开该条 F08 窗口；关闭后勾选两条漏洞，点击“打开勾选的漏洞”，检查名称、入口和归属。打开窗口不得触发工具或模型。
2. 选择推荐方案，查看来源、条件和步骤，再点击“使用此方案”。查看其他方案时不应自动替换当前草稿。默认文件、管理登录页不能仅凭存在或 HTTP 200 获得自动“验证成立”。
3. 明确点击“AI 生成新方案”或“AI 辅助调整”时才调用模型；成功后检查来源、版本、输入、判据及缺失条件。失败应保留原计划；保存草稿不得访问目标。
4. 手动选择步骤，查找或生成载荷，确认只有候选而没有自动绑定。查看内容、来源、适用条件，再点击绑定；解绑后，需要独立载荷的步骤应变为待补条件。无需独立载荷的内置检查保持其明确标识即可。
5. 修改并保存方案或绑定关系，确认产生新版本、旧确认失效。检查摘要中的目标、展开后的步骤输入、载荷关联、判据、预算和清理说明；取消确认框应不创建执行尝试。
6. 仅对授权目标确认开始。检查一个请求对应一个尝试、实际消费标记与执行证据一致。重复点击、修改版本和条件变化不得重复或越过确认执行；勾选多条时确认数量，验证顺序派发。中途取消后等待“停止确认”，`unknown` 不可当作已停止或直接重试。
7. 查看结果：先核对顶部对象、目标、实际执行和系统验证结果；系统依据不引用人工意见。左侧最新系统结果与右侧所选历史尝试要能区分。再到“证据与判据”选中证据行，查看完整安全字段和各项判据；复核勾选与查看行互不代替。响应状态、完整性、防护响应头和 Cookie 名称/属性应以业务字段展示，不展示响应全文或 Cookie 值。自动规则仅覆盖支持的三类检查；完整证据满足明确负向判据时可判本次目标未达成；截断、失败或错配证据应显示证据不足。
8. 在“证据与判据”勾选本次尝试的证据，进入“人工意见与历史”，明确选择人工意见、填写依据并保存；检查保存意见前后系统结果及目标达成计数不变，原自动判断、旧计划和历史意见保留。切换尝试不得沿用上一尝试的证据勾选；返回任务结果核对回填。
9. 在正常和窄窗口、实际显示缩放下检查完整动线，尤其是长载荷内容、缺失条件、取消反馈和复核按钮。模拟 API 的窗口回归不替代这一步，也不证明真实模型或靶场效果。

本机具体备份、构建、测试数量与截图记录放在 `.codex/` 的本次复查记录中，不作为其他机器已升级或已验收的证明。


### 证据展示与人工复核提示

默认窗口为 1360×860，并限制在当前屏幕可用范围内；左侧漏洞列表约占四分之一，可拖动分隔条调整。在 1024×600 等窄窗口中，顶部结果摘要保持可见，长依据可在详情查看。“证据与判据”使用紧凑证据行与选中行详情；“人工意见与历史”查看完整依据、限制、复核人和时间。证据行选中用于查看，复选框用于人工意见，两者相互独立。

F08 详情中的 `evidence[].observation` 从已保存的原始观察中先解析、再选择白名单字段并脱敏，包含状态码、入口、完整性、响应字节数、受支持响应头、Cookie 属性及 HTML 密码输入框特征。不会返回 HTTP 响应正文、Cookie 值或表单输入值。旧客户端使用的 `raw_stdout` 在字段脱敏完成后序列化为该安全观察的 JSON；它不再代表完整原始输出。原始入库证据不改写，自动判断仍使用原始证据。旧记录无需重跑或迁移即可提取这些关键事实；无法解析的旧记录不编造观察值。

密码输入框特征只帮助人工核对页面，不能证明它是管理员入口，更不能证明存在可利用漏洞。尚无适用判据的已完成尝试明确提示能力或证据缺口。人工意见初始为“请选择人工意见”，没有明确选择时不会提交；切换执行尝试会清空之前未提交的结论和说明，同一次尝试刷新仍保留填写内容。

达到尝试次数上限只阻止新执行，仍可查看已有记录和保存人工意见。不要因为对照路径返回预期 404 或结论待判定而重复执行；应先核对计划、已有证据与判据。


### 页面可访问性历史示例

只有可可靠识别为简单页面读取的登录页 HTTP 200 和不存在路径 HTTP 404 时，主结果显示“未开展适用的效果验证”。若旧方案还包含请求头、参数、内部输入或其他无法确定用途的设置，缺契约时显示“历史目标未明确，证据不足”，不只凭 GET 或页面名称推断用途。这两条安全观察仍可查看；旧人工 true/成立意见和人员时间保留在可选“人工意见与历史”，明确不替代自动验证结论。不能仅依据方案名称猜测执行了登录绕过或其他操作，也不追溯标记目标达成。


### 自验收边界修复

仅对消费方式为无需独立载荷、单个明确 GET/HEAD 请求且无查询、请求头、请求体、交互或变量的页面读取，使用可访问性兼容展示；其他 GET 不按方法名称推断用途。启动前取消或权限检查失败时，系统持久化明确未派发标记，在实际停止已确认后显示未开展；没有证据且没有明确未派发证明时仍为证据不足。统计启动口径与此保持一致。

尚无尝试时仍可展示已保存方案的对象和目标，状态为尚未执行，不将“没有尝试”误写成“没有适用方案”。任务结果列表读取版本化系统结果；旧统计柱图和筛选显示历史口径，不把旧 confirmed 重新解释为系统确认。


### 再验收的异常数据与完整文档边界

旧方案内容为 `null`、标量、数组、缺少必要步骤或步骤／变量结构无效时，仅在读取投影中标记历史结构无效、禁止直接启动，保留原快照与人工意见；不应返回详情 500。前端只接受版本化结果的五种状态，未知枚举降级为证据不足，不能借用旧 confirmed 或人工意见补成成功。

HTTP 传输完成不一定代表完整页面：响应头／目录文档目标遇到 204、205、206、空白正文或明确 Content-Range 时，系统结果为证据不足；逐项文档判据显示无法判断。旧自动判断不被覆盖。Cookie 属性目标可依据完整、同名的明确响应头属性判定，不因 204 没有页面正文而一并否定其已有属性证据。
