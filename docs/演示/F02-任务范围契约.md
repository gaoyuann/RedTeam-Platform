# F02 任务范围契约

新建任务的 `config.task_scope` 保存结构化范围。`includes` 是 IP、IPv4 CIDR、主机名、HTTP/HTTPS URL 或 `tcp://主机:端口` 的数组；`excludes` 使用相同格式。主目标必须在 `includes` 内且不能被排除。URL 范围按协议、主机、端口和路径前缀匹配，`/app/` 不包含 `/other`。任务配置还保存 `execution_location`、`environment_ref`、`auth_config_ref` 和 `discovery_budget`。引用字段只保存编号，不应填写密码或令牌。

创建时后端规范化配置；任务详情返回 `missing_conditions`。`scanner` 表示当前扫描端；`remote` 目前缺少执行适配，启动会被拒绝。认证配置引用目前没有凭据提供方，详情明确提示，扫描计划不能把需认证的检查记作已覆盖。旧任务没有 `task_scope` 时按原目标推导展示范围，保留原有扫描行为；新任务一律保存 `version: 1` 的范围对象。

新任务的子扫描在执行前核对父任务、所有者和范围。局域网自动发现只有候选网段整体在范围内才执行；包含排除目标的网段不执行。无法保证遵守路径限制或跳过排除 URL 子路径的通用 Web 扫描会被阻止并记录原因；入口发现改用受控 HTTP 请求，重定向每跳重新检查范围。关联执行 Run 的固定步骤与动态动作继续使用原有目标检查，并附加结构化范围检查。任务启动后不能修改范围；如需改变，创建新任务。

示例：`includes: ["https://range.example/app/"]`，`excludes: ["https://range.example/app/admin/"]`。可直接请求 `/api/pipelines/:id` 查看范围和缺失条件；扫描结果与原因仍在 F04 的任务结果接口查询。

范围规则限制平台发起的调用，不代替人工确认靶场授权。F01 的真实环境版本、地址、可用扫描位置及认证配置清单尚待交接；本地隔离测试不代表跨端联调完成。
