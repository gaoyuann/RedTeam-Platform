### 一、项目背景与内容边界

项目名称：**信息系统渗透智能化测试平台**。

项目面向授权安全测试场景，将测试目标、测试任务、工具资源、智能分析、验证过程和结果报告组织在统一的业务体系中，服务于测试人员、管理人员和教学人员。建设内容包括软件平台、中心服务资源、操作终端、目标测试环境以及授权与运行保障组件。

介绍重点是：项目是什么、软件由什么组成、架构如何支撑业务、硬件承担什么角色、功能如何使用、结果如何组织、能够给甲方带来什么价值。不要做成研发进度、问题整改或内部工作总结。

以下内容是用于介绍项目的能力与方案口径，不代表本次已经完成现场验收。可以据此撰写功能描述，但不要扩展为“全部测试通过”“已成功利用”“达到某性能指标”等结果声明。

**两套软件的介绍口径：**

- 智能测试平台：侧重测试组织与智能辅助，包括任务组织、资源配置、资产与拓扑、智能分析、知识库与预案、测试评估和报告管理。
- 渗透测试平台：侧重扫描与验证，包括漏洞扫描、攻击目标选择、载荷或测试步骤组织、受控执行、原始输出与证据采集。
- 二者围绕目标、任务、资源、执行和报告共同构成项目的软件能力体系。这是业务职责描述，不要推断二者已经共享数据库或存在特定接口连接。

**软件总体架构：**

采用四层逻辑架构进行解释；这些是职责分层，不代表四个独立服务或四台设备。

1. 交互层：Qt/C++ 客户端，承载任务创建、目标配置、过程监控、结果查看和系统管理。
2. 服务层：Node.js 后端，承载平台 API、任务调度、权限控制、配置管理和状态同步；WebSocket 用于状态通信。
3. 能力层：拓扑探测、漏洞扫描、智能分析、载荷生成、预案管理、受控执行、评估与报告。
4. 数据与资源层：SQLite 数据存储，以及任务、日志、证据、报告、安全工具、知识库、模型服务和靶场资源。这里的数据存储、服务与外部测试资源要分组表达，不要画成所有资源都存储在 SQLite 中。

**硬件与部署角色：**

- 中心服务资源：承载后端、数据存储、工具服务及相关资源管理。
- 操作终端：承载客户端操作，支持任务配置、执行监控和结果审阅。
- 被测系统与靶机：提供授权测试对象，包括源代码软件系统和 Web 靶场。
- 测试网络：承载授权实验环境内的连接与访问。
- 加密锁：作为软件授权相关的硬件组件，与权限管理、操作记录共同构成运行保障。

只介绍上述角色，不填写具体设备型号、台数、IP、操作系统版本、性能参数或模型部署位置，也不要自行补充 GPU、云服务或其他设备。可用“面向国产化软硬件环境的部署需求”介绍适配方向，不宣称已完成所有兼容认证。

**七类功能模块：**

1. 资源部署与系统配置：组织工具、靶场、模型、容器和平台参数。
2. 预案与知识库：组织测试预案、漏洞知识和工具使用信息。

4. 结果统计：说明任务状态、风险分类、验证状态、评分、报告和证据追溯。
5. 拓扑探测：说明目标发现、主机/端口/服务识别和资产关系查看。
6. 加密锁：说明设备识别、授权状态和受保护功能的展示内容，不宣称现场已经验证成功。
