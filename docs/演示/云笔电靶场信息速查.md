# 云笔电靶场信息速查

整理日期：2026-10-08。依据：《云笔电被测软件系统与目标靶机说明.docx》及师弟补充的实际访问入口。

**记住三个主机：110 是渗透测试平台，111 是 Web 靶机，113 是 C/C++ 被测系统。** 以下仅供授权实验内网使用，不要公开传播账号或将靶场映射到公网。

## 二、六个靶场怎么访问

| 名称 | 完整入口 | 访问方式 | 主要测试内容 |
| --- | --- | --- | --- |
| DVWA | `http://192.168.1.111:4280` | 浏览器直接打开 | SQL 注入、XSS、命令注入、文件上传/包含、认证与会话等 Web 练习 |
| Pikachu | `http://192.168.1.111:8765` | 浏览器直接打开 | 注入、XSS、越权、认证、文件、业务逻辑与会话等综合练习 |
| SQLi-Labs | `http://192.168.1.111:8088` | 浏览器直接打开；测试时按具体 lesson 选择入口 | 错误回显、联合查询、布尔盲注、时间盲注等 SQL 注入练习 |
| vulnerable-webapp | `http://192.168.1.113:8089` | 浏览器直接打开；含 dump/view/post 三个 CGI 入口 | C/CGI 请求处理、缓冲区边界与命令执行等教学风险验证 |
| vuln-demo.c | `http://192.168.1.113:8090` | 浏览器直接打开 | C 服务请求、进程和命令回显链路验证 |
| exploit_me（也称 exploitme） | `192.168.1.113:8091` | **TCP 交互，不是 HTTP；交给 agent 连接测试** | ARM/ARM64 交互式命令行二进制的分级漏洞练习 |

**8091 浏览器打不开是正常现象。** exploit_me 原本是命令行程序，为便于 agent 访问才额外开放了 TCP。不要将其写成 `http://192.168.1.113:8091`，也不要当作网站漏洞扫描目标。

`vuln-demo.c` 内部监听 `127.0.0.1:18090`，由 Apache 的 `8090` 对外代理；普通使用者只访问 `8090`，不需要访问或暴露 `18090`。

## 四、怎么选测试方式

- **第一次演示选 DVWA：** 目标填写 `http://192.168.1.111:4280`，预案选择 **DVWA 黄金杀伤链 (10工具饱和打击版 v2)**，编号 `golden_dvwa_max_tools`。具体点击流程见《云笔电操作手册：DVWA 演示流程》。
- **Pikachu / SQLi-Labs：** 另建任务，使用对应的 Web 或 SQL 注入预案；SQLi-Labs 应指向实际 lesson，不能只扫首页就声称全部题目验证完成。
- **vulnerable-webapp / vuln-demo.c：** 可做 HTTP 发现、Web 初筛和授权回显验证；内存破坏、控制流类问题还需 ARM64 源码/二进制分析及人工复核，不等同于普通 Web 扫描。
- **exploit_me：** 向 agent 提供 TCP 地址 `192.168.1.113:8091`、程序类型及授权范围，要求保留交互输入/输出和证据；不要套用 DVWA 预案，不做拒绝服务、关机等破坏性测试。

## 五、版本与数量：报告不要混用口径

| 对象 | 原说明的版本/覆盖口径 | 应如何理解 |
| --- | --- | --- |
| vulnerable-webapp | ARM64 CGI，3 个入口 | 3 个入口不是 3 个已确认漏洞；源码仓库的 x86_64 载荷不能直接视为 ARM64 可用 |
| vuln-demo.c | ARM64 debug；至少 2 类教学风险 | 具体漏洞数量需按实测和源码复核，不写成固定漏洞总数 |
| exploit_me | 本项目选定的 14 级版本 | 涵盖整数/栈/堆溢出、越界、off-by-one、栈 cookie、格式化字符串、类型混淆、零指针、命令注入、路径穿越、ROP、UAF、JOP；**不是已自动利用 14 个漏洞** |
| DVWA | `local/dvwa:arm64`，配套 MariaDB 10 | 按实际启用模块和安全级别统计，原清单未固化漏洞总数 |
| Pikachu | AMD64 镜像在 ARM64 主机经 QEMU 运行；52 场景、50 个独立 PoC 的资料口径 | 仅作为已有资料记录；实际 fork、配置和验证结果需逐项核对 |
| SQLi-Labs | 常用版本 65 lessons | 不是本次已验证数量；以当前部署目录和实际测试 lesson 为准 |

## 六、交接时确认这 4 件事

1. **入口以本表为准：** 师弟补充明确 SQLi-Labs 是 `8088`，exploit_me 对外 TCP 是 `8091`。本次 DVWA 不使用旧文档里的 `localhost:8080`、`172.17.x.x` 容器地址。
2. **黄金预案需先适配：** 确认使用 `192.168.1.111:4280` 的地址、端口和有效会话，所需工具/字典齐全。仓库旧模板含固定探测端口、默认本地地址和固定会话值，仅修改目标输入不能保证完成全部步骤。
3. **测试结果以证据为准：** 开放端口、HTTP 页面可达、工具成功退出和模型结论，都不单独证明漏洞已验证；不同靶场分别记录目标、入口、执行编号和证据。
4. **未做现场连通性验收：** 本表根据交接资料整理，未连接这些内网主机或执行测试。正式演示前由现场同学确认平台已连接、Web 页面可达、TCP 服务可连；异常联系维护人员，不自行清库、关机或更改部署。
