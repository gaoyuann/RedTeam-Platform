# F03 服务发现与检查计划

新任务先执行端口与服务识别，再根据真实 `open_port` 证据建立资产、服务和入口。资产、服务、入口及检查项使用基于任务和对象内容的稳定 ID，并保留来源扫描记录 ID。仅服务名称明确显示 HTTP/HTTPS，或用户提供的 URL 与该服务主机、端口相符时，才安排 Web 检查；私有 IP 本身不代表 Web 应用。

HTTP 服务先做受控入口探测；用户声明的 HTTP URL 即使端口识别没有结果，也保留探测机会。取得范围内成功响应后，安排 Web 安全检查与 API 路径、参数发现。扫描中发现的链接、表单动作和 API 端点单独记录；范围内新 URL 按 `task_scope.discovery_budget` 补充 Web 检查，预算用尽标为`未检查`，范围外标为`范围外`。路径范围过窄或有排除项时，不能保证遵守范围的通用扫描标为`缺条件`。发现参数后记录入口，但没有逐参数验证条件时标为`未检查`。认证角色在凭据提供方接通前标为`缺条件`。SSH 等非 Web 服务保留已识别服务和`未支持专项检查`状态，不将端口识别当成漏洞检查。

每项检查保存`待执行`、`执行中`、`已完成`、`部分完成`、`失败`、`已取消`、`不可达`、`未支持`、`缺条件`、`范围外`或`未检查`状态。取消或异常结束时，未运行的计划项转为`未检查`。子扫描结果继续使用 F04 的任务结果接口；`scan_coverage` 给出资产、服务、入口和检查状态。界面展示前 500 项并明确提示截断。完整清单可按类型稳定分页查询：

```text
GET /api/pipelines/:id/results/coverage?kind=assets|services|entries|checks&limit=100&after=<上一页 next_after>
```

该接口沿用父任务所有者权限。F01 的真实靶场服务基准、认证角色和跨端调用尚待联调；服务识别与检查计划的本地样例不代表全部漏洞覆盖。旧任务保留原扫描编排和结果读取，只有新建任务含 `task_scope` 时启用逐服务计划。
