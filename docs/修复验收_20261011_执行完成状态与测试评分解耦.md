# 执行完成状态与测试评分解耦

## 1. 需求与新规则

按用户要求，执行页的“完成”仅表示执行流程正常结束，不再承担测试通过或失败的判定。测试效果统一查看“测试评分”以及原始步骤、证据和日志。

| 场景 | 执行状态与展示 |
| --- | --- |
| 执行流程正常结束，所有工具成功 | `COMPLETED`，已完成 |
| 执行流程正常结束，部分或全部工具失败 | `COMPLETED`，已完成；保留失败步骤 |
| AI 正常返回停止动作，仍有未执行步骤 | `COMPLETED`，已完成；保留停止原因与未执行计数 |
| 操作员手动中止 | `ABORTED`，已中止 |
| 整体执行超时 | 保留 `FAILED` 与运行超时诊断 |
| 预检失败或未捕获系统异常，不能正常执行 | 保留原有异常状态和原因，不伪装成完成 |

单个工具的超时、输入拒绝、非零退出等结果不被改写。正常结束后，即使这些步骤失败，整体仍显示完成；这些结果继续用于评分和证据复核。

新汇总中的 `completionPolicy` 为 `execution_finished`。正常完成时，整体 `error` 为 `null`，但步骤失败、未执行数量、`hasNonOptionalFailure`、停止原因等事实仍保留。

## 2. 修改范围

- `backend/src/services/executionState.js`：正常结束统一汇总为 `COMPLETED`；按最终步骤结果计算成功、失败与未执行数量，避免重试累计计数失真。
- `backend/test/execution-state.test.js`：新增 10 项回归测试，覆盖必需步骤失败、AI 扩展失败、全部工具失败、AI 停止、重试计数、人工中止、整体超时和索引分配。
- 未修改评分算法、步骤成功标记、工具退出码、证据、流水线执行代码或前端代码。

前端执行页、测试评分页已有 `COMPLETED` → “已完成”的映射。流水线执行阶段已有正常返回且运行状态为 `COMPLETED` 时继续完成的逻辑，本次无需额外界面或流水线修改。

“已完成”不是“全部步骤通过”或“漏洞利用成功”；最终测试效果仍以评分和证据为依据。
