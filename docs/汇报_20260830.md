### 修改一：攻击测试3类编排 -- 对应需规 4.5(1)(2)(3)

**需规要求**：漏洞攻击测试模块包含3个子功能 -- (1)数据抵近窃取 (2)信息篡改欺骗 (3)关键设备夺控

**之前的问题**：3类编排仅实现为下拉过滤条件，功能上等于搜索过滤，不构成独立功能点。

**做了什么**：

1. Playbook分类标签补全：14个playbook按攻击类型归类到3个分组（data-exfiltration / tampering-deception / device-control），攻击执行页面可按类型筛选。

2. 执行详情页改造：改为左右分栏布局，左侧展示AI决策推理过程，右侧展示步骤执行详情和攻击证据，便于理解攻击链路和决策依据。

3. ReAct推理引擎增强：
   - 新增探索模式，面向未知应用时鼓励基于证据动态探索而非严格按预设脚本推进
   - 启发式规则库：发现HTTP端口自动插入目录枚举步骤，发现SQL错误自动插入注入测试步骤，发现登录页自动插入暴力破解步骤
   - 失败恢复新增pivot策略：某条攻击路径失败时自动切换攻击方向，而非直接终止
   - LLM输出清洗：去除英文冗余内容，保留中文推理结论

**完成状态**：部分完成

- [已完成] Playbook分类标签补全
- [已完成] 执行详情页分栏布局
- [已完成] ReAct推理引擎增强

### 修改二：扫描到攻击的工作流串联 -- 对应需规 1.2 "完整攻击链自动化"

**需规要求**：自主执行从漏洞扫描到漏洞利用到漏洞攻击维持持久化的完整攻击链。

**之前的问题**：扫描和执行是分离的手动流程，用户需手动跳转3个页面、点击4-5次按钮才能完成一次测试。

**做了什么**：

1. 扫描页面重构：改为左右分栏布局，左侧展示扫描任务和结果，右侧展示匹配推荐的攻击方案。扫描完成后自动推荐匹配的攻击方案，提供"前往执行"按钮一键跳转到攻击执行页面（自动选中方案并填入目标地址）。

2. 扫描执行器扩展：新增3种面向应用程序的扫描类型 -- 应用技术栈发现（whatweb+httpx）、API端点模糊测试（arjun+ffuf）、认证机制审计（nuclei认证模板）。同时去掉了对DVWA靶场的默认路径假设，改为通用路径探测。

3. 目标分类扩展：新增4种目标类别（web应用、REST API、GraphQL API、单页应用），支持两阶段分类 -- 先基于URL模式静态分类，扫描后再根据结果动态修正。

4. 知识增强器扩展：加载OWASP Top 10知识库，根据扫描发现的风险类别自动注入对应的应用安全知识到推理引擎，使攻击决策有领域知识支撑。

5. 攻击方案匹配和生成增强：扩展通用Web应用匹配规则，支持接收扫描分析结果作为额外输入来生成更精准的攻击方案。

**完成状态**：部分完成

- [已完成] 扫描页面分栏布局和自动推荐
- [已完成] 新增应用扫描类型
- [已完成] 目标分类扩展
- [已完成] OWASP知识注入
- [未完成] PipelinePage一站式工作流 -- 仍需手动跳转页面，未实现扫描到分析到生成到执行的全自动流水线

## 向老师提出的问题

### 问题1：攻击测试3类编排的实现形式

需规要求3个子功能：(1)数据抵近窃取 (2)信息篡改欺骗 (3)关键设备夺控

这三者在实战中有逻辑递进关系但不刚性：窃取是前提，篡改是手段，夺控是目标，但有时先拿到shell再窃取数据，有时篡改和窃取交替进行。

当前已完成的仅为分类标签级别（3个Tab过滤攻击方案列表），尚未达到独立功能点的层次。

两种方案：

|  | 方案A：Campaign战役模型 | 方案B：增强分类标签（当前状态） |
|---|---|---|
| 做法 | 3类作为战役的3个阶段，阶段内可编排多个攻击方案，阶段间可传递产物（如窃取到的凭据自动传入夺控阶段） | 3类作为攻击方案的分类标签，UI用3个Tab展示 |
| 优点 | 架构层次高，阶段间产物传递，符合实战逻辑 | 改动小，已实现 |
| 缺点 | 工作量大（需新增4张数据库表、后端API、前端页面） | 功能层次浅，等于搜索过滤，不构成独立功能点 |
