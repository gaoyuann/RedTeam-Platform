## 二、老师提出的修改要求

### 要求1：基于现有系统重新设计，前端改用 Qt

- 基于当前已实现的项目系统，重新设计一个新系统
- 前端按照功能结构图拆分为对应的模块
- **前端必须使用 Qt 开发**（为了更好兼容 Linux 及国产操作系统，如银河麒麟、统信UOS等）
- 替代当前的 React + Electron 前端方案

### 要求2：未实现模块先做前端壳，后续逐步实现

- 对照功能结构图，**未实现或未完全实现的模块**先把 Qt 前端界面做出来
- 后端逻辑后续再慢慢补全
- 具体需要先做前端的模块：
  - 网络拓扑探测与绘制（4个子功能全部未实现）
  - 加密锁验证
  - 测试报告自动生成 / 测试报告管理

### 要求3：系统需要数据库

- 当前系统**没有数据库**，所有数据基于 JSON 文件和内存
- 新系统需要引入数据库（需确定选型：SQLite / PostgreSQL / MySQL 等）

### 要求4：工作流改造 — 先扫描再生成Playbook

- **当前流程**：直接选择 Playbook → 执行 → 对靶场测试
- **要求流程**：先扫描目标 → 展示扫描结果 → 基于扫描结果智能生成 Playbook → 再执行
- 当前系统缺少"扫描结果驱动的 Playbook 自动生成"这一环节
- 这是核心工作流的变更，影响架构设计

## 四、架构决策分析

### 4.1 Qt 用 C++ 还是 Python？

| 维度 | C++ Qt (Qt6 + CMake) | Python Qt (PySide6) |
|------|----------------------|---------------------|
| 运行性能 | 原生编译，启动快，内存小 | 解释执行，启动慢，内存大 |
| 打包体积 | 静态链接 ~30-50MB | PyInstaller 打包 ~150-300MB（含 Python 运行时） |
| 国产OS兼容 | 编译即适配，无运行时依赖 | 需捆绑 Python + glibc 版本匹配，易出问题 |
| 开发速度 | 较慢（手动内存管理、构建配置） | 快（动态类型、丰富生态） |
| 分发可靠性 | 单二进制/AppImage，拷贝即用 | 依赖 Python 版本、glibc、so 兼容性 |

**结论：用 C++ Qt。** 理由：

1. 系统要物理迁移到其他设备（U盘/光盘），C++ 编译产物是单一二进制，拷贝即用；Python 打包在国产 OS 上 glibc 不匹配是常见坑
2. 国产系统（银河麒麟/统信UOS）内核版本差异大，C++ 静态链接或 AppImage 打包可规避运行时依赖问题
3. 作为安全测试工具，启动速度和资源占用有要求，C++ 优势明显
4. Qt 本身就是 C++ 框架，用原生绑定最稳定，Python 绑定在国产 OS 上的 Qt 版本可能滞后

### 4.2 工具容器化

当前 28 款安全工具直接装在宿主机上，迁移到其他设备时需要重新安装依赖。**必须容器化**。

- **容器引擎选型**：
  - Docker：生态最成熟，但银河麒麟 V10 SP1+ 才有官方支持，老版本需手动装
  - **Podman**：Daemonless，无需 root，RedHat 系国产 OS 原生支持，与 Docker CLI 兼容
  - 建议：**优先 Podman，Docker 作为备选**，Qt 前端自动检测可用引擎
- **工具镜像策略**：
  - 每款工具一个轻量镜像（基于 Alpine），或按类别分组（recon / exploit / brute）
  - 镜像打包进分发介质，离线加载 `podman load -i tool_nmap.tar`
  - 首次启动时自动检测并加载镜像
- **容器与后端交互**：
  - 现有 Node.js 后端通过 `child_process` 调用工具 → 改为调用 `podman run <tool_image>`
  - 工具执行结果通过容器 stdout/挂载卷 返回

### 4.3 离线分发与物理迁移

系统作为独立软件分发，不能依赖网络服务：

- **分发格式**：
  - Linux：**AppImage**（单文件，无需安装，FUSE 挂载即运行）或 deb/rpm 包
  - 国产OS：银河麒麟发 rpm，统信UOS 发 deb，同时提供 AppImage 通用版
- **打包内容**：
  ```
  RedTeam-Platform/
  ├── RedTeam-Platform.AppImage        # Qt 主程序
  ├── backend/                          # Node.js 后端（内嵌 node 运行时）
  │   ├── node                          # 内嵌 Node.js 二进制
  │   ├── server.js                     # 后端入口
  │   └── node_modules/                # 依赖
  ├── containers/                       # 工具容器镜像（离线 tar）
  │   ├── tool_nmap.tar
  │   ├── tool_sqlmap.tar
  │   └── ...
  ├── data/                             # 数据目录
  │   ├── redteam.db                    # SQLite 数据库
  │   ├── knowledge_graph/              # 知识图谱 JSON
  │   └── playbooks/                    # Playbook 配置
  └── start.sh                          # 一键启动脚本
  ```
- **一键启动**：`start.sh` 先启动 Node.js 后端（本地 localhost），再启动 Qt 前端，前端连 localhost 后端

### 4.4 后端复用策略

回答"问题1：后端能否直接调用现有系统"——**可以复用，且应该复用**。

现有 Node.js 后端已具备：28 款工具执行、23 套 Playbook 引擎、知识图谱、Preflight Gate、Score V2、LLM 推理。重写代价巨大且无必要。

**复用方式**：
- Node.js 后端作为**本地服务**随软件启动，绑定 `127.0.0.1:3002`
- Qt 前端通过本地 HTTP 请求调用后端 API（不是网络服务，是进程间通信）
- 新增的业务逻辑（数据库操作、扫描驱动 Playbook 生成）在 Node.js 后端中扩展
- 最终分发时内嵌 Node.js 运行时，用户无需单独安装 Node

## 五、修订后架构方案

```
┌──────────────────────────────────────────────────┐
│           Qt6/C++ 前端 (AppImage 分发)            │
│  ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐   │
│  │部署  │ │扫描  │ │攻击  │ │评估  │ │管理  │   │
│  │配置  │ │探测  │ │测试  │ │报告  │ │系统  │   │
│  └──────┘ └──────┘ └──────┘ └──────┘ └──────┘   │
└────────────────────┬─────────────────────────────┘
                     │ HTTP (127.0.0.1:3002)
┌────────────────────┴─────────────────────────────┐
│         Node.js 后端 (内嵌运行时，本地服务)         │
│  · Playbook 引擎    · 知识图谱推理                  │
│  · Preflight Gate   · Score V2 评分                │
│  · LLM 推理(CORTEX) · 数据库操作(SQLite)            │
│  · 扫描驱动Playbook生成（新增）                      │
└────────┬───────────────────────┬──────────────────┘
         │                       │
┌────────┴────────┐   ┌─────────┴──────────────────┐
│  SQLite 数据库   │   │  Podman/Docker 容器引擎     │
│  · 用户/任务/配置│   │  ┌────┐ ┌────┐ ┌────┐      │
│  · 扫描结果      │   │  │nmap│ │nuclei│ │sqlmap│   │
│  · 测试报告      │   │  └────┘ └────┘ └────┘      │
│  · 执行记录      │   │  每款工具一个容器镜像        │
└──────────────────┘   └────────────────────────────┘
```

**关键决策（修订版）：**
- **前端**：Qt6 + C++ + CMake，编译为 AppImage / deb / rpm 分发
- **后端**：保留现有 Node.js，内嵌 Node 运行时，作为本地服务启动
- **数据库**：SQLite（单文件，随软件分发，物理迁移时直接拷贝）
- **工具执行**：Podman/Docker 容器化，镜像离线打包，首次启动自动加载
- **通信**：Qt ↔ Node.js 通过 localhost HTTP（进程间通信，非网络服务）
- **分发**：单目录包含所有组件，`start.sh` 一键启动
