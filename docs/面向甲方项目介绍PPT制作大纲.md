# 信息系统渗透智能化测试平台

## 面向甲方的项目介绍 PPT 制作大纲（修订版）

> **PPT 定位：** 面向甲方介绍项目建设内容、软件产品组成、软件架构、硬件部署、功能能力和交付价值。
>
> **汇报主线：** 项目定位 → 软件产品介绍 → 软件总体架构 → 软硬件部署 → 平台模块与业务闭环 → 六项功能演示 → 安全保障与交付 → 建设价值。

## 一、制作原则

- 先回答“项目是什么、软件由什么组成、软件如何运行、硬件如何支撑”，再进入功能演示。
- 将智能测试平台和渗透测试平台作为协同的软件产品组成，说明各自职责和共同支撑关系。
- 单独介绍客户端、服务端、能力引擎、数据与资源层；不以单张功能截图替代软件架构说明。
- 功能演示页以需求文档的六项能力为主线；截图、统计数值和硬件参数未现场核验前只保留占位符或通用表述。
- 对外使用建设内容、产品能力、技术方案、应用价值和交付体系等表述，不展开内部研发过程或过程性问题。

## 三、逐页内容

### 第 1 页：项目名称与建设定位

**标题：** 信息系统渗透智能化测试平台
**副标题：** 智能测试平台与渗透测试平台软硬件一体化建设
**主结论：** 项目面向授权安全测试场景，建设统一管理、智能辅助和结果追溯的平台能力。

页面包含项目名称、建设单位、汇报单位、日期，以及面向测试人员、管理人员和教学人员的服务定位。使用交大模板封面版式，不放未确认的功能截图或测试结果。

### 第 2 页：汇报目录

**主结论：** 通过目录明确项目、软件架构、功能演示和交付价值的汇报路径。

使用模板“目录-2”版式，按以下五个章节展示：

1. 项目与软件产品（第 3 页）。
2. 软件架构与部署（第 4—5 页）。
3. 平台模块与业务闭环（第 6 页）。
4. 六项功能演示（第 7—11 页）。
5. 安全保障与建设价值（第 12—13 页）。

目录页不放功能截图，不堆叠正文，确保投影环境下能够快速识别汇报结构。

### 第 3 页：项目与软件产品概况

**主结论：** 项目由两套相互协同的软件平台组成，分别承担测试组织管理和渗透验证执行能力。

| 内容区 | 建议说明 |
|---|---|
| 项目建设对象 | 面向信息系统、源代码软件系统和目标靶场开展授权安全测试；统一管理目标、任务、工具资源、执行记录和报告。 |
| 智能测试平台 | 提供任务组织、资源配置、资产与拓扑、智能分析、知识与预案、评估与报告等能力。 |
| 渗透测试平台 | 提供漏洞扫描、目标验证、攻击载荷、受控执行和证据采集等能力。 |
| 共同支撑 | 两套软件围绕任务、资源、执行、证据和报告协同工作。 |

页面左侧放项目建设对象，右侧并列两套软件平台卡片，底部用共同支撑字段收束。需要现场确认两套软件的正式名称、版本、部署位置、职责边界和数据共享关系。

### 第 4 页：软件总体架构与技术分层

**主结论：** 软件采用客户端、服务、能力引擎、数据与资源分层协同的架构。

| 分层 | 建议说明 |
|---|---|
| 交互层 | Qt5/C++ 客户端，承载任务创建、目标配置、过程监控、结果查看和系统管理。 |
| 服务层 | Node.js 后端，承载任务调度、权限控制、配置管理、状态同步、WebSocket 通信和平台 API。 |
| 能力引擎层 | 承载拓扑探测、漏洞扫描、智能分析、载荷生成、预案管理、受控执行、评分和报告。 |
| 数据与资源层 | 承载任务、日志、证据、报告等过程数据，以及安全工具、知识库、模型服务和测试靶场。 |

使用四层分区卡片或分层架构图；每层保留 2—4 个关键词，细节通过讲解补充。两套平台的接口、数据共享和独立运行边界以现场确认结果为准。

### 第 5 页：软硬件一体化部署

**主结论：** 中心服务、操作终端、测试网络和授权目标共同构成平台运行底座。

- **中心服务资源：** 承载平台服务、数据库、容器工具、模型服务和报告资源。
- **操作与测试终端：** 承担任务配置、过程监控、结果审阅和现场操作。
- **被测与目标环境：** 包括被测源代码软件系统、Web 靶场、专项靶场或目标靶机。
- **授权与扩展硬件：** 包括 USB 硬件加密锁，以及现场实际使用的网络设备、GPU、虚拟机或专用设备。

左侧使用设备角色表或实物照片占位，右侧说明中心服务区、操作终端区、被测区和授权硬件。服务器型号、终端数量、操作系统、CPU 架构、网络角色和设备地址以现场盘点为准。

### 第 6 页：平台模块与业务闭环

**主结论：** 平台模块围绕目标、任务、资源、执行、评估和报告组织完整业务。

| 模块 | 主要能力 |
|---|---|
| 资源部署与系统配置 | 工具、靶场、模型、容器、平台和系统参数 |
| 预案与知识库 | Playbook、知识图谱、漏洞知识和工具资源 |
| 网络拓扑探测 | 目标发现、主机/端口/服务和拓扑关系 |
| 脆弱性扫描 | 扫描任务、结果列表、风险线索和智能分析 |
| 漏洞攻击测试 | 攻击目标、载荷/预案、执行过程和证据 |
| 测试评估 | 执行评分、风险汇总、报告和证据查看 |
| 系统管理 | 用户、权限、任务、审计和基础配置 |

采用模块卡片或分组矩阵，底部用文字概括：目标管理 → 任务组织 → 资源调用 → 受控执行 → 结果评估 → 报告交付。模块名称最终与实际客户端导航保持一致。

### 第 7 页：被测源代码系统渗透与攻击测试

**主结论：** 对每个被测源代码系统形成扫描发现、漏洞列表、逐项验证、定向攻击和证据交付闭环。

展示被测系统清单和类型、扫描任务和范围、漏洞列表、逐项验证状态、攻击目标与候选漏洞清单、执行状态和证据入口。素材使用漏洞扫描结果列表主截图、逐项验证局部截图和攻击目标清单。所有被测源代码系统、平台分工、载荷适配范围和对外展示字段需现场确认。

### 第 8 页：目标靶场渗透与攻击测试

**主结论：** 对目标靶场通过任务统一组织目标配置、扫描、预案、受控执行、证据和报告。

选择一个主靶场作为完整案例，展示目标配置、授权范围、扫描结果、预案或 Flow、执行监控、关键输出、目标侧证据和报告入口。其他靶场以覆盖矩阵简要说明。DVWA、Pikachu、SQLi-Labs 等对象以现场连通性、版本和授权清单为准，历史地址、历史 Run 和统计不能直接作为本次结果。

### 第 9 页：PentAGI 与大语言模型载荷生成能力对照

**主结论：** PentAGI Agent 编排和直接大语言模型生成形成两条可对照、可审核的载荷生成路径。

| 对照项 | PentAGI 路径 | 大语言模型路径 |
|---|---|---|
| 输入 | 目标、漏洞线索、任务上下文 | 目标、漏洞线索、结构化提示 |
| 生成方式 | Agent/任务上下文组织 | 模型直接生成建议 |
| 输出 | 载荷或测试步骤建议 | 载荷或测试步骤建议 |
| 控制方式 | 记录 Flow/Task、审核和执行状态 | 记录会话/任务、审核和执行状态 |

左右两栏使用相同字段，底部统一展示人工审核、授权边界、允许执行状态和证据编号；敏感载荷细节按汇报范围处理。

### 第 10 页：测试结果统计与证据追溯

**主结论：** 统计结果能够从统一口径下的汇总项回溯到任务、执行记录、漏洞和证据。

页面包括统计范围、时间窗口和任务分母，任务状态、风险分布、漏洞分类、验证状态和评分，统计项下钻到任务、执行记录、漏洞详情、证据和报告。所有数值必须来自本次正式演示数据。

### 第 11 页：网络拓扑探测与资产识别

**主结论：** 拓扑探测将授权范围内的主机、端口和服务关系转化为可查看、可定位的资产视图。

页面包括探测目标、授权网段和任务编号，主机、端口、服务和节点关系，节点详情、原始探测结果和关联任务入口。主区域使用真实拓扑结果截图，占位阶段不以人工示意拓扑替代功能结果。

### 第 12 页：安全保障与交付体系

**主结论：** 加密锁、权限、过程审计和软件硬件交付资料共同支撑平台安全运行与项目交付。

- **加密锁与授权：** 设备识别、注册/校验、策略状态、关键功能授权及异常状态反馈。
- **软件与过程安全：** 用户角色权限、测试范围控制、审批、高风险操作、日志、原始输出、证据和报告关联。
- **交付体系：** 平台客户端与中心服务端、数据库、工具容器、模型配置、靶场接入、安装手册、用户手册、运维资料和硬件网络配置说明。

加密锁型号、SDK、驱动、客户端兼容性、成功/异常演示方式及最终交付清单需要现场确认。

### 第 13 页：建设价值与结束页

**主结论：** 项目形成统一管理、智能辅助、受控验证和证据追溯的安全测试能力。

统一管理目标、任务、资源、执行和报告；智能辅助分析、预案、载荷和结果整理；受控验证授权范围、人工审核和过程留痕；证据追溯任务、执行、漏洞、证据和报告关联。结束后进入现场演示或问答环节。

3. 核对服务器、终端、网络、靶机和加密锁的实际清单。
4. 按第 6—10 页功能矩阵采集截图和证据，保留任务、Flow、Run、报告编号。
5. 确认第 11 页加密锁、安全控制和最终交付清单。
6. 按本大纲更新页面脚本和占位符 PPT，再以现场截图替换占位符。
