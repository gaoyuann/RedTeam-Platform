# 信息系统渗透智能化测试平台

## 面向甲方的项目介绍 PPT 制作大纲

> PPT 定位：面向甲方的项目建设方案与产品能力介绍
>
> 制作主线：建设目标 → 总体方案 → 软硬件架构 → 核心业务能力 → 部署方式 → 应用价值与交付内容

## PPT 制作原则

- 面向甲方介绍平台建设目标、系统方案、产品能力和应用价值。
- 重点呈现软硬件一体化架构、部署形态、业务闭环和交付内容。
- 使用“建设内容、技术方案、系统能力、应用价值”等表述。
- 不展开内部研发问题、缺点、未完成项或过程性复盘。
- 项目截图暂时不作为主要内容，可使用架构图、流程图、部署拓扑图和模块关系图。

## 第 1 页：项目名称与建设定位

**标题：** 信息系统渗透智能化测试平台

**副标题：** 面向信息系统安全测试的智能化平台；集测试管理、资产发现、智能分析、验证执行和报告管理于一体。

**页面内容：** 项目名称、建设单位、汇报单位、日期。

## 第 2 页：项目建设目标与总体方案

### 建设目标

- 统一管理测试目标、测试任务和测试资源。
- 提升安全测试的自动化和智能化水平。
- 建立从扫描发现到验证报告的完整闭环。
- 支持国产化软硬件环境、固定式实验室和移动式现场使用。
- 实现过程留痕、证据关联和结果追溯。

### 总体方案

测试人员 / 管理人员 / 教学人员 → 平台客户端 → 中心服务平台 → 工具资源、模型服务、数据库和测试靶场。

平台形成统一入口、统一任务、统一资源、统一执行和统一报告。

## 第 3 页：软硬件一体化架构

### 硬件组成

- 中心服务器：海光 x86，承载后端、数据库、容器引擎、安全工具和模型服务。
- 云笔电客户端：飞腾 E2000Q ARM64 + 银河麒麟 V10 SP1，运行 Qt/C++ 客户端。
- 测试网络：通过 PoE 局域网连接云笔电、测试靶机和被测设备，任务与数据统一经服务器转发。
- 扩展硬件：GPU 加速设备、USB 硬件加密锁、虚拟机及专用网络设备。

### 软件分层

1. 交互层：Qt5/C++ 客户端。
2. 服务层：Node.js 后端、任务调度、权限管理、WebSocket。
3. 能力层：扫描、漏洞分析、预案生成、执行引擎、评分和报告。
4. 资源层：SQLite、容器工具、知识库、模型服务和测试靶场。

## 第 4 页：部署拓扑与运行模式

建议绘制“中心服务器—PoE 局域网—多台云笔电—测试靶场”的拓扑图。

运行模式：服务器集中部署，客户端批量接入；支持离线安装、物理迁移和实验室/现场两类使用场景。

## 第 5 页：核心业务流程

任务创建 → 目标配置 → 资产扫描 → 智能分析 → 预案生成 → 人工审核 → 受控执行 → 证据采集 → 结果评估 → 报告输出。

- 任务创建：明确测试范围和授权边界。
- 资产扫描：发现主机、端口、服务和风险线索。
- 智能分析：关联知识和证据，形成风险判断。
- 预案生成：形成可编辑、可审核的测试方案。
- 受控执行：按授权范围执行工具和验证步骤。
- 结果评估：形成可追溯的测试结论和报告。

## 第 6 页：平台功能模块与资源体系

| 模块 | 主要能力 |
| --- | --- |
| 工作台 | 全局态势、任务统计、待办和运行状态 |
| 测试任务 | 任务创建、目标配置、扫描和流程管理 |
| 资产与拓扑 | 资产、服务、网络关系和拓扑展示 |
| 智能分析 | 风险识别、证据关联、知识解释和建议 |
| 预案与知识库 | Playbook、知识图谱、漏洞和工具资源 |
| 结果与报告 | 验证结果、证据管理、风险评估和报告导出 |
| 系统管理 | 用户、权限、模型、工具、配置和审计 |

工具资源覆盖网络探测、漏洞扫描、Web 安全、凭证测试、漏洞验证、云安全和系统检测等类别，并通过 Podman/Docker 容器统一管理。

## 第 7 页：AI 智能协作能力

- 根据扫描结果识别潜在风险。
- 关联漏洞知识、攻击技术和工具能力。
- 辅助生成测试预案和验证建议。
- 支持自然语言问答、依据解释和结果修订。
- 辅助整理证据、风险建议和报告内容。

**协作模式：** AI 辅助决策 → 人工审核确认 → 系统受控执行。

## 第 8 页：权限、安全与审计保障

- 用户、角色和权限分级管理。
- 测试范围、授权边界和高风险操作控制。
- 工具调用、执行过程、日志和原始输出统一留痕。
- 证据与任务、预案、执行记录建立关联。
- 报告支持审核、发布、版本管理和归档。
- 可结合 USB 硬件加密锁实现软件授权控制。

## 第 9 页：结果评估与报告交付

甲方可获得的测试成果包括：测试任务总体概览、资产和服务清单、风险发现及验证结果、攻击步骤和工具执行记录、网络数据和测试证据、风险评分与安全建议、结构化测试报告及导出文件。

核心表达：测试结果能够从报告追溯到任务、预案、执行记录和原始证据。

## 第 10 页：典型应用场景与应用价值

### 典型场景

- 实验室网络安全测试。
- 国产化环境适配测试。
- 云笔电协同测试。
- 靶场教学与实训。
- 现场安全检测。
- 多角色协同的测试任务管理。

### 应用价值

- 提升安全测试效率。
- 降低工具和流程使用门槛。
- 提高测试过程的规范性。
- 加强测试结果的可信度和可追溯性。

## 第 11 页：部署运维、扩展与交付内容

### 部署与扩展

- 支持服务器集中部署、客户端批量接入和离线物理迁移。
- 支持工具镜像统一更新以及国产操作系统环境。
- 支持后续增加安全工具、模型、测试靶场、GPU 和专用硬件。

### 交付内容

- 平台客户端和中心服务端软件。
- 数据库及数据管理模块。
- 安全工具容器及镜像。
- AI 模型接入与配置模块。
- 测试任务、报告管理和靶场接入能力。
- 部署手册、用户手册、运维资料及硬件网络配置说明。

## 第 12 页：项目建设价值与结束页

- 构建统一的智能化安全测试工作平台。
- 打通“扫描—分析—预案—执行—评估—报告”业务闭环。
- 兼容国产软硬件环境，支持实验室、教学和现场应用。
- 以过程留痕、证据追溯和权限控制保障测试质量。
- 为后续扩展智能安全测试能力提供统一基础。

**结束语：** 谢谢各位领导、老师，欢迎指导。
