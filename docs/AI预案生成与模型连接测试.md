# AI 预案生成与模型连接测试

## 生成行为

普通扫描的预案生成遵循现有执行变量校验，模型最多调用两次：首次生成，校验失败后修正一次。两次调用共享 120 秒预算，普通扫描页和简化客户端等待 150 秒。程序源码测试仍使用原有独立生成流程和等待时间。

提示词提供当前目标的可用变量名称，不提供上下文中的凭据值。变量名使用执行契约校验器过滤；例如当前不支持含数字的 `s3_bucket`，不会将其列为可用变量，也不放宽执行校验。普通步骤不能声明报告、端口列表等运行时输出；只有已识别 DVWA 的受支持 curl 登录步骤可产出会话变量。DVWA 的 sqlmap 步骤即使声明空 inputs，也必须有前置登录 Cookie 生产步骤。缺少登录条件时应选择无会话依赖的侦察步骤，不得编造凭据。

生成结果须为 2–5 步的预案，纯 JSON、带或不带 json 标记的 Markdown 代码块均可解析。格式、工具及变量依赖校验失败会触发一次修正；网络、认证、额度或超时失败不会再次请求模型。最终失败不保存预案，成功通过事务保存；生成本身不执行步骤。重复点击是新的生成请求，不承诺跨请求去重。

现阶段仍沿用“成功生成即保存，再展示预览”的行为；确认后再保存不属于本批改动。

## 模型连接测试

`POST /api/config/llm/test-connection`，请求体 `{}`，使用既有登录认证，仅管理员可调用。

接口使用与预案生成相同的生效配置，向模型发送最小文本请求，输出预算 256 token，最多等待 20 秒。配置优先级不变：环境变量优先于数据库 default 条目，其次为已有回退配置。接口不修改配置、不携带任务材料、不返回模型正文和密钥。

Qt 的“测试连接”保留先保存配置的行为，保存成功后调用此接口，等待 25 秒。成功返回 `status: "ok"` 和 `data.message`；失败返回 `status: "error"` 和 `error.code/message`。配置保存成功不再被当作连接成功。模型返回推理内容但没有最终正文时，提示“连接成功，未返回最终回答”；有输出且 `finish_reason=length` 时，返回 `data.truncated=true` 并提示达到长度上限，不将其误判为空响应。既无正文又无推理内容仍判为空响应。仅保留推理内容是否存在的布尔值，不返回推理正文；生成预案仍要求可解析的最终 JSON。

## 切换内网模型

管理员可在“部署配置”的大模型配置中填写内网服务，例如 API 地址 `http://<模型服务器IP>:8000/v1`、服务实际提供的模型名（如 `qwen3.8`）和对应密钥，保存后测试连接。地址须包含 `http://` 或 `https://`，填写到 `/v1`，客户端会追加 `/chat/completions`。服务须支持现有的聊天请求及 `choices[0].message.content` 响应格式。

模型配置保存在运行后端使用的数据库 `system_config` 表、`category='llm'` 的 `default` 条目中，每次请求都会重新读取，单独修改该配置无需重启后端。扫描分析、预案生成和 ReAct 共用该配置。配置属于运行数据，不随 Git 同步；部署到另一台后端时，需在那台后端另行保存，密钥不得写入源码或文档。

若部署进程设置了 `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL` 或兼容的 `OPENAI_*`、`DEEPSEEK_API_KEY`，这些值会按字段覆盖数据库配置。切换时须核对进程的实际环境，避免旧密钥、地址或模型名混用；修改进程环境后需要按既有部署方式重启后端。内网服务不可达时请求会报错，不会自动切回公网供应商。应从**运行后端的机器**验证网络；`No route to host` 表示连接未建立，尚不能确认密钥和模型名是否有效。

## 错误约定

| 错误码 | 含义 |
| --- | --- |
| `LLM_NOT_CONFIGURED` | 缺少密钥 |
| `LLM_AUTH_ERROR` | 模型服务认证或权限失败 |
| `LLM_QUOTA_ERROR` | 额度不足或请求受限 |
| `LLM_TIMEOUT` | 模型调用或生成预算耗尽 |
| `LLM_NETWORK_ERROR` | 无法连接模型服务 |
| `LLM_EMPTY_RESPONSE` | 模型返回空内容 |
| `LLM_SERVICE_ERROR` | 其他服务配置或调用错误 |
| `PLAYBOOK_FORMAT_ERROR` | 修正后仍不能解析 JSON |
| `PLAYBOOK_VALIDATION_ERROR` | 修正后仍不满足预案执行约束 |

模型服务错误经过归类，不向客户端返回供应商错误正文。预案生成接口保留旧有 HTTP 400 和 `error.message`，新增 `error.code`；既有调用方仍可读取消息。客户端不再将普通校验错误当成密钥错误。

## 验证与生效

运行 `npm --prefix backend test` 验证后端；运行 `cmake --build build --target RedTeam-Platform -j2` 验证现有 Qt 构建。专项覆盖生成修正、格式兼容、DVWA Cookie 依赖、超时不落库、连接测试权限与错误脱敏。

真实模型测试应使用虚构目标和内存数据库，不执行预案。通过生成校验只表明预案结构满足平台约束，不代表各工具实际运行成功。代码更新后需按现有方式重新启动后端和客户端才能使用新接口与界面；无需数据库迁移。
