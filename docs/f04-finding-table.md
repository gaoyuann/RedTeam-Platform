# F04 漏洞候选表设计与展示口径

漏洞表属于 F04 扫描结果；单条发现的方案准备、执行与证据查看进入 F08，跨记录去重、统计与报告由 F09 负责。表中展示扫描发现的候选记录，不直接表示攻击成功。

## 字段与阅读顺序

优先展示编号、名称、严重性、测试状态、验证结论。目标与位置、载荷情况、来源工具在后续列保留，窄窗口可横向滚动；列宽可拖动调整。

| 字段 | 内容与规则 |
| --- | --- |
| 编号 | 仅显示完整稳定发现 ID，不加展示序号或 # 前缀。ID 是 scan_results 表的自增主键，各任务及不同类型的结果记录共用，不编码漏洞类型、严重性或日期，也不限定四位数。 |
| 漏洞名称 / 记录内容 | 优先取扫描名称、标题或发现文本，附带已有 CVE、CWE、规则或模板 ID；没有结构化名称时保留原结果摘要。 |
| 严重性 | 原扫描工具的严重性标签，与验证结论独立。颜色只作辅助，不用验证结果倒推严重性。 |
| 测试状态 | 未测试、准备中、缺少条件、准备失败、已就绪、排队中、执行中、取消中、停止未知、已完成、执行失败、已中止。未返回状态时显示“状态未提供”，不伪装为未测试。 |
| 验证结论 | 系统结果独立展示为待判定、目标已达成、目标未达成、证据不足。提示与详情保留验证目标、依据、限制；旧接口或未知状态不能升级为成功。 |
| 目标与位置 | 已保存的主机、URL、路径、文件、参数、端口和行号；缺失显示“未记录”，不从任务主目标猜测子发现的位置。 |
| 载荷情况 | 待匹配、有匹配候选、已关联（待核对条件）、关联已失效、暂无匹配；名称、匹配依据及条件说明放在提示中。 |
| 来源工具 | 工具名称；任务聚合视图同时保留子扫描 ID 和稳定发现 ID。 |
| AI 场景分类 | 任务聚合表展示五类需求场景的候选关联；支持多标签、无法确定和过期提示，点击查看分类依据及待补条件。分类不改变严重性、测试状态、验证结论或统计。用法和接口见 [漏洞 AI 场景分类](finding-classification.md)。 |

## 状态与结论的边界

- “已完成”仅描述执行生命周期；不得自动映射为漏洞成立。
- “目标已达成”仅针对该次验证目标。页面可访问性、配置暴露与实际安全影响不能互相替代，具体目标和限制必须可查看。
- “目标未达成”不表示目标安全或扫描发现一定是误报。
- 人工意见单独保存在 F08 详情中，不覆盖系统验证结果。“人工判定误报”不能作为自动验证结论回填。
- 历史记录只有旧版 `confirmed` 等字段而无受支持的结果契约时，显示“证据不足（旧记录）”。
- 载荷匹配或关联不等于载荷已经执行或可执行。当前摘要接口不提供足够信息区分“本轮生成”“仅参考”“已有可执行”，因此不根据名称或匹配状态推断这些标签。

## 分区、覆盖与交互

漏洞候选统一分组；信息级发现、普通提示、端口、服务、错误及原始输出分别展示。概览计数继续使用既有分类规则，且明确是已加载、未去重的记录数。信息级发现不提供逐漏洞测试勾选框，不计入漏洞候选数。

扫描部分失败时，保留已获得结果，并在任务状态区显示失败原因、未执行检查和覆盖不足情况。分页、分类及来源筛选沿用已有接口，不以当前页数冒充任务全部漏洞数。

表格不设“操作”列。双击候选或通过右键菜单准备验证进入既有 F08 窗口；该窗口可能创建准备记录，但不会因打开而执行工具。结果重新读取沿用已有刷新与“加载更多”入口。

批量勾选只打开验证工作区，不直接批量发起测试。停止未知、取消中及执行中的具体操作约束继续由 F08 和后端控制。

## 验收要点

1. 未测试记录显示待判定；执行完成和结论分别显示。
2. 旧记录、未知结果、停止未知不被显示为成功。
3. 信息、端口、错误与候选分组，错误信息保留，候选计数不包含普通提示。
4. 编号仅显示完整稳定 ID，规则信息、位置及完整记录均可追溯；不存在操作列或行内按钮。
5. 单条和勾选入口不执行工具；切换任务、迟到响应、分页和返回清理继续回归。
6. 检查正常窗口、1024×600 和高 DPI 下的文字、严重性、状态与横向滚动。离屏截图与自动化通过不替代真实部署机验收。
