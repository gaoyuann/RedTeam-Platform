# 信息系统渗透智能化测试平台 — 项目进展汇报

> 汇报时间：2026-07-09

---

## 一、项目概述

本项目是对 RedTeam-Edu（React + Electron + Node.js）系统的全面重构。根据老师要求，围绕四个核心改动展开：

1. **前端改用 Qt5/C++** — 兼容银河麒麟、统信UOS等国产操作系统
2. **引入数据库** — 原系统无数据库，全靠 JSON/内存，新系统采用 SQLite
3. **工具容器化** — Podman/Docker 容器化执行，支持离线物理迁移
4. **工作流改造** — 从"手动选 Playbook → 执行"改为"先扫描 → 展示结果 → 智能生成 Playbook → 再执行"

```
┌────────────────────┴─────────────────────────────┐

         │                       │
┌────────┴────────┐   ┌─────────┴──────────────────┐

│  · 测试报告      │   │  └────┘ └────┘ └────┘      │
│  · 执行记录      │   │  每款工具一个容器镜像        │
└──────────────────┘   └────────────────────────────┘
```

### 2.2 关键架构决策

| 决策项 | 选型 | 理由 |
|--------|------|------|
| 前端框架 | Qt5 + C++ + CMake | 原生编译，单二进制分发，国产OS无需额外运行时依赖 |
| 后端框架 | Node.js Express (ESM) | 复用现有后端逻辑，内嵌Node运行时，localhost通信 |
| 数据库 | SQLite (better-sqlite3, WAL模式) | 单文件随软件分发，物理迁移时直接拷贝 |
| 容器引擎 | Podman优先 → Docker → 宿主机三级回退 | Daemonless，无需root，国产OS原生支持 |
| 通信方式 | Qt ↔ Node.js 通过 localhost HTTP | 进程间通信，非网络服务，安全且简单 |
| 分发格式 | AppImage / 便携目录 / deb / rpm | 单目录包含所有组件，start.sh一键启动 |

### 2.3 数据库设计

共设计 **16张表**，覆盖用户管理、扫描任务、Playbook、执行记录、评分、审计等全部业务：

| 类别 | 表 | 用途 |
|------|-----|------|
| 用户体系 | users, classes, memberships, assignments, submissions | 用户/班级/作业/提交 |
| 核心业务 | playbooks, playbook_steps, execution_runs, execution_steps | Playbook定义与执行 |
| 扫描体系 | scan_tasks, scan_results | 扫描任务与结果（新工作流核心） |
| 评估体系 | evidence_records, test_reports | 攻击证据与测试报告 |
| 系统管理 | system_config, audit_log, _migrations | 配置/审计/迁移跟踪 |

### 2.4 容器化设计

8个工具镜像，基于Alpine 3.19（体积小），按功能分组：

| 镜像 | 包含工具 |
|------|---------|
| rt-recon | nmap, curl, httpx |
| rt-vuln-scan | nikto, sqlmap, nuclei |
| rt-brute | hydra, john, hashcat |
| rt-exploit | evil-winrm, netexec, sshpass |
| rt-web | python3, arjun |
| rt-credential | python3, responder, mitm6 |
| rt-cloud | python3, awscli, cloudmapper, pacu |
| rt-system | coreutils, ping, netstat |

## 五、核心工作流实现

### 扫描驱动Playbook生成流程（已实现）

```
Step 1: 输入目标 → Step 2: 执行扫描 → Step 3: 展示扫描结果
→ Step 4: 基于扫描结果智能生成Playbook → Step 5: 确认/编辑Playbook → Step 6: 执行
```

**实现细节：**
- **playbookMatcher** — 扫描结果 → 规则匹配推荐已有Playbook（MITRE精确匹配 ×3、severity驱动、端口覆盖、兜底策略）
- **playbookGenerator** — 扫描结果 + LLM → 生成新Playbook（is_generated=1）
- **executionEngine** — 逐步执行Playbook，替换args_template中<target>占位符，记录execution_steps
- **gradingEngine** — 步骤得分 + MITRE覆盖率 → 总分 + 等级(A-F)
