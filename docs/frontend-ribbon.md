# Qt Ribbon 功能导航

客户端继续使用 C++ / Qt Widgets。默认进入组成图的“测试资源部署配置 → 资产探测”，标题栏没有工作台、任务中心或知识资源等额外入口。任务管理归属系统管理；知识资源保留在战术手册内部。平台名称“信息系统安全智能化测试平台”仅显示在窗口标题栏，不再设置重复的浅蓝色标题横栏；内容区依次是七大模块页签、紧凑子功能区和任务上下文。已选功能直接由功能区标识，不再额外显示面包屑、大标题和整段说明。功能区折叠按钮位于模块页签右侧，折叠后页签保持可见；较窄窗口允许横向滚动。

## 入口与可用范围

`frontend/src/widgets/ModuleRibbon.cpp` 是 7 模块、34 子功能的注册表。每项使用稳定功能 ID，标记实现状态与管理员要求。没有实现的按钮使用原生禁用状态，不连接点击处理；主窗口路由再次核对，程序调用同样不会触发页面或请求。部分已实现的管理功能也会因当前角色而置灰。

| 模块 | 接入已有实现 | 置灰入口 |
| --- | --- | --- |
| 测试资源部署配置 | 资产探测；运行环境、模型、靶场、工具配置 | HexStrike部署配置 |
| 漏洞利用想定与预案 | 当前任务智能分析、任务预案、预案与知识库 | 无 |
| 网络拓扑绘制 | 共用原拓扑画布，定位探测、编辑、展示、标注控件 | 无 |
| 脆弱性扫描 | 系统、Web、端口、弱口令配置，共享现有发现与源码工作区 | 后门探测 |
| 漏洞攻击测试 | 数据抵近窃取、信息篡改欺骗、关键设备夺控入口，共用执行页 | 跨网致瘫攻击测试、无线攻击测试 |
| 测试评估 | 原网络数据捕获与分析 | 安全态势感知、分析、展示 |
| 系统管理 | 平台任务列表、用户、权限、加密锁、任务报告与报告索引 | 无 |

“已接入”表示原有工作区可到达，实际操作和结果延续现有实现，不扩展执行器能力。入口不代表独立场景已完成全面验证；原 AI 场景分类继续保留，分类不等于执行或验证成功。

## 页面与任务复用

- `MainWindow::switchToPage` 保留原内部页编号，已有报告跳转、回退和任务回调继续使用。用户看到的七模块由 Ribbon 独立映射，不把模块行号当成旧页面编号。
- 首次打开资产探测。资源配置、独立扫描、执行和捕获页面按需创建，重复进入复用实例；打开资源配置不会构造用户管理页。
- 资源配置复用 `DeployConfigPage` 原控件、接口和保存逻辑，分区显示。运行环境、工具页同时显示关联镜像信息。没有添加常驻容器管理或 CPU / 内存监控。
- 已选择任务时，扫描、想定、预案、执行、拓扑仍由同一个 `FlowPage` 维护上下文。资产探测也沿用当前任务的拓扑范围；没有选择任务时使用现有独立拓扑页。
- 没有选定任务时，扫描与执行可进入原有独立工作区；想定、任务预案和报告生成显示当前功能内的任务选择页，明确提供选择按钮，选择后返回原功能。探测类任务不支持的阶段不会被强行启用。
- 工作区原有阶段标签收起；“任务概况”“测试结果”快捷入口保留概况、评分、统计和证据访问。源码扫描、源码详情、逐漏洞验证、AI 分类及载荷功能继续使用原组件；预案与知识资源从战术手册的内部资源页进入。
- 三个可用攻击场景入口复用执行工作区。独立执行时筛选预案类别；任务执行时，按已保存且未过期的 AI 分类筛选逐漏洞执行记录。未分类、过期或旧后端没有分类投影的记录不会自动归类，界面说明范围与缺口。任务预案与运行保持不变，不重新执行，也不把分类当成验证结论。
- 资产探测显示真实资产清单；拓扑探测、编辑、展示、标注分别定位来源、属性、画布与标注字段。拓扑展示默认收起侧栏，空画布使用不随图形缩放的说明。
- 扫描列表直接显示在工作区左侧，不再只修改隐藏弹窗的类型。点击扫描子功能会按来源类型筛选可见记录，保留其他来源数据、分页边界和任务归属。
- 捕获和网络分析使用原独立捕获任务工作区，界面明确标注其作用范围。在捕获页选择对应记录；当前测试任务选择仍保留，没有虚构捕获与父任务的自动绑定。
- 报告智能生成入口打开当前任务报告区，由用户显式点击生成；切换入口不提交报告生成请求。历史报告与独立评估兼容入口继续保留。
- 加密锁失效会禁用模块、功能区、上下文快捷操作与任务中心。恢复后返回此前页面、任务和具体功能。

## 验证

使用项目现有构建目录，编译应用与 UI 回归目标后运行 `ctest`。回归覆盖全部功能注册、未实现按钮无操作、角色禁用、资源表单分区与实例复用、当前任务保留、独立捕获范围、锁屏恢复，以及现有源码和逐漏洞流程。

可用 `REDTEAM_RIBBON_SCREENSHOT_DIR` 为 UI 回归指定本地截图目录。截图使用隔离接口样例，不访问真实扫描、模型或硬件；截图及此前生成的设计图均不提交。

## 载荷生成的位置

“漏洞利用想定与预案 → 漏洞利用预案”提供“载荷生成与管理”按钮；扫描发现操作区保留同一入口。入口先读取当前任务的漏洞候选，支持分页、失败重试和换任务时失效，再显式选择漏洞打开其载荷代码页。无任务时提示并提供前往任务管理的按钮。

载荷生成沿用现有逐漏洞工作区：关联发现 → 准备测试与查看条件 → 查看/生成载荷代码 → 核对与保存 → 显式确认执行 → 查看证据与系统结果。打开具体漏洞工作区可能建立该漏洞的测试记录，但不会自动调用模型生成代码或启动验证。源码载荷收集、Python 改写、已有载荷绑定与验证代码生成保留原有操作和前置条件。

## 夜间修订验证

新增行为回归逐个点击全部已实现子功能，核对可见标题、选中按钮、扫描实际结果过滤、执行场景实际记录过滤、任务选择返回原功能及载荷选择窗口。生成的真实 Qt 截图只保存在本机；`REDTEAM_RIBBON_REVIEW_ONLY=1` 可单独运行这组检查，常规 `ctest` 仍完整执行原回归。

执行快照只读投影补充保存分类，用于场景过滤；证据变化标为过期，未安装分类表的旧数据库仍可读取，且不会触发模型。相关后端回归覆盖保存分类、证据变化和旧库兼容。

## 页面与按钮联动复核

功能组成图的完整名称、子功能数量和视觉顺序有独立回归清单核对；按钮选中互斥，未实现按钮不产生路由。源码扫描、任务概况和通用执行记录作为既有扩展工作区显示准确标题，不误选图中的系统扫描或某个攻击场景。任务报告打开和返回时同步系统管理中的报告归属。

独立执行的场景筛选同时作用于预案目录和执行记录。目录延迟返回、连续预选两份预案、手工切换类别不会覆盖后来的选择；类别缺失的记录不按名称猜测。目录和执行记录读取失败有明确提示及刷新入口，旧数据保留但不可用预案不允许提交。点击执行先读取当前预案实际保存的步骤，再展示确认窗口；不再按目标类型虚构通用攻击流程。取消确认不创建运行，提交中重复点击不重复创建；已确认启动不因场景切换丢失后续启动调用，也不清空后来输入的目标。

捕获操作分别定义为：新建待执行记录、开始所选待执行任务、停止所选运行任务。新建不会自动开始；已完成的记录不能用开始按钮覆盖，需新建记录。网络分析只作用于完成或停止的捕获记录，选择其他记录会终止旧轮询；迟到详情、提交、分析结果都不能覆盖新选择。失败明确显示，可重试；分析页隐藏不属于该操作的新建捕获入口。删除记录仍需确认，运行中不可删除，失败保留选择。

资产表不展示扫描器与逻辑网络分组，显示设备、服务、状态和来源；双击打开只读资产详情。资产页隐藏缩放、图编辑等无作用按钮，拓扑页仍保留原操作。

## 小窗口与滚动

主工作区和任务内部堆叠只使用当前页面的最小尺寸，隐藏表单不再撑大当前页面。业务区提供外层滚动；预案编辑主体独立滚动，保存、提审等动作保持在页底。窗口较矮时默认收起功能区，用户可手动展开；模块标签仍可到达。源码扩展隐藏无关的网络扫描左栏；同一层级的重复标题和按钮逐步精简。

检查覆盖 1024 / 1366 / 1600 宽度、600 高度，以及 1 / 1.25 / 1.5 缩放。截图使用隔离样例，只作为界面检查；真实模型、捕获设备、扫描环境与硬件锁仍需目标部署环境验收。

任务取消、删除使用同一入口处理列表和详情操作：请求中抑制重复提交；失败保留当前页面与记录并显示原因；切换任务后，旧操作响应不会重载或关闭新任务。删除成功才清除对应任务上下文。

资源读取失败不再显示成默认配置：模型与运行环境保留已有输入，禁用保存/测试并提供刷新恢复；工具、镜像和靶场列表显示读取失败。靶场自检的失败结果使用错误状态，不显示绿色成功样式；请求中不能重复提交。模型连接按钮标为“保存并测试连接”，明确沿用当前服务先保存再测试的行为。

独立扫描提交按钮明确标为“创建并开始扫描/测试”，请求期间禁用重复提交；切换检测类型不会清空后来输入的目标，也不会重复创建旧任务。任务扫描左侧列表使用当前任务的来源元数据刷新，避免结果区已有记录而左侧仍为空。载荷工作区关闭后刷新当前任务的载荷与验证状态；切换任务时旧载荷选择窗口失效。

仅探测任务不适用想定、预案或报告阶段时，当前功能显示原因及选择其他测试任务的入口，不显示无效表单。选择任务使用上下文版本核对，同一不适用任务再次被选择也不会使页面标题与内容不一致。

## 当前功能内完成任务操作（2026-10-31 修正）

- 子功能按钮高 44 像素，使用 18 像素图标与文字并排；整条子功能区高 78 像素。七模块及 34 子功能名称、归属和顺序保留。
- 隐藏与已选功能重复的面包屑、大标题和说明栏，操作说明仅放在提示中。源码等无对应叶子的扩展内容只使用一行小标题。
- 当前任务栏提供“选择/更换任务”，选定后返回当前功能；扫描、执行和拓扑还可明确切换到独立操作，避免选定任务后被绑定在旧范围中。
- 扫描、想定、预案、执行和报告功能可直接“新建测试任务”，创建的是 `assessment` 测试任务，沿用既有创建和启动接口，确认后开始扫描；不再先创建仅供探测的任务。扫描完成后在同一任务中继续想定、预案、载荷及验证。
- 资产探测保留“对所选资产创建测试”，可从资产清单直接进入后续任务。
- 点击左侧某条扫描记录后，再选另一扫描子功能会重新读取该类型的任务结果，避免旧详情阻止切页。

上述路径使用实际 Qt 控件交互和模拟接口验证；不以静态图或仅核对标题替代流程验证，真实目标执行仍需部署环境验证。
