# Qt Ribbon 功能导航

## 主界面统一任务流程

主界面的七模块是唯一的阶段导航。任务管理只负责列出、选择和管理任务；双击或右键打开任务后，在同一主窗口按状态定位：扫描中的任务进入脆弱性扫描，待审批任务进入任务方案，有运行记录的活动任务进入攻击测试，结束的执行进入测试结果与评估，资产探测任务进入拓扑。更换任务与单纯打开任务不同：在某功能内更换任务时保留当前功能。

扫描、方案、攻击和结果入口均复用同一个任务及其页面实例。不选择任务时提供选择已有任务和发起测试，主界面不再构建独立扫描、独立攻击页面，也不再显示“独立操作”按钮。旧页面编号 10／11 重定向到统一入口；后端记录不转换、不删除。原 `FlowPage` 只作为内部任务状态和页面承载组件，旧阶段页签及返回工作区按钮收起，不是另一套用户流程。

从任意主模块发起新测试，默认先在主界面展示本任务的扫描进度与全部发现；生成方案、确认执行和查看结果继续使用该任务。测试评估新增“测试结果与评估”入口；捕获与网络分析保留为明确标注的辅助工具，不虚构与父任务的自动关联。模板的执行入口先关联任务方案，不再跳到无任务的独立执行表单。

本次对照的是本机 PentAGI Qt 参考实现：`main_window/MainWindow.cpp` 将扫描结果入口映射到已有 `VulnerabilityScanPage`；该页面的 `openTaskDetails` 可打开以原 Flow ID 为上下文的详情窗口。参考项目确有详情窗口，复用的仍是同一任务页面和记录；这不等于需要在本项目主界面保留另一套独立扫描／执行流程。本次不修改参考项目。


## 当前默认入口（恢复原流程）

普通网络目标新任务不再写入 `workflow_mode=intelligent`，直接复用重构前的 pipeline：扫描 → 分析 → 生成预案 → 建立本任务草稿、提审、管理员批准 → 执行 → 结果。授权范围和冻结版本执行规则继续生效。已有 intelligent、staged、源码／程序及资产探测任务按各自保存的配置处理，不批量修改历史数据。

扫描和生成结束进入同一任务的方案审核；原流程需在方案页选择已生成的来源，建立草稿并提审。攻击页在待审批时提供“审阅本任务方案，确认后执行”，无需切换任务或另建独立执行。任务模式的提示和按钮放在始终可见的页面容器中，避免被隐藏的独立执行页签一并遮蔽。整体任务执行默认展示本次方案步骤，结束后从执行页进入同任务结果；失败执行同样保留证据。进入结果不自动生成报告。

顶部预案模块保留为方案与知识库的管理入口；主流程中的方案审核仍是执行前的确认环节。下文智能自动送审描述仅适用于已有 intelligent 任务。独立扫描和执行的历史数据保留；逐漏洞验证继续复用现有组件，主界面不再提供另一套独立操作入口。

顶部模块按用户确认的顺序排列：网络拓扑绘制 → 脆弱性扫描 → 漏洞利用想定与预案 → 漏洞攻击测试 → 测试评估 → 测试资源部署配置 → 系统管理。“想定与预案”位于扫描与攻击之间，资源配置集中放在流程模块之后；子功能名称、功能 ID 和原内部工作区页号保留，扫描与执行扩展入口的模块选中及记忆同步调整。

顺序调整验证：应用和 Qt 回归目标构建通过；`REDTEAM_RIBBON_REVIEW_ONLY=1` 在 `QT_SCALE_FACTOR=1`、`1.5` 下分别通过 446 项检查，覆盖子功能归属、页面路由、任务上下文及源码扫描扩展返回。

对象之间的业务衔接、智能及分阶段测试模式和接口见 [测试流程衔接](test-workflow.md)。新建普通目标测试复用原 pipeline，扫描、分析、生成后进入本任务草稿、提审与批准执行；已有 intelligent 任务继续自动送审。历史任务继续沿用记录的流程模式。

智能测试的“漏洞利用预案”展示自动送审的目标、方案说明及步骤，管理员可直接确认该版本并开始测试，无需填写工具参数或手动建立草稿。已有分阶段测试仍展示逐漏洞预案列表；扫描或拓扑选中漏洞后的专项验证也保留。顶部七模块保持组成图归属，共享同一任务；执行与证据进入同任务评估和报告，不要求按顶部从左到右逐项点击。

智能测试进入攻击测试后，默认展开本次方案的执行详情，并选中步骤页签，直接展示运行状态、调用与证据。已有分阶段任务仍以逐漏洞记录为主；用户对详情的手动收起选择在同一执行的刷新中保留。

## 参考 PentAGI 的任务入口与控件

参照本机 `pentagi-v3/src/ui/pages/scan/VulnerabilityScanPage.cpp` 的目标优先表单，以及 `src/ui/widgets/PageComponents.h` 的菜单组织方式，在本项目现有 Qt 页面中适配：

- 功能栏与系统管理的任务列表均提供“发起测试”。任务列表主按钮直接创建普通智能测试，资产探测保留独立次要入口，避免“快速测试／完整配置”名称与实际探测行为混淆。
- 发起窗口默认显示测试目标和自动推断的任务类型；任务名称自动生成，放在折叠的“更多任务选项”内，展开可改名、核对完整范围摘要。源码／程序类型仍显示真实来源与运行条件；授权确认和范围约束沿用原逻辑。折叠不清除输入，取消不提交。小屏幕高缩放下优先保留目标和类型可见，较长的源码表单仍可滚动。
- “漏洞利用预案”内部以“测试方案”呈现。智能任务默认显示方案摘要、步骤及确认动作；来源模板、名称编辑、步骤工具与参数通过“更多 → 显示技术详情”展开。编辑草稿时自动显示编辑区域，保留保存、提审和版本规则。
- 方案中的载荷与逐漏洞操作、扫描页的检查详情与扫描管理收在“更多”菜单。菜单只代理原按钮点击，保留权限、禁用状态、校验和重复提交保护；打开菜单只同步显示状态。
- 新增 `frontend/src/widgets/PageComponents.h`，包含原生操作菜单与折叠区域；不引入新依赖，不修改参考仓库、模型提示词或既有后端执行接口。

控件与流程回归集成进 `RedTeam-Platform-Batch16Checks`。可用 `REDTEAM_INTELLIGENT_ONLY=1` 聚焦任务发起、方案确认与菜单行为；设置 `REDTEAM_PENTAGI_UI_SCREENSHOT_DIR` 保存模拟接口下的实际 Qt 截图，截图不提交到 Git。

### 字号与阅读体验

按用户反馈提高默认字号：应用基础字体从 11pt 调到 12pt，通用输入、按钮和表格约 16px，紧凑操作及说明约 14–15px，七模块标题 16px、子功能 15px。按钮同步加高；子功能按钮高 56px、功能区高 68px，覆盖下文早期 48／60px 的尺寸记录。小窗口继续允许折叠功能区和滚动，不通过缩小文字容纳长内容。旧执行预案概况增加内部滚动，避免较大文字和完整身份信息把 1024×600 窗口撑高。方案状态改为“方案已准备 · 等待确认”，简化确认说明。

方案、执行、结果和推荐表格的基础行高调整为 42px。任务编号列按当前字体实际宽度保留单行，任务名称和目标在窄窗口换行。回归中发现的旧执行详情最小尺寸及编号列缩放问题已修正；创建窗口的截图检查展开范围摘要后恢复原折叠状态，避免测试改变后续表单高度比较的前提。保留原窗口尺寸、完整编号和范围可达性断言。

本轮构建应用和 `RedTeam-Platform-Batch16Checks` 通过；`ctest --test-dir build -R '^ui-context-1$' --output-on-failure` 全部通过（约 98 秒）。智能流程与新控件在 1／1.25／1.5 缩放下通过，扫描与拓扑展示专项通过。使用模拟 API 生成并查看了发起窗口、简洁方案页和技术详情的真实 Qt 截图；不表示已验证真实模型、工具或目标环境。

客户端继续使用 C++ / Qt Widgets。默认进入组成图的“测试资源部署配置 → 资产探测”，标题栏没有工作台、任务中心或知识资源等额外入口。任务管理归属系统管理；知识资源保留在战术手册内部。平台名称“信息系统安全智能化测试平台”仅显示在窗口标题栏，不再设置重复的浅蓝色标题横栏；内容区依次是七大模块页签、紧凑子功能区和任务上下文。已选功能直接由功能区标识，不再额外显示面包屑、大标题和整段说明。功能区折叠按钮位于模块页签右侧，折叠后页签保持可见；较窄窗口允许横向滚动。

## 入口与可用范围

`frontend/src/widgets/ModuleRibbon.cpp` 是 7 模块、35 子功能的注册表（增加当前任务结果与评估入口）。每项使用稳定功能 ID，标记实现状态与管理员要求。没有实现的按钮使用原生禁用状态，不连接点击处理；主窗口路由再次核对，程序调用同样不会触发页面或请求。部分已实现的管理功能也会因当前角色而置灰。

| 模块 | 接入已有实现 | 置灰入口 |
| --- | --- | --- |
| 网络拓扑绘制 | 共用原拓扑画布，定位探测、编辑、展示、标注控件 | 无 |
| 脆弱性扫描 | 系统、Web、端口、弱口令配置，共享现有发现与源码工作区 | 后门探测 |
| 漏洞利用想定与预案 | 当前任务智能分析、任务预案、预案与知识库 | 无 |
| 漏洞攻击测试 | 数据抵近窃取、信息篡改欺骗、关键设备夺控入口，共用执行页 | 跨网致瘫攻击测试、无线攻击测试 |
| 测试评估 | 当前任务结果与评估、原网络数据捕获与分析 | 安全态势感知、分析、展示 |
| 测试资源部署配置 | 资产探测；运行环境、模型、靶场、工具配置 | HexStrike部署配置 |
| 系统管理 | 平台任务列表、用户、权限、加密锁、任务报告与报告索引 | 无 |

“已接入”表示原有工作区可到达，实际操作和结果延续现有实现，不扩展执行器能力。入口不代表独立场景已完成全面验证；原 AI 场景分类继续保留，分类不等于执行或验证成功。

## 页面与任务复用

- `MainWindow::switchToPage` 保留原内部页编号，已有报告跳转、回退和任务回调继续使用。用户看到的七模块由 Ribbon 独立映射，不把模块行号当成旧页面编号。
- 首次打开资产探测。资源配置和捕获辅助工具按需创建；任务页面共享并复用实例；打开资源配置不会构造用户管理页。
- 资源配置复用 `DeployConfigPage` 原控件、接口和保存逻辑，分区显示。运行环境、工具页同时显示关联镜像信息。没有添加常驻容器管理或 CPU / 内存监控。
- 已选择任务时，扫描、想定、预案、执行、拓扑仍由同一个 `FlowPage` 维护上下文。资产探测也沿用当前任务的拓扑范围；没有选择任务时使用现有独立拓扑页。
- 没有选定任务时，扫描、攻击、评估、想定、任务预案和报告生成统一显示任务选择与发起入口，选择后返回原功能。探测类任务不支持的阶段不会被强行启用。
- 工作区原有阶段标签收起；“任务概况”“测试结果”快捷入口保留概况、评分、统计和证据访问。源码扫描、源码详情、逐漏洞验证、AI 分类及载荷功能继续使用原组件；预案与知识资源从战术手册的内部资源页进入。
- 三个可用攻击场景入口复用当前任务执行页；按已保存且未过期的 AI 分类筛选逐漏洞执行记录。未分类、过期或旧后端没有分类投影的记录不会自动归类，界面说明范围与缺口。任务预案与运行保持不变，不重新执行，也不把分类当成验证结论。
- 资产探测显示真实资产清单；拓扑探测、编辑、展示、标注分别定位来源、属性、画布与标注字段。拓扑展示默认收起侧栏，空画布使用不随图形缩放的说明。
- 扫描任务列表由工作区的“扫描任务”按钮按需展开，默认将全宽留给漏洞列表，空任务栏不占据首屏。点击扫描子功能会按来源类型筛选可见记录并保留侧栏展开选择、其他来源数据、分页边界和任务归属。视图选择、进度和操作共用一行工具栏，双层页签合并为单个视图选择框。
- 捕获和网络分析使用原独立捕获任务工作区，界面明确标注其作用范围。在捕获页选择对应记录；当前测试任务选择仍保留，没有虚构捕获与父任务的自动绑定。
- 报告智能生成入口打开当前任务报告区，由用户显式点击生成；切换入口不提交报告生成请求。历史报告与独立评估兼容入口继续保留。
- 加密锁失效会禁用模块、功能区、上下文快捷操作与任务中心。恢复后返回此前页面、任务和具体功能。

## 验证

使用项目现有构建目录，编译应用与 UI 回归目标后运行 `ctest`。回归覆盖全部功能注册、未实现按钮无操作、角色禁用、资源表单分区与实例复用、当前任务保留、独立捕获范围、锁屏恢复，以及现有源码和逐漏洞流程。

可用 `REDTEAM_RIBBON_SCREENSHOT_DIR` 为 UI 回归指定本地截图目录。截图使用隔离接口样例，不访问真实扫描、模型或硬件；截图及此前生成的设计图均不提交。

## 载荷生成的位置

“漏洞利用想定与预案 → 漏洞利用预案”提供“载荷生成与管理”按钮；扫描发现操作区保留同一入口。入口先读取当前任务的漏洞候选，支持分页、失败重试和换任务时失效，再显式选择漏洞打开其载荷代码页。无任务时提示并提供前往任务管理的按钮。

载荷生成沿用现有逐漏洞工作区：关联发现 → 准备测试与查看条件 → 查看/生成载荷代码 → 核对与保存 → 显式确认执行 → 查看证据与系统结果。打开具体漏洞工作区可能建立该漏洞的测试记录，但不会自动调用模型生成代码或启动验证。源码载荷收集、Python 改写、已有载荷绑定与验证代码生成保留原有操作和前置条件。

## 夜间修订验证

新增行为回归逐个点击全部已实现子功能，核对可见标题、选中按钮、扫描实际结果过滤、执行场景实际记录过滤、任务选择返回原功能及载荷选择窗口。生成的真实 Qt 截图只保存在本机；`REDTEAM_RIBBON_REVIEW_ONLY=1` 可单独运行这组检查，常规 `ctest` 仍完整执行原回归。

执行快照只读投影补充保存分类，用于场景过滤；证据变化标为过期，未安装分类表的旧数据库仍可读取，且不会触发模型。相关后端回归覆盖保存分类、证据变化和旧库兼容。

## 页面与按钮联动复核

功能组成图的完整名称、子功能数量和视觉顺序有独立回归清单核对；按钮选中互斥，未实现按钮不产生路由。源码扫描、任务概况和通用执行记录作为既有扩展工作区显示准确标题，不误选图中的系统扫描或某个攻击场景。任务报告打开和返回时同步系统管理中的报告归属。

独立执行的场景筛选同时作用于预案目录和执行记录。目录延迟返回、连续预选两份预案、手工切换类别不会覆盖后来的选择；类别缺失的记录不按名称猜测。目录和执行记录读取失败有明确提示及刷新入口，旧数据保留但不可用预案不允许提交。点击执行先读取当前预案实际保存的步骤，再展示确认窗口；不再按目标类型虚构通用攻击流程。取消确认不创建运行，提交中重复点击不重复创建；已确认启动不因场景切换丢失后续启动调用，也不清空后来输入的目标。

捕获操作分别定义为：新建待执行记录、开始所选待执行任务、停止所选运行任务。新建不会自动开始；已完成的记录不能用开始按钮覆盖，需新建记录。网络分析只作用于完成或停止的捕获记录，选择其他记录会终止旧轮询；迟到详情、提交、分析结果都不能覆盖新选择。失败明确显示，可重试；分析页隐藏不属于该操作的新建捕获入口。删除记录仍需确认，运行中不可删除，失败保留选择。

资产表不展示扫描器与逻辑网络分组，显示设备、服务、状态和来源；双击打开只读资产详情。资产页隐藏缩放、图编辑等无作用按钮，拓扑页仍保留原操作。

## 小窗口与滚动

主工作区和任务内部堆叠只使用当前页面的最小尺寸，隐藏表单不再撑大当前页面。业务区提供外层滚动；预案编辑主体独立滚动，保存、提审等动作保持在页底。窗口较矮时默认收起功能区，用户可手动展开；模块标签仍可到达。源码扩展隐藏无关的网络扫描左栏；同一层级的重复标题和按钮逐步精简。

检查覆盖 1024 / 1366 / 1600 宽度、600 高度，以及 1 / 1.25 / 1.5 缩放。截图使用隔离样例，只作为界面检查；真实模型、捕获设备、扫描环境与硬件锁仍需目标部署环境验收。

任务取消、删除使用同一入口处理列表和详情操作：请求中抑制重复提交；失败保留当前页面与记录并显示原因；切换任务后，旧操作响应不会重载或关闭新任务。删除成功才清除对应任务上下文。

资源读取失败不再显示成默认配置：模型与运行环境保留已有输入，禁用保存/测试并提供刷新恢复；工具、镜像和靶场列表显示读取失败。靶场自检的失败结果使用错误状态，不显示绿色成功样式；请求中不能重复提交。模型连接按钮标为“保存并测试连接”，明确沿用当前服务先保存再测试的行为。

独立扫描提交按钮明确标为“创建并开始扫描/测试”，请求期间禁用重复提交；切换检测类型不会清空后来输入的目标，也不会重复创建旧任务。任务扫描左侧列表使用当前任务的来源元数据刷新，避免结果区已有记录而左侧仍为空。载荷工作区关闭后刷新当前任务的载荷与验证状态；切换任务时旧载荷选择窗口失效。

仅探测任务不适用想定、预案或报告阶段时，当前功能显示原因及选择其他测试任务的入口，不显示无效表单。选择任务使用上下文版本核对，同一不适用任务再次被选择也不会使页面标题与内容不一致。

## 功能区展开与收起

## 字体与可读性

启动时先加载程序目录及其上级 `fonts/` 内的字体，再从已安装的简体中文字体中选择无衬线字体，优先 Noto Sans CJK SC / 思源黑体，依次兼容微软雅黑、苹方、文泉驿；没有候选时使用系统无衬线回退。部署机器需提供其中一种中文字体，不在仓库内附带字体二进制。

全局正文使用 11 磅、中等字重；模块页签 14 像素、子功能与紧凑按钮 13 像素，使用半粗字重。常规按钮、表单、表头和工作区页签以 14 像素为主；次要文字加深颜色。子功能按钮按实际字体和样式计算宽度，执行记录的可选详情适当缩小内部间距，适配增大的字形。代码查看器保留等宽字体。UI 回归使用与主程序相同的字体选择，并检查小窗口和三档缩放下的布局。
