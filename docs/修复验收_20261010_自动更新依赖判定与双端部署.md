## 原因与修复

原服务器更新器只要发现 `backend/package.json` 发生变化，就执行 `npm ci`。本次变更仅增加测试命令，依赖声明和锁文件未变，实际无需重新安装。

此次不必要的安装遇到 npm 镜像下载超时及 `Exit handler never called!`，留下不完整的暂存依赖；后续迁移预检查无法加载 `better-sqlite3` 原生绑定，更新未激活，也没有发布新的 `deployed-main`，因此云笔电继续停留在旧版本。原部署未被本次失败的暂存安装覆盖。

修复文件：`scripts/auto-update-platform.sh`。

- 比较依赖、安装生命周期脚本及相关安装配置；仅增加测试命令不触发重新安装。
- 锁文件变化、实际依赖配置变化或缺少 `node_modules` 时仍执行安装。
- 安装命令失败立即退出，保留原部署。
- 激活前检查生产依赖解析，并实际执行 `better-sqlite3` 内存数据库查询和 bcrypt 哈希校验，避免仅依赖 npm 退出码。
- 保留现有迁移预检查、备份、健康检查、失败回滚及成功后发布机制。

## 自动更新链路

1. 服务器约每 300 秒检查 GitHub `main`。
2. 通过部署预检查及后端健康检查后，服务器发布 `deployed-main`。
3. 云笔电约每 60 秒检查服务器 `deployed-main`，构建、切换并启动客户端。

上述间隔是轮询间隔，不是保证完成更新的时限；构建耗时、网络、运行中任务及本地代码冲突等条件仍可能延迟或阻止部署。本地未提交或未推送的代码不会自动发布到两端。
