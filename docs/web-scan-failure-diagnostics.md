# Web 参数扫描未执行与失败诊断

页面读取成功不代表开展过 SQL 检测。缺少认证会话、表单包含动态令牌或没有已观察的可检测入口时，扫描记录 `prerequisite_check` 和具体原因，不让模型猜测账号、请求体或入口；`checks_started=0` 表示未开展检测，不能据此得出安全结论。

模型从本轮 `available_actions` 复制动作、入口编号和来源证据，再补充依据。无效动作记录 `rejection_code`，区分 JSON/schema、入口不存在、来源证据不匹配、前提条件、范围、参数与重复动作；允许一次带诊断的纠正，连续无效则停止。记录不包含原始模型回复或会话内容。

能力评估保留工具是否启动、停止是否确认、退出码、超时和解析覆盖。缺失、损坏或非对象的旧工具结果视为未知；停止未确认时禁止继续派发或分析，成功的其他检查不能掩盖它。普通 ReAct 任务已有完整可用检查且其余工具均已停止时，可保留部分结果继续分析，具体条件见[扫描部分完成后继续任务](partial-scan-continuation.md)。

界面顶部使用简洁状态，真实原因仍可从进度提示、扫描记录与过程日志查看。执行步骤的成功判定另见[执行器跨步骤会话与结果判定](executor-session-results.md)。
