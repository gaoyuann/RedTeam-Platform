# 云笔电客户端部署指南

> 目标设备：飞腾 E2000Q (ARM64) + 银河麒麟 V10 SP1
> 服务器地址：192.168.1.103:3002（按实际修改）
> 日期：2026-08-13

---

## 一、首次部署（每台云笔电执行一次）

### 1. 安装编译依赖

```bash
sudo apt update
sudo apt install -y build-essential cmake g++ qt5-default libqt5network5-dev libqt5websockets5-dev
```

> 如果 `qt5-default` 找不到，用 `qtbase5-dev libqt5network5-dev libqt5websockets5-dev cmake g++`

### 2. 关闭 KYSEC 安全执行控制

图形界面操作：**开始菜单 → 安全中心 → 安全设置 → 执行控制 → 关闭**

> 不关的话，所有自编译的二进制都无法执行（报 `KYSEC: 权限不够`）。内网教学环境关掉无安全风险。8 台都要关。

### 3. 拉取代码并编译

```bash
cd ~
git clone https://github.com/gaoyuann/RedTeam-Platform.git ~/RedTeam-Platform
cd ~/RedTeam-Platform
cmake -B build -S .
cmake --build build -j$(nproc)
```

### 4. 验证网络连通性

```bash
curl http://192.168.1.103:3002/api/health
# 期望输出: {"status":"ok",...}
```

### 5. 启动前端

```bash
# 方式 A：一键脚本（推荐）
bash ~/RedTeam-Platform/scripts/run.sh

# 方式 B：直接运行
~/RedTeam-Platform/build/frontend/RedTeam-Platform --server 192.168.1.103:3002
```

启动后出现登录界面，输入服务器地址 + 用户名密码即可。

## 二、日常更新（开发者 push 代码后）

云笔电上一条命令：

```bash
bash ~/RedTeam-Platform/scripts/update-client.sh
```

自动完成：**git pull → 增量编译 → 重启前端**，约 10 秒。

## 三、登录角色说明

| 角色 | 对应终端 | 可用模块 | 说明 |
|------|---------|---------|------|
| `operator` | 攻击测试端 | 拓扑探测 + 脆弱性扫描 + 漏洞攻击 | 学生操作员 |
| `admin` / `teacher` | 测试控制端 | 全部 7 个模块 | 管理员全景视图 |
| `student` | 学习者 | 只读 + 提交作业 | 不能发起扫描和攻击 |
| `viewer` | 只读观察者 | 仅查看 | 不能执行任何操作 |

攻击测试端和测试控制端是**同一个 Qt 前端程序**，区别仅在登录角色不同。

## 四、网络架构

```
服务器 (192.168.1.103, x86 海光)
  │ Node.js 后端 + SQLite + Docker + LLM
  │ 监听 0.0.0.0:3002 (HTTP + WebSocket)
  │
  │ PoE 局域网
  ├── 云笔电 1 (operator)  ← 攻击测试端
  ├── 云笔电 2 (admin)     ← 测试控制端，实时看到云笔电1的操作
  ├── 云笔电 3~8
  └── ...
```

- 云笔电之间**不需要直接通信**，所有数据经服务器中转
- WebSocket 实时推送：攻击端操作 → 服务器广播 → 控制端实时看到
- 云笔电只跑 Qt 前端，不跑后端/数据库/容器

## 五、常见问题

### 编译报错 `setTransferTimeout` / `SkipEmptyParts` / `idClicked`

Qt 版本兼容问题，代码已修复。`git pull` 拉最新代码即可。

### 启动报 `KYSEC: 权限不够`

银河麒麟安全执行控制未关闭。去 **安全中心 → 安全设置 → 执行控制 → 关闭**。

### 启动报 `could not connect to display`

在 SSH 终端里跑 GUI 程序。需要在云笔电本地桌面终端执行，或设置 `export DISPLAY=:0`。

### cmake 报 `CMakeCache.txt` 路径不匹配

之前在 `/opt/` 下编译过，缓存冲突。删除重建：

```bash
rm -rf ~/RedTeam-Platform/build
cmake -B build -S .
cmake --build build -j$(nproc)
```

### 云笔电互 ping 不通

正常现象，PoE 交换机端口隔离。不影响系统使用，所有通信经服务器中转。

## 七、从内网服务器自动同步源码

当服务器使用尚未提交的已验证修复时，`git pull` 不会取得这些工作区内容。客户端可通过 `REDTEAM_SYNC_SOURCE` 启用源码同步模式：只同步根目录 `CMakeLists.txt`、`frontend/` 和 `third_party/rockey/`，不同步服务器数据库、账号、模型配置或后端依赖。

云笔电需已配置到服务器的 SSH 公钥登录，并预先确认服务器主机密钥。配置示例：

```bash
mkdir -p ~/.config/redteam ~/.config/systemd/user/redteam-autoupdate.service.d
cat > ~/.config/redteam/client-update.env <<'EOF'
REDTEAM_SYNC_SOURCE=aistation@192.168.1.103:/opt/RedTeam-Platform
REDTEAM_SERVER=192.168.1.103:3002
DISPLAY=:0
XAUTHORITY=/home/user4/.Xauthority
BUILD_JOBS=2
POLL_INTERVAL=30
EOF
cat > ~/.config/systemd/user/redteam-autoupdate.service.d/source-sync.conf <<'EOF'
[Service]
EnvironmentFile=%h/.config/redteam/client-update.env
EOF
systemctl --user daemon-reload
systemctl --user restart redteam-autoupdate.service
```

`XAUTHORITY` 按实际桌面用户修改，配置中不需要存储 SSH 密码。此模式使用项目 `.client-update/` 下的独立源码和构建目录；源码发生变化或上次构建失败时才重新编译。编译成功后原子替换客户端，并由独立的 `redteam-client.service` 用户服务启动，避免更新服务重启时连带终止客户端。构建失败保留旧程序；启动失败尝试回退上一版，下一轮重试。切换版本会关闭旧客户端窗口，需要重新登录平台。

麒麟系统若启用了 KYSEC 执行控制，需要先由管理员将更新脚本标记为 `verified`，并给固定的客户端暂存及正式路径设置单命令授权；无需关闭整机安全保护。下面示例仅授权 `user4` 为客户端二进制设置执行许可，账号和绝对路径必须与实际部署一致：

```bash
cat > ~/.config/redteam/client-update.sudoers <<'EOF'
user4 ALL=(root) NOPASSWD: /usr/sbin/kysec_set -n exectl -v verified /home/user4/RedTeam-Platform/build/frontend/RedTeam-Platform.next
user4 ALL=(root) NOPASSWD: /usr/sbin/kysec_set -n exectl -v verified /home/user4/RedTeam-Platform/build/frontend/RedTeam-Platform
EOF
sudo visudo -cf ~/.config/redteam/client-update.sudoers
sudo install -m 440 -o root -g root ~/.config/redteam/client-update.sudoers /etc/sudoers.d/redteam-client-update
sudo kysec_set -n exectl -v verified ~/RedTeam-Platform/scripts/auto-update-client.sh
```

如果单文件授权失败，更新脚本保留正在运行的旧客户端并记录错误，不会安装未授权程序。脚本内容再次修改后，需要重新确认该脚本的执行许可。

```bash
systemctl --user status redteam-autoupdate.service redteam-client.service
tail -n 50 ~/RedTeam-Platform/update.log
cat ~/RedTeam-Platform/.client-update/deployed
```

这个机制同步的是**服务器当前源码**，并不自动把开发机上的未提交修复上传到服务器，也不执行服务器端数据库迁移或后端重启。服务器必须先独立完成备份、同步及健康检查。
