# 来源预案与任务执行版本

选择“DVWA 黄金杀伤链”“目录与文件枚举”等已有预案时，来源预案只保留一份，供不同任务选择。建立草稿后，编辑的是当前任务的步骤和参数；来源预案保持原样。

2026-10-13 只读检查实验室现有记录，这两个名称各有一份模板和一份批准执行版本。显示两个同名条目是任务执行版本混入通用预案列表，并非导入器把同一案例保存了两遍。本次修复区分用途，保留历史记录。

草稿与审批确认本次目标、授权范围、执行参数和步骤。批准后保留本任务的执行版本，用于执行与结果追溯，即使后来修改通用模板，也不会改变已经批准的步骤。它不会作为第二份通用预案展示在预案库，也不能再次选作新任务来源。

界面中：

- 预案库与独立执行选择列表只显示可选的来源预案。“包含智能生成内容”也不会把已批准的任务执行版本混入其中。
- 任务预案显示来源名称、当前任务和审批版本，执行版本从所属任务的执行与历史记录查看。
- 执行版本的展示名称包含任务名称和提审版本，例如“DVWA 黄金杀伤链 · DVWA 本次测试 · 执行版本 v2”。批准内容中的原名称保持不变，用于严格校验历史报告来源。
- 既有同名审批记录保留，更新后自动从通用列表隐藏，不删除执行证据，不需要数据库迁移。

接口行为：

- `GET /api/playbooks?includeGenerated=true` 默认排除任务审批执行版本。
- 历史查询可显式使用 `includeSnapshots=true`，仍受原有所有者 / 管理员读取权限约束。
- 直接按已知预案 ID 读取历史执行版本仍可使用 `GET /api/playbooks/:playbookId`；返回 `access.snapshot=true`、`access.direct_run=false` 和独立的 `display_name`。
- 修改或删除批准执行版本仍返回 409；不能从独立执行入口绕过任务审批。
- 新版本的 `metadata.task_plan` 记录来源预案 ID、来源名称、任务名称与展示名称；冻结内容名称和步骤继续与审批记录严格一致。

回归使用仓库实际的 DVWA 黄金模板和目录与文件枚举模板，检查来源只有一份、旧审批记录兼容、重复审批被拒绝、其他用户无法读取执行版本、已批准步骤不受模板后续修改影响，以及历史报告来源校验保持通过。
