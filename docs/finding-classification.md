# 漏洞 AI 场景分类

任务工作台 → 扫描发现 → 勾选漏洞 → **AI 分类**。菜单提供“分类勾选漏洞（复用已有结果）”和“重新分类勾选漏洞”。当前入口位于任务聚合结果表，可通过来源筛选选择子扫描；独立扫描视图暂不提供分类按钮。选择范围是当前列表中已加载、已勾选的漏洞，不包括未加载分页、信息、端口、凭据、错误和输出记录。

分类使用平台配置的大模型，经自己的 Node.js 后端调用，不依赖 PentAGI 分类或执行后端。该操作只保存分类，不创建载荷、测试计划、验证项或执行任务，也不修改原始扫描记录、严重性、验证结论和统计口径。

## 分类与展示

| 代码 | 场景 |
| --- | --- |
| data-exfiltration | 数据抵近窃取 |
| tampering-deception | 信息篡改欺骗 |
| device-control | 关键设备夺控 |
| cross-network-disruption | 跨网致瘫 |
| wireless-attack | 无线攻击 |

每条漏洞可以关联多个场景，模型需要提供依据、分类置信度和待补条件。无法根据现有证据判断时，类别为空数组，显示“无法确定”。“未分类”“无法确定”“分类暂不可用”和“已过期，需重新分类”分别展示，不根据漏洞名称或关键词伪造模型结果。

分类是可能的需求场景关联，不表示攻击发生或验证成立。尤其不能把普通命令执行自动等同于关键设备夺控、跨网可达等同于跨网致瘫、普通 Web 漏洞等同于无线攻击。缺少访问位置、设备身份、拓扑或无线证据时，应明确缺口。

表格增加“AI 场景分类”列；点击标签打开只读详情，查看依据、置信度和待补条件。打开表格或查看详情不调用模型。同任务内刷新保留已勾选 ID；分类期间暂停结果轮询和筛选，防止旧读取覆盖本次结果。切换任务会停止后续批次，迟到回复不更新新任务；已经提交的一批仍可能在后端完成，返回原任务后可读取保存结果。

## API 与保存

`POST /api/pipelines/:id/results/classifications`

```json
{"finding_ids":[123,124],"force":false}
```

仅任务所有者或管理员可用。每次请求接受 1–30 个不重复的稳定 `scan_results.id`；前端每批提交 10 条，后端按最多 10 条及 18000 字符的输入预算进一步拆批。单条脱敏证据最多 6000 字符，截取情况返回 `evidence_truncated` 并进入模型上下文。模型每次最多等待 60 秒，一次 API 请求总模型等待预算为 120 秒；前端请求超时为 150 秒。

响应 `data.items[]` 为 `finding_id` 和 `classification`，另返回 `generated_count`、`cached_count`。`classification` 包括 `schema_version=1`、`state`、`categories`、`reason`、`confidence`、`missing_conditions`、`evidence_truncated` 和保存时间。扫描分页结果 `scan_records[].classification` 和单条结果读取也返回该投影；非漏洞记录为 `null`。

新增迁移 `040_finding_classifications.js`，以任务和稳定发现 ID 保存最新有效分类、实际提供的脱敏输入及来源指纹。来源指纹包含完整脱敏记录、扫描目标、扫描类型和分类规则版本；来源变化后旧结果显示过期，默认分类会重新调用模型。相同来源默认复用已保存结果，包括“无法确定”；明确重新分类才强制生成。

模型 JSON 需要完整覆盖本批编号，拒绝遗漏、重复、外部编号、非法类别和缺失依据；输出未完整结束也不接受。一次 API 的所有模型批次全部通过，且异步请求后重新核对权限、发现可见性和来源指纹，才事务保存。任一批失败均保留本次 API 之前的有效分类。前端跨多个 API 批次执行时，先前成功批次已经保存，后续失败会显示已完成数量。

同一后端进程、同一任务只运行一个分类请求；遇到冲突返回 409。模型调用发生在保存之前，进程中断或响应丢失后可刷新结果再决定重试；没有成功保存的请求重试可能再次调用模型。此版本不提供跨多个后端实例的分类锁。

400 为请求或记录类型无效，401 为身份失效，403 为无权访问，404 为发现不可见或归属不符，409 为并发或来源变化，422 为模型内容无效，502 为模型连接／超时失败，503 为迁移未安装。模型公共错误不返回供应商原文。未安装迁移的旧数据库仍可读取漏洞表，分类显示暂不可用；写入前须按现有部署流程更新后端并运行迁移。

## 验证范围

后端隔离测试覆盖多标签、无法确定、复用、强制重分、权限、跨任务编号、隐藏的源码阶段发现、分批完整性、错误保留、来源变化、并发及旧数据库。Qt 回归覆盖勾选入口、分批、详情、失败保留、错误编号、任务切换与迟到回复，并核对未调用执行接口。

针对性验证命令：

```bash
cd backend
node --experimental-test-module-mocks --test test/finding-classification.test.js
```

在仓库根目录使用现有构建目录：

```bash
cmake --build build --target RedTeam-Platform RedTeam-Platform-Batch16Checks -j2
ctest --test-dir build -R '^ui-context-' --output-on-failure
git diff --check
```

这些验证使用模拟模型与内存数据库，不证明真实模型分类准确率。实际模型输出质量及目标机窗口显示仍需配套环境验收。本次实现不自动启动后端，不迁移本机或远端运行数据库，不执行攻击测试。
