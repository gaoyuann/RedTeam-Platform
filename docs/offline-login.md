# 后端不可用时进入界面

登录继续使用服务器上的原账号，无需创建另一套本地账号。成功在线登录后，客户端按服务器地址、用户名保存带随机盐的 PBKDF2-SHA256 校验值及该次角色，不保存额外的明文密码。

后续登录遇到连接拒绝、主机不可达、超时等传输错误，或服务器返回 HTTP 5xx 时，客户端使用缓存校验输入的密码；匹配即可进入主界面。后端明确返回 HTTP 401／403 时不会离线放行，并删除该账号在当前服务器下的缓存。服务器恢复后，再次在线登录会更新缓存。

没有登录缓存的新终端也可以点击登录页的“离线打开界面”，以离线访客身份进入，查看本地界面。该入口无需服务器或密码，不创建账号，也不会授予后端权限。网络请求进行期间也可点击此入口；迟到的登录响应不会覆盖离线身份。

主界面状态栏标明“离线”。离线登录不生成或沿用 JWT，扫描、在线任务、报告数据和用户管理仍需要服务器提供服务并验证身份。后端恢复后，退出登录再用原账号登录；“检测连接”只检查可达性，不会自动恢复认证。

缓存位于 Qt 的 `RedTeam/RedTeam-Platform` 用户配置中，使用 `offlineLogin/` 键。原“记住密码”设置保持原行为；离线缓存独立于该选项，不读取后端数据库，也不会同步到其他终端。此前版本登录过的终端，需要在更新后成功在线登录一次才会建立缓存；此前也可通过访客入口进入界面。

验证：`cmake --build build --target RedTeam-Platform RedTeam-LoginChecks -j 4`；`ctest --test-dir build -R '^ui-login$' --output-on-failure`。测试使用临时用户配置和回环模拟服务器，不修改真实账号、配置或数据库。

本次验证：应用、登录检查及原 Batch16Checks 目标构建通过；登录专项 11 项通过；`ctest --test-dir build -R '^ui-task-journey$' --output-on-failure` 通过。首次运行登录专项发现 Qt 的 `StripTrailingSlash` 保留根路径 `/`，造成同一服务器的缓存键不一致；已改为显式归一化路径，原断言重跑通过。未在云笔电上部署或执行真实后端联调。
