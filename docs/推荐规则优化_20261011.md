# 推荐规则优化（2026-10-11）

## 背景

原推荐链路把扫描结果先归并成工具类别，再按固定权重排序；流水线只取排序第一项。因此，多个任务出现“漏洞模板扫描（Nuclei）”并不一定表示发现了可利用漏洞，更多时候只是通用扫描器在候选中的固定优势。推荐结果也没有充分区分“入口补全、配置复核、漏洞定向验证”三个阶段。

本次优化先在本地完成规则和回归验证，随后按用户指令部署到服务器和云笔电；**未合并 PR**。

## 新规则

### 1. 以证据类别匹配能力

- 将结果归并为 SQL 注入、文件上传、XSS、凭据、响应头、Cookie、敏感暴露、目录索引、待复核漏洞、云配置、Web 指纹和主机服务等证据类别。
- 同一类别只保留最有代表性的证据，重复的低价值结果不会线性放大分数。
- `not vulnerable`、失败扫描、无效 HTTP 状态、原始输出和不完整主机发现不生成攻击推荐。
- 页面标题或产品名称只作为 Web 指纹，不能单独推断 SQL 注入、DVWA 或可利用漏洞。

### 2. 按任务阶段推荐

- **入口与信息补全**：HTTP/技术指纹、主机服务、目录与参数发现。
- **补充扫描/配置复核**：Nikto、通用 Nuclei、响应头、Cookie 和敏感信息暴露复核。
- **漏洞定向验证**：只有存在对应 SQL 注入、上传、XSS 或凭据线索时，才进入验证候选。
- 预案包含固定入口、具体参数、认证凭据、会话 Cookie 或高风险参数时，候选标记为“需补充执行条件”，不允许静默执行。

### 3. 纳入已完成检查和目标范围

- 推荐只读取调用方明确提供的扫描任务 ID，并要求扫描任务目标完全匹配、状态为 `COMPLETED` 或 `PARTIAL`。
- 同一扫描任务中的外域 URL、重定向到其他端口的结果不会借用为当前目标的漏洞证据。
- 已完成的同类检查会标记为“本任务已检查”并降低重复检查优先级；失败工具不会被视为已完成。
- 同分时优先选择“可供选择”的候选，再选择需要补充条件或已检查候选。

### 4. 安全边界默认收紧

- 自动推荐路径排除 DoS、破坏、持久化、外传、权限维持、文件写入、SQL 导出、OS Shell 等高风险动作。
- 未能识别的工具或参数不进入自动证据推荐；人工预案目录仍保留原有能力，但不能因此自动执行。
- DVWA 专用预案只有在目标画像明确确认 DVWA 且置信度达到阈值时才参与推荐。
- 自动执行资格仅授予“漏洞定向验证 + 所需证据齐备 + 执行条件齐备”的候选；其余候选必须经过人工确认。

## 真实案例回放

使用 2026 年 10 月 11 日保存的扫描任务证据回放三组目标：

- 目录与入口证据较强的目标，目录枚举候选可以排在 Nuclei 前面。
- 仅有响应头、Cookie 或敏感暴露观察结果的目标，Nuclei 仍可能是第一候选，但原因是“补充扫描/配置复核”，不是漏洞已确认；目录枚举、通用复核等候选仍会同时返回。
- SQL 训练站页面标题不会被当作 SQL 注入证据；首页只有 SQL 线索时，SQLMap 候选会标记缺少具体参数入口，审批接口拒绝直接执行。
- 已完成 Nikto 检查的目标，重复 Nikto 会标记为“本任务已检查”并降低优先级。
