# Web 扫描入口与页面发现

通用 Web 扫描（Nikto）会把字典路径拼接到扫描入口。它适用于网站根路径或明确的应用目录，不应直接用于登录页、表单提交地址或 API。服务器可能把 `/login.php/任意路径` 当作脚本的附加路径，始终返回登录页和 HTTP 200，造成大量与目标无关的产品、文件和漏洞候选。

## 调度规则

- 根路径和以 `/` 结尾的目录 URL 可进入通用扫描，例如 `http://example.test/`、`http://example.test/app/`。现有任务范围、排除项、可达性和新入口预算继续生效。
- 自动发现的具体页面、无尾斜杠且类型不明确的路径、表单和 API 保留在入口清单中，通用目录检查标记为“未检查”并记录原因，不消耗新目录扫描预算。表单同时保留缺少方法、字段或角色条件的专项检查记录；当前未自动接入这些入口的专项验证。
- 脚本附加路径（如 `/login.php/`、`/login.php/admin/`）、查询参数及含糊的编码路径不作为目录扫描入口。不会自动改成父目录，避免扩大原目标。
- 手动执行或旧队列中的 `web_scan` 若使用页面 URL，将保存扫描错误并跳过 Nikto。若另外指定了同源 `sqli_url`，仍沿用既有显式 SQL 注入验证流程。裸主机或 IP 仍按原有规则识别为根入口。
- 重复探测同一地址不会重复安排检查；同一地址既是跳转落点又是表单地址时，两种入口证据均保留。
- 初始目标与新增入口使用相同的类型判断。无后缀且以 `/` 结尾的登录表单、空 action、缺省 action、未加引号的 action 和 API 记录也不能作为目录基址。含密码输入的页面同时记录为页面入口。
- Nikto 与 FFuf 的实际执行入口统一校验，覆盖手动任务和旧队列。阻止 FFuf 不影响已经显式发起的 Arjun 参数发现；这种任务会显示部分完成和未执行原因。

## 执行前响应对照

通过静态入口校验后，每个目录工具最多进行 3 次 GET：基址、随机不存在路径、随机不存在的 `.php` 路径。单次请求上限 5 秒、响应上限 64 KB，不跟随跳转，不请求范围外地址。FFuf 对照实际使用的 `api/` 前缀，允许该前缀本身没有索引页（404/410）。

两个不存在路径必须都明确返回 404 或 410。成功页、跳转、认证拦截、服务异常、超时和响应不完整均停止目录扫描并说明原因，不将其解释为漏洞成立或目标安全。即使 CSRF 标记等动态内容不同，随机路径返回成功也不能据此推断文件存在。

对照证据仅保存角色、状态码、字节数、内容 SHA-256 和阻止原因，不保存响应正文、会话或 Cookie。取消期间不会继续启动字典扫描。此检查不会遍历现有候选或删除证据。

目录扫描附加参数只允许有限的速率、并发、超时和显示选项，不允许覆盖目标、根目录、认证、代理或关闭过滤；端口须与 URL 一致。FFuf 的专用 Cookie 字段同时传给对照和实际扫描，并在证据中脱敏。原 Nikto 适配器的 `-C` 并非可靠的 Cookie 传递方式，因此含 Cookie 的 Nikto 扫描会明确停止；需要认证时使用显式专项验证，不静默降级为未登录扫描。Nikto 2.1.6 的选项定义可参见[官方实现](https://github.com/sullo/nikto/blob/2.1.6/program/plugins/nikto_core.plugin)。

“未检查”和原因通过既有 `scan_coverage.entries/checks` 返回，Qt 扫描页使用现有状态与提示展示，无新增 API 或前端构建要求。

## 应用与限制

更新后端并重新加载服务后，新任务使用上述规则。历史扫描结果、原始证据和验证引用不改写，原有两千多条候选不会自动消失；应创建新任务核对修复效果。仅有源码更新而后端进程未重新加载时，仍运行旧逻辑。

目录 URL 的形状不证明服务器确实存在该目录。本修复增加有界的随机路径对照，保守阻止软 404、登录跳转和通配成功响应。SPA、统一认证网关或统一错误路由可能因此被标为未检查，需要专项验证。对照只是扫描前的有限样本，不能保证覆盖所有后缀、User-Agent 差异、扫描期间路由变化或每条规则误报；扫描结果仍为待验证候选，不保证固定发现十几条。

## 本地验证

在 `backend/` 运行：

```sh
node --experimental-test-module-mocks --test test/web-scan-policy.test.js test/web-directory-probe.test.js test/scan-coverage.test.js test/scan-coverage-pipeline.test.js test/scan-result-integrity.test.js
```

回归涵盖根入口跳转登录页、重复表单证据、目录预算、初始表单/API、脚本附加路径、显式页面目标、FFuf 基址、参数覆盖、软 404、失败、取消和保留历史候选。工具使用测试替身；响应适配器另外通过回环 HTTP 服务验证不跟随跳转，不向实际靶场发起扫描。
