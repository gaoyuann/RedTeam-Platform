# RedTeam-Platform 系统重构技术文档

> 本文档记录 RedTeam-Platform 从 Phase 0 到 Phase 6 的完整实现过程、架构设计、文件结构和已知问题，供后续维护和修改参考。

---

## 一、项目概述

RedTeam-Platform 是对 RedTeam-Edu（React+Electron+Node.js）的全面重构，核心改动：

| 维度 | 旧系统 (RedTeam-Edu) | 新系统 (RedTeam-Platform) |
|------|---------------------|--------------------------|
| 前端 | React + Electron | Qt5/C++ (兼容国产OS) |
| 数据存储 | JSON/内存 | SQLite (better-sqlite3, WAL模式) |
| 工具执行 | Docker直接调用 | Podman优先→Docker→host 三级回退 |
| 工作流 | 手动选Playbook→执行 | 扫描→推荐/生成Playbook→执行 |
| 分发 | npm打包 | AppImage/便携目录 (内嵌Node运行时) |

### 架构

```
Qt5/C++ 前端 (端口无关，HTTP客户端)
    ↕ HTTP (127.0.0.1:3002)
Node.js Express 后端 (ESM, 端口3002)
    ↕ better-sqlite3
SQLite 数据库 (data/redteam.db, WAL模式)
    ↕ child_process / podman run
容器化工具 (8个镜像, Alpine 3.19)
```

### 开发环境

- WSL2 Ubuntu 22.04 on Windows 11
- Qt 5.15.3 (apt), CMake 3.22.1, g++ 11.4.0
- Node.js v22.10.0, npm
- 构建命令：`cmake -B build -S . && cmake --build build`
- 运行：`./scripts/start.sh`（开发模式）或 `./dist/RedTeam-Platform/start.sh`（便携模式）

### 6.2 工具执行流程

```
toolRunner.runTool(toolId, args)
  → containerEngine.getEngine()  // podman > docker > host
  → 查 IMAGE_MAP[toolId] 得镜像名
  → 查 BIN_MAP[toolId] 得容器内二进制路径
  → podman run --rm --network host [-v wordlists] [-v nuclei-templates] <image> <bin> <args>
  → 返回 { success, exitCode, stdout, stderr, executionMode }
```

特殊配置：
- 特权容器：nmap, mitm6
- 词表挂载：hydra, gobuster, ffuf, john, nikto → `/usr/share/wordlists`
- Nuclei模板挂载：nuclei → `/usr/share/nuclei-templates`
- 输出大小限制：2MB，超时：300s

## 七、核心业务逻辑

### 7.1 扫描驱动工作流 (Phase 4)

```
用户创建扫描任务 → 扫描完成
    ↓
playbookMatcher: scan_results → 匹配预定义Playbook
  - MITRE精确匹配 (score × 3)
  - severity驱动: result_type → baseline_group
  - 端口覆盖: 445→brute, 80→vuln_scan, 3306→exploit
  - 兜底: low severity → recon
    ↓
playbookGenerator: scan_results + LLM → 生成新Playbook (is_generated=1)
    ↓
用户选择Playbook → executionEngine逐步执行
  - 替换args_template中<target>占位符
  - 逐步调用toolRunner.runTool()
  - 记录execution_steps
  - 非optional步骤失败 → 标记run FAILED
```

### 7.2 评分引擎 (Phase 5)

```
gradingEngine.computeGrade(runId):
  1. 步骤得分: earned = Σ(step.score WHERE success=1), total = Σ(step.score)
  2. MITRE覆盖率加分: mitreScore = round(covered/114 × 20)
  3. 总分: finalEarned = earned + mitreScore, finalTotal = total + 20
  4. 等级: ≥90=A, ≥80=B, ≥70=C, ≥60=D, <60=F
  5. 缓存到execution_runs.score_data
```

### 7.3 LLM集成

- 配置来源：system_config表 category='llm' → 环境变量fallback (LLM_API_KEY, LLM_BASE_URL, LLM_MODEL)
- API兼容：OpenAI格式 (覆盖DeepSeek/Qwen/本地Ollama)
- 用途：playbookGenerator生成Playbook
- 超时：120s，不reject

```bash

./scripts/package-linux.sh

# 3. 内嵌Node.js运行时
./scripts/embed-node.sh [v22.10.0]
```

### 8.3 start.sh行为

1. 检测便携/开发模式（bin/RedTeam-Platform是否存在）
2. 设置 `LD_LIBRARY_PATH` + `QT_PLUGIN_PATH`
3. 启动内嵌Node后端 (`./node/bin/node backend/src/server.js`)
4. 轮询 `/api/health` 等后端就绪（最多30s）
5. 启动Qt前端
6. 退出时kill后端进程
