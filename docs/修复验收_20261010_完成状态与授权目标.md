# 完成状态、评分明细与授权目标修复

- 日期：2026-10-10。
- 基线：`ad7c039`（远端 `main`）；在独立 worktree 中修改，未带入正在开发的任务工作台改动。
- 本文使用 `http://192.0.2.10:8088` 作为脱敏示例，不包含真实内网目标、凭据、令牌或完整运行日志。

## 已核实原因

云笔电连接的是服务器后端，不是开发机数据库。对应任务的运行与流水线均由后端返回完成状态，但摘要实际记录成功 1 步、失败 5 步、未执行 3 步。

1. `web_vuln_exploit` 四个预案步骤全部为 `optional=1`，AI 动态步骤也为可选。旧终态只检查必选步骤失败或未执行，所以全可选计划即使提前结束也可能返回 `COMPLETED`。
2. 固定评分表按原预案索引与工具匹配。三个没有执行记录的预案步骤被统一标为失败，没有区分“未执行”。
3. AI 新增动作把任务 URL 改成了扫描证据中出现的容器内网地址，后续五次调用连接失败。授权目标未固定呈现在每轮提示词中，动态动作入队也未验证 URL 范围。

## 修复策略

### 执行与流水线

- `COMPLETED` 仅用于所有计划步骤最终成功的运行。任一步骤失败、编译阻断、未执行、被 pivot 移除，或者空计划，不再标记完成；使用既有 `FAILED`，无需扩展数据库状态枚举。
- `optional` 仍决定机械引擎是否立即停止；它不再表示可忽略失败并宣称测试完整完成。
- 人工取消保留 `ABORTED`；超时保留 `FAILED`。AI 停止本身不是成功依据，最终结果仍按步骤核对。
- 汇总直接根据最终步骤状态计算成功、失败和未执行数量，不使用可能因重试发生偏差的累计计数；保留执行尝试次数。
- 将具体失败原因传给流水线，避免出现 `执行阶段失败: undefined`。
- 失败任务仍可打开评分与生成报告，避免终态修正后丢失结果入口。

### 评分

- 每个计分步骤增加 `status`：`PASSED`、`FAILED`、`NOT_EXECUTED`。
- 前端分别展示“通过”“失败”“未执行”及三个计数；兼容没有新字段的旧评分响应。
- 原始分值与 MITRE 加分算法不变。工具成功退出不等于发现漏洞；评分不作为目标风险评级。

### 目标校验

- 两种 ReAct 模式每轮都提示权威任务目标；示例改用执行器支持的 `{{base_url}}`，不再使用 `http://target:8080`。
- `insert`、`parallel`、`pivot`、`adjust` 在改变计划前渲染参数并核对显式目标；被拒绝的动作不占用新增步骤配额、不移除原计划、不触发工具调用，并写入 `guardBlocks`。
- URL 任务的显式 URL 必须与任务目标同协议、同主机、同端口，可改变路径和查询参数；不自动把越界目标改写成其他地址。
- 执行前再次校验已渲染参数；越界步骤保存为阻断结果，工具不启动。阻断目标文件、请求文件及 curl 连接覆盖配置等无法直接核对的输入形式。
- 本轮解决明确 URL 参数的目标偏离，不替代工具内部重定向、DNS 解析、模板内容和实际出站网络的隔离。非 URL 任务的多主机/CIDR授权管理仍需独立设计。

## 历史记录校正

迁移 `024_reconcile_execution_outcomes.js` 在事务内处理原状态为 `COMPLETED`，且原摘要明确记录失败、未执行、必选失败或超时的运行：

- 改为 `FAILED`，保留原始计数与停止原因，并增加 `statusReconciliation` 审计信息。
- 清除旧评分缓存，下一次评分生成区分未执行的新明细。
- 同步关联的已完成流水线与执行阶段，保留扫描和分析数据；不覆盖已经取消的任务。
- 没有可靠摘要或摘要无法解析时不猜测，不用低分推断失败；成功记录、非完成记录及已有报告文件不重写。
- 幂等：重复执行不再次修改已经校正的记录。

部署前备份数据库并暂停业务写入；部署后启动后端会自动执行迁移。回滚旧代码不会自动撤销数据校正，如需恢复必须使用部署前备份。已生成的旧报告应重新生成，而不是修改原文件。

## 上线验收边界

本次提交 PR，不直接部署、重启生产服务或改写生产记录。合并及发布后需同时更新后端与云笔电客户端，再核对原异常任务是否变为失败、三个评分项是否显示未执行。若只更新后端，旧客户端仍会把评分中不成功的步骤统一显示为失败。
