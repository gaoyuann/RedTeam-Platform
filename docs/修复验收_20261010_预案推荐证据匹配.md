# 预案推荐证据匹配修复与验收

## 问题与根因

用户反馈云笔电上三个不同靶场均推荐“Web 漏洞利用通用测试”。本地使用内存数据库和仓库预案库复现了相同偏置，未连接云笔电或读取其三个扫描记录。

- 原匹配器将 Nikto 的 `web_vuln`、Nuclei 的 `vulnerability` 默认归入 `vuln_scan`；大量专项模板却使用 `web-vuln-scan`，未被等价匹配。
- 漏洞子类型只读取 `vuln_type`、`title`，没有读取工具实际输出的 `finding`、`template`、`detail`。安全头缺失与 SQL 注入模板因而容易走相同分支。
- 同为 `web_url` 的通用预案得到固定类型加分，即使没有相应上传、认证或利用证据也会进入推荐；同类结果还会逐条累加，使重复配置发现压过专项证据。
- 许多只有通用工具步骤的预案历史元数据标注为 DVWA，原逻辑将它们和真正含 DVWA 固定路径、会话变量的预案一起排除。
- 前端推荐表启用了列排序，但没有分数列或固定的默认分数排序，不能保证第一行就是最高匹配项。

## 修复范围

1. 按实际工具字段区分配置缺失、SQL 注入、文件上传、XSS、弱口令及侦察发现，结合预案实际工具和参数选择候选；兼容两种 Web 扫描基线名称。
2. 相同信号只保留最高权重，对辅助信号贡献设上限；目标兼容性只作为已有证据命中的加分，不再凭类型制造推荐。
3. 不兼容及 `notSuitableFor` 明确排除的预案不进入列表。含 DVWA 专属路径、会话或入口变量的模板必须有当前扫描的高置信度 DVWA 指纹；纯通用步骤不因旧 DVWA 标签被误排除。
4. 扫描推荐接口仅以选中扫描的结果重建画像，历史扫描也可解释，不借用相同目标的其他扫描记录。
5. 增加 `web_sqli_verify` 通用 SQL 注入定向验证预案及迁移 `025_import_sqli_verify.js`。不预置 DVWA 路径、凭据、数据库名，不自动导出数据或获取系统 shell。
6. 前端显示数值匹配分，并在加载后按分数降序排列。

## 验收与限制

| 输入证据 | 预期行为 |
| --- | --- |
| 安全头缺失、Cookie 安全配置发现 | 优先配置专项扫描，不当作已证实的漏洞利用 |
| 通用目标的 SQL 注入模板或 sqlmap 发现 | 优先通用 SQL 注入定向验证，不套用 DVWA 路径 |
| 文件上传漏洞模板 | 优先上传专项测试 |
| 仅 HTTP 可达或技术指纹 | 推荐侦察类方案，不凭可达性推荐漏洞利用 |
| 高置信度 DVWA 指纹与 SQL 注入发现 | 优先适配 DVWA 的 SQL 注入步骤 |
| 只有错误、原始输出或无发现 | 不制造命中项 |
| 大量重复配置发现与一个 SQL 注入发现 | 重复条目不挤占 SQL 专项优先级 |

本地验证使用 `node --test backend/test/*.test.js`、`cmake --build build --target RedTeam-Platform -j2` 和 `git diff --check`。测试数据库均为内存数据库，不清理或迁移现场数据。

最初工作区验证结果：23 项测试全部通过，其中新增推荐回归测试 15 项；前端编译链接成功，JavaScript 语法与差异空白检查通过。另在内存数据库执行完整迁移链，确认新增预案正常导入。

PR 另从 `origin/main` 的 `6eb48e7` 建立独立工作树，仅带入本次推荐修复，不包含原工作区的其他功能改动。在独立工作树中执行 `node --experimental-test-module-mocks --test backend/test/*.test.js`，32 项测试全部通过；执行 `cmake -S . -B build-pr -DCMAKE_BUILD_TYPE=Release`、`cmake --build build-pr --target RedTeam-Platform -j2`，前端编译链接成功。完整迁移链及重复迁移调用在内存数据库验证通过，已有预案库升级的幂等性也由回归测试覆盖。

构建环境未安装 Qt5 WebSockets，使用仓库已有的非实时推送降级配置；现有 `FlowPage`、`TopologyPage` 的 Qt 弃用警告未作为本次修复范围。

本次并未增加 Pikachu、SQLi-Labs 的全流程产品适配，也未声称三个靶场必须得到三个不同预案。若实际证据相同，推荐相同的初筛方案仍可能合理；推荐必须能够用证据解释。

SQLi-Labs 及其他 SQL 注入目标执行前需要选定具体带参数入口。本次新增模板仍使用执行时选定的 `<target>`，不自动从扫描发现中改写执行地址，也不能将首页扫描解释为全部 lesson 已验证。

云笔电尚未部署或现场复测。验收需要更新后端和前端，启动后端应用新增预案迁移，分别检查三个扫描的类型、实际发现、匹配原因、分数及最终执行入口。若旧扫描没有应用指纹，不应补猜其靶场身份。
