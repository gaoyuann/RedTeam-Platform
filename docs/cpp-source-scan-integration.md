## 使用流程

1. 扫描后端运行在一台云笔电（或服务器），靶场程序运行在另一台云笔电。若靶场已像截图一样通过 `/source/` 提供目录索引，后端可直接通过 HTTP 只读获取；否则使用 SSH 只读获取。扫描工具和 AI 仍运行在后端，不需要在靶场云笔电安装扫描器。
2. 构建扫描镜像：`docker build -t rt-sast-c containers/sast-c`。Podman 同样适用。没有容器引擎时使用本机 cppcheck、Flawfinder。源码读取需要 Python 3。
3. HTTP 源码目录可直接在页面填写，不需要配置文件。若要保存常用映射或使用 SSH，将 `data/source-scan/connections.example.json` 复制为 `data/source-scan/connections.json`，按源码暴露方式填写 `source_url` 或 SSH 只读参数、项目标识和运行地址。也可通过 `SOURCE_SCAN_CONNECTIONS_FILE` 指定配置位置。
4. 试测前备份数据库和现有程序版本，启动后端，由现有迁移器创建 `source_audits` 和 `source_verifications` 表。使用重新编译的 Qt 客户端，在现有新建任务弹窗选择“C/C++ 源码辅助测试”；单独扫描页面的“C/C++ 程序测试”也保留。
5. 像现有扫描一样输入靶场运行地址。源码目录可填完整 URL 或 `/` 开头的路径，也可点击“浏览远端目录…”打开目录索引，进入子目录后点击“选择当前目录”。手动目录优先于后端映射；留空则按运行地址匹配已配置项目，没有映射时仅进行远程测试。确认 AI 分析批次后创建测试。
6. 查看源码发现、文件行号、代码哈希、工具分析、关联证据和覆盖记录。任务模式在扫描分析后等待选择攻击演示对象；选择 1–10 条发现，逐项生成正常对照和验证步骤，进入现有任务预案建立草稿，审阅后执行 HTTP/TCP 验证。单独扫描页仍可直接前往执行。
7. 在扫描结果中复核发现，引用关联步骤的真实执行证据，保存“支持 / 未复现 / 无法判断”的结论。

未选择源码项目时仅进行远程 HTTP/TCP 测试，覆盖记录明确显示没有读取源码。网站地址无法替代源码目录。源码扫描可在服务离线时执行，入口请求失败会使任务显示部分完成。

例如运行地址填写 `http://192.168.1.113:8089`，源码目录填写 `/source/`；另一项目也可填写 `/project/code/`，程序没有固定拼接 `source`。目录浏览由后端访问远端 HTTP 服务，不是打开客户端本机文件选择器。若站点不提供目录索引，弹窗无法枚举其磁盘目录；此时应使用 SSH 项目配置。选择的源码 URL 会保存在任务参数和快照清单中，便于核对版本与覆盖范围。

## 项目配置

```json
[
  {
    "id": "my_cpp_program",
    "name": "C++ 程序",
    "kind": "http",
    "source_url": "http://192.168.1.113:8089/source/",
    "targets": ["http://192.168.1.113:8089/"],
    "architecture": "arm64",
    "analysis": {
      "standard": "c++17",
      "platform": "unix64",
      "defines": ["FEATURE_ENABLED=1"]
    }
  }
]
```

`standard` 可省略，支持 c89/c99/c11 或 c++03/11/14/17/20。`platform` 支持 unix32、unix64、win32A、win32W、win64；Linux ARM64 项目默认 unix64，它描述类型宽度，不能模拟 ARM64 指令。`defines` 只接受受校验的宏名和简单值，最多 32 项，不接受命令字符串。具体项目应使用真实构建条件。

截图这种 Apache 目录索引使用 `kind: "http"` 和 `source_url`，必须与运行目标使用同一协议、主机和端口；后端只跟随同一源码根目录下的链接，不跟随重定向、不访问外部主机、不执行源码。若未暴露目录索引，仍可使用 `kind: "ssh"` 的只读配置。

扫描后端发起两类远程连接：源码快照通过 HTTP 或 SSH 访问靶场云笔电，HTTP/TCP 验证也由后端直接访问靶场云笔电的运行地址。Qt 客户端只访问后端，不要求两台云笔电互相暴露数据库或扫描服务。部署前应在后端机器检查源码来源和运行地址的连通性；HTTP 来源可执行 `curl http://192.168.1.113:8089/source/`，SSH 来源需执行 `ssh -o BatchMode=yes ...`。如果运行地址不可达，扫描会保留已获取的源码结果，但程序验证会显示连接失败，不能据此判定漏洞不存在。

## 分析与效果

- cppcheck 提供其支持的越界、空指针、生命周期等静态诊断；Flawfinder 补充危险调用候选和 CWE。XML 属性顺序、转义字符和 CSV 多行内容不会丢失定位。
- 快照包含最多 500 个 C/C++ 文件，每文件 512 KiB、总内容 8 MiB。源码只读挂载，静态工具容器禁用网络。符号链接、不支持编码、超限和读取失败会记录。
- AI 首先审查静态告警及危险操作附近代码，默认最多 12 批，页面可调至 24 批。每批最多 120 行，并检索最多 4 个相关代码片段。主定位和跨文件引用必须对应本批提供的真实代码。
- 合并重复候选时保留工具/AI 的各次依据；cppcheck 多位置诊断保存为关联代码证据。静态结果一直标为待验证，不把危险函数名称或 HTTP 200 当作漏洞成立。
- 预案默认允许 Agent 根据证据追加请求，也可在页面关闭，或生成 API 传入 `adaptive:false`。执行页面选机械模式也会关闭动态追加。Agent 最多 8 次决策，整次程序验证有 10 分钟期限，请求限制同协议、同主机、同端口。
- 扫描、预案、执行、报告及程序事件按任务创建者和管理员隔离；报告的列表、生成、导出和修改沿用相同检查。

目前没有接入完整 `compile_commands.json`、项目依赖和编译器调用图，也不自动编译运行被测源码。相关代码检索基于词法，AI 完成审阅不等于证明代码安全。Flawfinder 对已做边界检查的调用仍可能产生候选；需要结合源码和运行证据复核。

cd backend
SOURCE_TEST_SAST=1 node --experimental-test-module-mocks --test test/*.test.js
