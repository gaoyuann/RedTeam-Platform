# PR 说明与部署验收

建议标题：接入 C/C++ 源码扫描、代码证据分析和 Playbook 验证流程

## 问题与改动

原来的源码告警缺少稳定的源码版本、充分的代码上下文及逐发现的运行证据关联，无法把静态疑点可靠地传递给后续验证。

本次在现有扫描、预案和执行体系中接入 C/C++ 源码扫描：112 收集并冻结源码副本，运行 cppcheck/Flawfinder，再由 AI 结合相关代码分析。发现保存文件、行号、代码、哈希、前提、修复建议及可校验的证据链；同位置重复告警保留不同检测来源。选中发现后生成验证预案，按既有引擎对 113 的 HTTP/TCP 入口执行，人工引用实际证据复核。

113 保持现有部署，无新增扫描器或 Agent。新任务弹窗支持源码辅助模式及远端源码目录选择；扫描分析后选择演示对象，每项独立生成正常对照与验证。预案进入现有任务草稿审阅和机械执行，步骤及证据保留发现 ID 和阶段。没有源码时显示远程黑盒测试，不声明源码覆盖。

- 新增闭环验证覆盖 4 项发现 / 8 步演示、清单顺序、逐项证据、审批复制预案的证据查询，以及拒绝重复输入 / 混合关联 / 编辑后丢失对照。
- Qt 前端编译通过；任务范围与源码选择入口在 1、1.25、1.5 三种缩放下通过回归；构建输出仍有既有 Qt 弃用警告。
- Git 差异空白检查通过。
- 模型回复由测试替身提供；以上不是实际模型发现率或云笔电部署验收。

## 部署顺序

1. 备份现有数据库，在 112 部署后端、前端及兼容架构的 rt-sast-c 镜像。
2. 指定 113 上可读取的 HTTP 源码目录，或通过 data/source-scan/connections.json 配置 SSH / 本机快照来源并绑定运行入口。
3. 启动后端应用迁移，先运行一个小项目，检查快照、扫描覆盖及工具状态。
4. 验证 112 到 .113:8089、8090 的 HTTP 和 .113:8091 的 TCP 连通性。
5. 使用已知漏洞与修复版本进行对照，记录漏报、误报及真实触发证据，再决定是否合并。

## 需要关注的限制

- 代码片段及相关上下文检索有预算；尚无完整编译数据库、跨文件数据流或宏配置分析。
- 静态分析及 AI 输出为待复核疑点；执行成功不代表漏洞成立。
- 不提供 ARM64 调试、崩溃回收和任意二进制交互。
- 源码版本与线上二进制的一致性由发布记录核对。
- 当前源码推荐列表展示本任务生成的预案，不按 CWE 自动套用任意库存模板。
- HTTP 目录可输入或浏览索引选择，目录名不固定为 source；SSH / 本机来源使用后端项目配置，没有新增上传/克隆界面。
- 自动发现目标上所有已安装软件、纯本地漏洞和进程级内存利用证明仍不在当前覆盖内；需要逐软件清单和实际部署验收。
- 现有报告可以保存执行和追溯材料，但源码发现、扫描覆盖和逐发现人工复核还没有完整纳入报告正文。这是试测版本的已知缺口，不能据此按完整源码测试报告验收。
