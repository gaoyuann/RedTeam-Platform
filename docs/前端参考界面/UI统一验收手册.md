# UI 优化统一验收手册

> 用途：第 1–16 批修改完成后的统一人工验收。自动化回归只证明接口、状态和隔离契约成立，不能替代真实账号、真实授权任务和目标部署机上的视觉检查。

## 一、验收前准备

1. 使用重新构建的前端程序，并确认后端已加载全部数据库迁移。
2. 准备三个账号：普通用户 A、普通用户 B、管理员；普通用户 A 使用一条明确授权的测试目标。
3. 记录验收任务编号、目标、授权范围、创建模式（快速/完整）、执行策略和开始时间。
4. 不要把生产目标、真实凭证或未授权地址填入验收任务；本手册只验证平台流程，不授权任何目标。

## 二、任务闭环

| 步骤 | 操作 | 通过标准 | 证据 |
| --- | --- | --- | --- |
| 1 | A 创建快速任务，再创建完整任务 | 两种模式都保留同一目标、当前登录人和授权范围；伪造创建人不会生效 | 任务编号、目标、创建人、配置摘要 |
| 2 | 从任务概况进入扫描/分析 | 页面只展示当前任务数据，六阶段为准备→扫描→分析→预案→执行→评估；后端仍是四类执行步骤 | 截图或任务日志 |
| 3 | 查看扫描和智能分析 | 结构化扫描记录、AI 候选、工具返回和证据分区展示；候选带“未复核/不等于漏洞成立”提示，不以来源校验替代漏洞验证 | 候选名称、来源和提示截图 |
| 4 | 打开预案并编辑 | 预案目标、授权范围、步骤和来源预案可追溯；保存后版本号增加 | 预案版本和历史记录 |
| 5 | 提交预案审批 | 普通用户可提审；未确认授权、候选未处理或旧版本提交会被阻止 | 错误提示或日志 |
| 6 | 用管理员审批 | 非管理员不能审批；批准后显示批准版本，并进入执行准备/执行状态 | 审批人、审批版本和时间 |
| 7 | 查看执行、尝试和证据 | Run、步骤、尝试、证据通过任务编号、所有者、目标和尝试编号关联；失败/未执行不被当成安全结论 | 执行快照截图 |
| 8 | 生成结果报告 | 报告是冻结来源快照，显示来源指纹、预案版本、Run 和证据；重复生成相同来源会复用 | 报告编号和来源链 |
| 9 | 提交并完成报告审阅 | 报告审阅版本独立递增；任务所有者不能自审；审阅不把候选改成已验证漏洞 | 审阅历史和候选状态 |
| 10 | 导出 JSON/HTML | 导出内容与冻结快照一致，包含来源链、范围声明和脱敏提示；不支持的格式明确拒绝 | 下载文件或响应结果 |

## 三、隔离与异常验收

- A 的任务编号、日志、预案、执行、结果和报告，使用 B 账号访问均应明确拒绝；B 只能看到自己的任务。
- 管理员可以检查跨用户任务，但普通用户不能通过修改 URL、请求体中的 `created_by`、任务编号或目标绕过所有权检查。
- 同一目标创建两条任务时，任务名称、预案版本、Run、证据和报告不能互相串联。
- 仅在可丢弃的隔离数据库中将任务关联的 Run 所有者或目标改成不匹配值，执行/结果接口应拒绝展示；正式数据库不要做此破坏性检查，也不能把来源错误降级成空数据。永久回归已自动覆盖这一项。
- 让分析、日志、结果、资源索引分别返回失败和空列表，页面应区分“加载中”“加载失败”“暂无数据”“未接入”，且不残留上一任务内容。
- 关闭或返回来源页后，不应误触发启动、取消、扫描、执行、生成报告或提交审批。
- 任务 A 切换到 B 的加载期间，A 的扫描列表、目标、阶段完成状态和顶部操作应立即清空；返回来源页后，迟到扫描响应不得恢复旧数据。同一任务返回后立即重开，也不能被上一次请求覆盖。

## 四、视觉与响应式验收

在至少 `1024×600`、`1360×860` 和目标部署机尺寸下各检查一次，并在目标高 DPI 缩放下复核：

- 左侧导航、顶部标题、阶段指示器和主要操作均可见；窄窗口使用滚动/折叠，不遮挡核心操作。
- 任务名称、目标、状态、阶段名称和账号信息使用纯文本；含 HTML 标签的测试名称应显示字面文本而非被渲染。省略的名称有完整提示，核心状态仍可辨认。
- 表格空态、加载态、失败态和成功数据不重叠；重试后旧任务内容不会回填到新任务。
- 工作区、AI 协作面板、任务日志和页签可独立滚动/折叠；返回按钮显示正确来源。
- 全局搜索和通知若仍显示“未接入”，应保持禁用，不得表现为点击后无响应的假功能。

## 五、能力边界（不能按已实现验收）

| 能力 | 当前可验收内容 | 仍受限或未接入内容 |
| --- | --- | --- |
| 创建与目标范围 | 快速/完整任务复用 Pipeline，单个目标字符串、任务类型、授权确认/范围、执行确认策略 | 不支持独立多目标集合向导、负责人分配、计划时间和前端并发配置；快速创建会请求启动，完整创建保留待启动 |
| 六阶段工作流 | 六阶段 UI 映射后端 `scan/analyze/generate/execute`；同任务上下文、失败/取消展示 | 不新增通用暂停/恢复/手动重试；补充扫描或重复执行的自动挂接不能假定已支持 |
| AI 与分析 | 任务级问答、来源引用、结构化分析、分析候选加入预案 | 模型配置和回答质量需实际验证；不提供逐条 AI 风险到证据的完整映射或跨任务推理 |
| 预案与授权 | 新式草稿版本、编辑、提审、管理员批准快照、授权确认一致性校验 | 授权范围文本不是完整网络/路径强制约束；旧独立执行入口并未整体改造成同一审批系统，参数约束仍需核对既有引擎策略 |
| 执行与证据 | 任务级只读监控、Run/目标/所有者关联、尝试及证据来源核对、常见敏感内容屏蔽 | `linked/verified` 只证明来源关联，不证明漏洞成立；未提供全平台原始输出脱敏、不可篡改证据库或独立漏洞裁决流程 |
| 结果与报告 | 未复核候选、存储教学分、冻结展示快照、独立报告审阅、JSON/HTML 导出 | 报告仍为草稿，审阅不等于正式发布、风险评级或漏洞验证；新式报告不支持 PDF/Word，不保证包含完整原始证据和全部历史 |
| 资源与全局入口 | 工具注册目录、现有知识/预案/样本入口、任务分析和报告索引 | 工具目录不等于安装健康检查；漏洞知识未接入 CVE 数据源；全局搜索、通知中心仍禁用，不支持跨任务风险排名 |
| 权限与性能 | 已覆盖路径的所有者/管理员隔离、索引分页、限长展示、离屏布局回归 | 不是全平台安全审计，不新增全平台即时令牌撤销；索引分页不代表数据库级性能优化，长期运行和大型历史库需实测 |

上述限制是本轮已知边界，不是验收失败后自动增加的新功能需求。需要扩大能力时应单独立项；本轮人工验收按当前真实行为判定，不把参考概念图或实施表中的目标状态当成现状。

## 六、自动化证据与人工边界

第 15 批永久回归位于 `backend/test/task-closed-loop.test.js`，覆盖全量迁移、真实 HTTP、JWT、RBAC、任务创建、快速/完整配置、预案提审/审批、批准快照、执行证据、结果报告、报告审阅、导出、跨账号隔离、同目标任务隔离、目标/所有者错配、过期来源指纹和审计日志。

```bash
JWT_SECRET=batch15-fixture-secret npm --prefix backend test
cmake -S . -B build -DBUILD_UI_CHECKS=ON
cmake --build build -j2
ctest --test-dir build -R 'ui-context-' --output-on-failure
git diff --check
```

测试 fixture 只写入内存数据库，通过回环 HTTP 验证真实路由和认证；扫描发现/分析由受控存储记录代替，审批后的执行入口注入 fixture 回调，不连接外部目标、不运行真实扫描/工具/模型。因此这不是真实引擎或前后端联合业务端到端验收。

第 16 批将任务上下文关键回归固化到 `frontend/test/batch16_context_checks.cpp`：回环 mock 检查七个工作区页签共享同一任务、AI 阶段一致、扫描范围隔离、准确打开报告、切换/返回清理、迟到列表与详情响应隔离、同一任务重开时的请求版本隔离，以及只读导航不发出写请求。CTest 注册 `ui-context-1`、`ui-context-1.25`、`ui-context-1.5` 三组离屏检查，无需 `/tmp` 源文件或真实后端。需要已安装 Qt5 Test 开发组件；普通发布构建默认 `BUILD_UI_CHECKS=OFF`，不要求该组件。

第 14/15 批临时视觉和闭环专项仍保留为历史辅助证据，并非所有临时检查都已迁移。新的永久 Qt 专项聚焦本批修复及任务上下文契约，不替代实际部署机的布局检查、模型调用或授权任务验收。Node 和 Qt 测试均可从仓库独立重跑，不修改正式业务数据库。

人工验收必须使用独立的测试账号和明确授权目标。最终验收结果填写回 `UI优化实施任务表.md` 第 10 节，不要把自动化通过项直接视为人工项目已完成；该节为目标清单，超出第五节已实现边界的条目应注明“部分支持/另行建设”，不能全部直接勾选。
