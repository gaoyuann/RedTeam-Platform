> **状态：** 本轮分批开发与隔离自动验证已收尾；已完成批次见第 11 节，最终手动验收待统一进行
> **编制日期：** 2026-10-10

## 1. 实施目标与边界

本轮工作不是单纯替换颜色、控件或截图式复刻，而是将现有界面调整为：

1. **任务驱动**：所有目标、扫描、分析、预案、执行、证据和报告均归属于一个正式测试任务。
2. **流程贯通**：形成“任务准备 → 扫描发现 → 智能分析 → 预案制定 → 执行验证 → 结果评估”的完整闭环。
3. **AI 协作**：AI 能理解当前任务上下文，生成可查看、修改、审核的结构化成果，不能绕过审批直接触发高风险执行。
4. **结果可信**：扫描事实、AI 候选风险、验证结果和正式结论必须分层展示并能追溯证据。
5. **视觉统一**：统一为浅色专业软件风格，支持窗口缩放、可伸缩工作区和一致的空/加载/失败状态。

### 1.1 本轮不做的事项

- 不以“逐像素复刻概念图”为目标；概念图中的示例数据不能直接进入正式界面。
- 不在未确认后端数据模型前伪造任务、漏洞、证据或审批状态。
- 不整体重写 Qt 前端；优先复用现有 `QMainWindow`、`QStackedWidget`、`QSplitter`、页面类和接口封装。
- 不将工具执行成功、端口开放或 AI 建议直接显示为“漏洞已验证”。

### 2.2 任务领域对象

| 对象 | 正确含义 | 前端需要展示的关键字段 | 不可混淆的对象 |
| --- | --- | --- | --- |
| `Task` | 一项完整、可审计的安全测试工作 | 名称、状态、类型、负责人、授权范围、时间、进度 | `Target`、`ScanJob` |
| `Target` | 被测 IP、域名、网段、URL 或资产集合 | 值、类型、备注、授权状态、关联服务 | `Task` |
| `ScanJob` | 一次具体扫描动作 | 工具、参数、状态、起止时间、原始输出、错误 | `Task`、`Finding` |
| `Finding` | 扫描发现的事实或待验证线索 | 来源工具、目标、服务、事实、原始证据 | AI 推断、正式漏洞 |
| `Analysis` | AI 或规则产生的结构化分析成果 | 依据、适用条件、候选风险、建议、引用知识 | `Finding`、验证结果 |
| `Plan` | 面向特定任务的执行预案 | 版本、步骤、输入、约束、停止条件、审批状态 | Playbook 模板 |
| `Execution` | 已审批预案的实际运行过程 | 队列、步骤、工具状态、日志、暂停/重试记录 | `Plan`、证据 |
| `Evidence` | 支撑结论的原始或整理后证据 | 来源、时间、原始输出、关联步骤、完整性 | AI 文本摘要 |
| `Report` | 可审核、可导出的最终成果 | 版本、结论、已验证项、未确认项、引用证据 | 执行日志 |

## 7. 状态、权限与数据真实性验收表

| 场景 | 必须展示 | 禁止行为 | 验收方式 |

| 执行失败/超时 | 失败原因、步骤、日志、重试/恢复操作 | 页面卡死或静默失败 | 中断工具或后端响应 |
| 已验证结果 | 关联预案、执行记录、证据和结论 | 只有 AI 文本而没有证据 | 从结果页追溯到原始输出 |
| 报告生成 | 版本、生成时间、审核状态、引用内容 | 把未确认候选风险写成已验证结论 | 导出报告并抽查引用 |

**接口与状态约定：**

| 接口 | 用途 / 限制 |
|---|---|
| `GET /api/pipelines/:id/plan` | 读取当前草稿与最近历史；没有草稿返回 `data: null`，不会自动建草稿 |
| `POST /api/pipelines/:id/plan` | 从来源预案建立任务草稿；仅待审批任务允许 |
| `PUT /api/pipelines/:id/plan` | 保存编辑；必须提交当前 `revision`，仅编辑状态允许 |
| `POST /api/pipelines/:id/plan/suggestions` | 加入真实分析候选；校验类别、索引、来源内容及版本 |

| `POST /api/pipelines/:id/plan/reject` | 管理员驳回已提审版本；原因不能为空 |
| `POST /api/pipelines/:id/plan/approve` | 管理员批准当前已提审版本并恢复任务执行；创建独立快照，不直接执行临时 AI 文本 |
