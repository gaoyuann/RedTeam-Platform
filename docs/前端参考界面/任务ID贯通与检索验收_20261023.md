## 范围与视觉目标

依据用户批准的 [设计方案](../任务编号与检索设计方案.md)，复用当前主界面与 `Theme`、`UiUtil` 风格。本批只贯通任务身份、检索和相关反馈，保留 Qt Widgets/CMake、任务内部关联、权限、状态转换和扫描执行方式。原窗口的“任务名称 → 测试目标 → 任务类型”顺序保持。

视觉变化：名称列使用两行展示名称和任务ID；创建成功使用浅色通知条，提供“复制ID”“打开任务”；详情公共顶部显示任务ID及轻量复制操作，切换阶段仍可见。独立验证窗口和相关页面显示所属任务ID，报告编号继续单独保留。未添加创建输入或高级设置。

## 功能验收

- 发号使用上海日期和每日至少六位序号；独立数据库连接并发写入不重号，跨日、重启、删除和事务失败保留正确高水位；数据库阻止重复编号和更新已有编号，包括仅改变字母大小写。
- 旧任务按原创建时间稳定补号；内部 ID、状态、时间与关联步骤不变；迁移重复检查保持编号；异常历史时间回滚。
- 同一创建请求得到原任务；内容变化返回冲突；删除原任务后不能用旧请求重新创建；关联重试产生新编号，同一重试请求复用该编号。
- 精确检索包含全部可见状态，兼容原内部ID；普通用户查他人和未知ID得到相同不可访问结果；管理员遵循既有权限。
- 搜索框向后端发起检索，支持大小写、复制、回车打开及清空恢复；旧响应不能覆盖新查询；任务切换和详情失败立即清除旧编号。
- 新报告 JSON、HTML、DOCX 和 PDF 均含冻结任务ID；历史报告补号后存储内容保持不变，不把新元数据冒充历史内容。

## 追加复查

按用户要求复查后修复三类问题：

1. 原列表沿用的会话校验弱于新查找接口。现在由任务路由集中核对当前账号有效性及角色；账号停用、管理员降权后，旧令牌不能继续通过其他任务入口访问或创建任务。
2. 搜索从前端转到后端后，中文类型名会漏匹配，后端匹配的类型代码还可能被客户端再次过滤；搜索词中的加号也可能被解释为空格。已补齐类型显示名匹配、搜索已处理标志和字面值编码。
3. 旧后端不支持创建请求幂等，原界面却仍提供重试入口。现按后端协议版本显示该操作；未确认支持或后端撤回支持时只提示刷新列表核对，同时阻止隐藏按钮被程序调用后发送重放请求。

本次只修改任务路由、`FlowPage`、相关回归及本说明，没有修改发号迁移或运行数据。回归先复现原有失败，再核对修复结果；未删除或放宽原断言。两个既有越权测试补齐真实测试账号，继续严格核对有效账号越权返回403；失效会话单独核对返回401。
