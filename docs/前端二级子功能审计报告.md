# 前端二级子功能审计报告

> 审计时间：2026-07-09
> 审计范围：Qt5/C++ 前端 7 个一级模块 vs 28 个二级子功能
> 目的：识别前端应有但未呈现的二级子功能，为后续补全提供依据

---

## 一、审计方法

逐页阅读 `frontend/src/pages/*.cpp` 源码，对照 `docs/系统重构需求与功能模块分析.md` 中的 28 个二级子功能表，判定每个子功能在前端是否有对应的 UI 呈现。

判定标准：
- ✅ 有对应 UI — 前端有专门的交互区域展示该子功能
- ⚠️ 部分覆盖 — 有相关 UI 但不完整或不专属于该子功能
- ❌ 完全缺失 — 前端无任何 UI 对应该子功能

---

## 二、逐模块审计

### 模块1：渗透测试资源部署配置 — `DeployConfigPage`

**当前页面内容：**
- 后端连接检测按钮
- 容器镜像状态表（镜像名/标签/大小）
- 工具列表表（工具ID/镜像/类型）
- 系统配置表（配置项/值/类别，只读）

| # | 二级子功能 | 状态 | 当前前端呈现 | 缺失说明 |
|---|-----------|:----:|-------------|---------|
| 1 | HEXSTRIKE部署配置（即平台部署配置） | ❌ | 无 | HexStrike 即本平台前身，此处指对平台自身的配置：启停控制、监听端口、审计策略开关、CORS/安全策略、版本信息 |
| 2 | 沙箱运行环境部署配置 | ❌ | 无 | 应展示沙箱开关、沙箱类型选择（none/docker/podman）、沙箱镜像 |
| 3 | 大语言模型LLM部署配置 | ⚠️ | 混在系统配置表中 | LLM 的 API Key、模型名、Base URL 散在 system_config 大表里，无专用配置区域，无法直观修改和测试连接 |
| 4 | 测试靶场部署配置 | ❌ | 无 | 应展示靶场列表（名称/IP/端口/状态）、添加/启停靶场 |
| 5 | 测试工具部署配置 | ✅ | 工具列表表 + 容器镜像状态表 | 工具和容器状态已覆盖 |

**小结：5 个子功能，✅1 / ⚠️1 / ❌3。模块1 是偷懒最严重的模块之一。**

### 模块4：脆弱性扫描 — `ScanPage`

**当前页面内容：**
- 创建扫描（目标输入 + 扫描类型选择 + 创建按钮）
- 扫描任务列表（任务ID/目标/类型/状态/时间）
- 扫描结果表（类型/严重度/数据/工具）
- 推荐 Playbook 表（名称/难度/基线组/匹配原因）
- AI 生成 Playbook 按钮

| # | 二级子功能 | 状态 | 当前前端呈现 | 缺失说明 |
|---|-----------|:----:|-------------|---------|
| 1 | 系统漏洞扫描(nuclei等) | ✅ | scan_type=vuln_scan | |
| 2 | Web漏洞扫描(sqlmap等) | ✅ | scan_type=web_scan | |
| 3 | 端口扫描(nmap) | ✅ | scan_type=port_scan | |
| 4 | 弱口令扫描(hydra) | ✅ | scan_type=brute_force | |

**补充缺失（非子功能表项，但影响体验）：**
- ❌ 扫描参数配置 — 无端口范围、线程数、超时等参数输入
- ❌ 扫描实时日志 — 无 WebSocket/轮询实时输出展示
- ❌ 自动执行扫描 — 创建任务后不会自动调工具执行，需手动 POST results

**小结：4 个子功能，✅4。模块4 是覆盖最好的模块。**

### 模块5：漏洞攻击测试 — `ExecutionPage`

**当前页面内容：**
- 选择 Playbook + 输入目标 + 执行按钮
- 执行记录列表（RunID/Playbook/目标/状态/时间）
- 步骤执行详情表（步骤/工具/参数/成功/输出摘要）

| # | 二级子功能 | 状态 | 当前前端呈现 | 缺失说明 |
|---|-----------|:----:|-------------|---------|
| 1 | 数据抵近窃取攻击测试 | ⚠️ | 通用执行入口 | 无按攻击类型分类的快捷入口，需从 Playbook 下拉框手动查找 |
| 2 | 信息篡改欺骗攻击测试 | ⚠️ | 通用执行入口 | 同上，DVWA 文件篡改等剧本需手动找 |
| 3 | 关键设备夺控攻击测试 | ⚠️ | 通用执行入口 | 同上，WinRM/SSH 夺控剧本需手动找 |

**补充缺失：**
- ❌ 攻击类型分类 — 无 Tab/分组按"数据窃取/信息篡改/设备夺控"分类展示
- ❌ evidence 证据展示 — 步骤详情里无 evidence_records（工具输出原文、MITRE 命中、修复建议）
- ❌ 攻击结果可视化 — 无攻击路径/影响范围的可视化

**小结：3 个子功能，⚠️3。执行引擎做了，但 3 个子功能没有分类入口，evidence 完全缺失。**

## 五、额外发现（非子功能表项，但影响体验）

| 问题 | 所属页面 | 说明 |
|------|---------|------|
| 扫描无参数配置 | ScanPage | 创建扫描时无法设置端口范围、线程数、超时等参数 |
| 扫描无实时日志 | ScanPage | 执行扫描后无法看到工具实时输出，需 WebSocket 或轮询 |
| 扫描无自动执行 | ScanPage | 创建 scan_task 后不会自动调工具执行并写入 results |
| 系统配置只读 | DeployConfigPage / SystemPage | 配置表只能看不能改，应支持双击编辑 |
| 班级管理只读 | SystemPage | 班级列表只能看，无添加/编辑/删除 |
| Playbook 无新建 | PlaybookPage | 只能浏览和删除，无法手动新建 Playbook |
| 报告无导出 | EvaluatePage | 测试报告只能在线查看，无 PDF/Word 导出 |

## 六、建议补全顺序

```
第一批（P0，4项）：补全后用户能完成核心操作闭环
  └─ LLM配置 → 靶场配置 → evidence展示(模块5) → evidence面板(模块6)

第二批（P1，7项）：补全后 7 个模块都有实质内容
  └─ HEXSTRIKE配置 → 沙箱配置 → 脚本编辑 → 快捷执行
  └─ 攻击分类 → 任务管理 → 知识图谱

第三批（P2 + 额外发现）：打磨体验
  └─ 权限管理 → 加密锁 → 网络拓扑
  └─ 扫描参数 → 实时日志 → 配置可编辑 → 班级CRUD → 报告导出
```
