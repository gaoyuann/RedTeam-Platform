# PR 总结汇报

> 分支：`feature/exec-abort-cortex-refactor`
> 日期：2026-09-30

---

## 一、本次 PR 功能性总结

本次 PR 围绕**漏洞攻击测试执行环节**做了一次集中增强，分前端和后端两部分。核心目标是：让攻击执行过程**可中止、可干预、可看清**。

### 1. 后端：执行控制与 ReAct 引擎增强

| 功能 | 说明 |
|------|------|
| **执行中止** | 新增 `POST /api/runs/:runId/abort` 接口，操作员可随时手动中止运行中的攻击执行；引擎循环每步检查中止信号，安全退出 |
| **失败重试** | 单个步骤失败后可重试，最多 2 次，避免因偶发故障导致整条攻击链中断 |
| **Pivot 攻击方向切换** | ReAct 引擎新增 `pivot` 动作（动作列表 5→6），某条攻击路径失败时自动切换方向，而非直接终止 |
| **强制规则** | ReAct 规则 2/3/5/6 由"建议"升级为"强制"，禁止用 `continue` 跳过关键检查 |
| **动态探索模式** | 执行前半程采用探索模式（鼓励基于证据插入补充步骤），后半程切换为自动驾驶（专注完成预案） |
| **Playbook 主线放宽** | 允许 AI 基于实际证据插入补充侦察/验证步骤，不再死板按预设脚本推进 |
| **执行状态准确判定** | 追踪非可选步骤的失败情况，最终状态据此判定 `COMPLETED` / `FAILED` |
| **引擎类型兼容** | `playbook` 作为 `mechanical` 的遗留别名兼容处理，并通过 migration 017 自动转换存量数据 |

### 2. 前端：执行界面重构

| 功能 | 说明 |
|------|------|
| **CortexPanel 结构化时间线** | 从原来的聊天式面板重构为按步骤分组的结构化决策时间线，更清晰地展示每一步的推理与执行 |
| **长文本展开/折叠** | Thought、Payload 等长文本默认折叠，点击展开，减少界面噪音 |
| **引擎标签颜色化** | mechanical 引擎显示琥珀色，react 引擎显示绿色，一眼区分执行模式 |
| **状态点颜色** | 步骤状态点按运行/完成/失败/中止显示不同颜色 |
| **停止执行按钮** | 执行页面新增 🛑 停止按钮，轮询时实时更新按钮状态 |
| **步骤来源标注** | 步骤表新增"来源"列，区分"预案"步骤与"AI 动态插入"步骤，便于审查 AI 的自主决策 |
| **冗余面板清理** | 移除 FlowPage 中冗余的 AI 推理面板，统一由 CortexPanel 承担展示 |
| **步骤指示器优化** | StepIndicator 节点连接线改为 chevron 箭头，执行流向更直观 |

### 3. 改动规模

共修改 13 个文件，新增 478 行，删除 432 行。涉及后端执行引擎、ReAct 引擎、路由层，以及前端 CortexPanel、ExecutionPage、FlowPage、StepIndicator 等核心执行链路页面。
