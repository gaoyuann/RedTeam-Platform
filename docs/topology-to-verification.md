# 网段发现后如何选择目标测试

网段扫描的输出是主机、服务、入口和扫描记录。主机在线、端口开放、扫描器执行成功都不是漏洞验证结论；扫描结果中的“漏洞”分类仍是候选，需要后续执行证据。

## 默认先探测，再从拓扑发起扫描

新建网络任务默认记录 `config.task_mode=discovery`。启动后仅复用现有 Nmap 端口、服务、路径与局域网主机发现，不进入 ReAct 漏洞扫描、模型分析、预案生成或执行验证。普通创建保留“创建后启动”的交互，快速创建直接开始探测，不增加探测／扫描模式选择。

采集结束以 `status=completed` 结束探测任务，`result.next_action=select_topology_target` 表示后续应从拓扑选目标，不表示漏洞检查完成。`result.completeness` 和原始扫描记录保留完整性、失败和取消信息。Qt 显示“探测结束 · 请在拓扑选择目标”，打开资产与拓扑页签；此探测任务的分析、预案、执行和评估页签禁用。存在未完成项时可查看已取得的资产，完全失败时不继续后续扫描。

选择具体主机或已识别的 Web 服务，点击或右键选择“对所选目标发起扫描”，确认后创建 `task_mode=assessment` 的独立任务。扫描、分析和后续人工验证全部使用所选目标。源码／程序任务和没有 `task_mode` 的历史任务保持原执行方式。

节点详情的“关联扫描”每五秒刷新，也可手动刷新，显示最近 50 项可访问关联任务的状态及漏洞候选数量。双击进入对应任务查看进度、证据和验证记录；子任务提供“返回来源拓扑”。子任务结果不会混入原探测任务的漏洞和报告统计。

### 创建与关联接口

节点扫描复用 `POST /api/pipelines` 和现有 `request_id` 幂等协议，Qt 自动发送 `config.task_mode=assessment`、所选单主机／服务范围与确认记录，增加顶层 `topology_source={pipeline_id,node_id}`。独立拓扑使用 `{scan_task_id,node_id}`，两种来源只能指定一种。

服务端从可访问的存储结果重新投影节点，核对主机、开放 Web 服务的协议与端口或已记录的入口；不能用客户端编辑的地址、手工节点或伪造来源替代实测证据。目标表单锁定所选地址，范围不得扩展到其他主机。来源不继承父任务凭据、方案或执行对象。同网段邻居可以在明确确认其目标范围后创建新任务，不能扩大原任务范围。

首次输入的 HTTP/HTTPS 地址会以 `state=declared` 的应用入口保留完整协议、域名、端口、路径和查询参数，不代表应用已响应。域名入口只有在同次主机探测记录明确关联到该 IP 时才附到 IP 节点；不在绘图时查询 DNS 或猜测别名。节点优先选择原应用入口，同协议端口已有应用入口时不再默认替换成 IP 根路径。任务内拓扑、独立拓扑和节点创建校验使用相同规则；修改为没有记录的域名、路径或端口会被拒绝。客户端使用完整编码 URL 传递目标，避免编码空格等字符被显示格式改写。

资产探测和节点扫描的启动均检查目标是否存在活动任务或停止未确认的工具。冲突返回 409，任务保持待启动，不派发工具；停止得到确认后可重新启动，不同目标仍可正常探测。

核实后的来源保存到子任务 `config.topology_source`，配置更新保留此字段；它不同于记录 HTTP 请求来源的 `topology_origin`。`GET /api/topology/linked-tasks?pipeline_id=...&node_id=...` 查询关联任务，独立拓扑使用 `scan_task_id` 参数，同时校验来源与子任务权限。普通集成调用可显式创建 `task_mode=assessment`，Qt 开局表单不提供这个模式选择。

没有新增数据库迁移，历史数据与旧节点补充探测接口继续兼容。上线需同时更新后端和 Qt 客户端，真实工具和网络路径仍需在授权靶场联调。

## 单 IP 测试附带同网段发现

单 IPv4 主机或使用 IPv4 地址的 HTTP/TCP 入口测试，在原有端口与服务扫描之后，附带一次仅供拓扑使用的主机存活发现。后端根据扫描端的实际网卡、掩码和最长匹配路由选择目标所在的直连网段，不猜测 `/24`。自动发现最多覆盖 4096 个地址；目标需要经过网关、缺少有效网络信息或网段过大时跳过，并在扫描记录中说明原因。

附带发现使用 Nmap `-sn`，不对邻居做端口、服务或漏洞扫描。邻居以 `lan_host_discovery` 保存，用于拓扑节点和同网段归属关系；不加入目标画像、攻击分析或任务资产与检查覆盖统计，也不会排入后续扫描队列。发现证据与网段记录标记为 `topology_only`。任务原有测试范围保持不变，范围外邻居不能在原任务内发起节点扫描；需要测试时，按下文流程另建并确认授权的新任务。

发现继续遵守任务排除项：IP 和 CIDR 直接排除，URL/TCP 入口排除项按整台主机跳过。发现失败或超时会保留已响应的邻居及未完成提示，不影响原目标扫描结果；操作员取消仍会中止当前工具。已有历史任务和扫描记录继续可读，无需数据迁移。

## 已有扫描任务

网段任务已经产生漏洞候选时，可直接进入同一任务的“扫描发现”，选择“漏洞”分类，双击一条候选或勾选多条后打开验证窗口。选择或生成方案、补齐实际入口与判据、核对所需载荷后，确认执行，再检查证据并复核结论。无需为了进入验证再扫一次整个网段。

## 从拓扑节点继续

在“资产与拓扑”点击具体主机，画布上方会显示目标选择和后续操作。

| 当前情况 | 操作 | 后续行为 |
| --- | --- | --- |
| 节点已有本任务漏洞 | “验证此节点漏洞（数量）” | 打开该节点漏洞的方案、载荷、尝试和证据窗口；不会自动发起攻击 |
| 已识别到开放的 HTTP/HTTPS 服务 | 在下拉框选择具体服务，点击“对所选目标发起扫描” | 显示已填写目标的任务表单；确认授权后创建并启动新的服务和漏洞检查任务 |
| 仅发现主机、没有明确 Web 服务 | 下拉框选择主机端口与服务检查，再建立任务 | 先识别主机服务，再按实际识别结果安排适用检查；不猜测 Web 端口 |
| 选择的是逻辑网段节点或连线 | 改选具体主机 | 不将逻辑交换机、网段归属或连线当作单个攻击对象 |

独立“资产与拓扑”页面与任务内拓扑都支持对所选目标建立新任务。独立拓扑没有本任务的漏洞归属时，漏洞验证按钮说明需要先建立任务；历史归档或手工节点不自动获得执行权限，新任务仍需重新核对目标和授权。

目标下拉框来自所选节点的主机地址、已记录的同主机 Web 入口，以及服务清单中明确识别为开放 HTTP/HTTPS 的 TCP 服务。不根据端口号单独猜测协议，关闭或未知状态的服务不自动包装成已发现的 Web 服务，也不会把另一个主机的入口混到当前节点。

新建任务的范围默认是所选主机或具体服务，不复制整个网段作为攻击目标。点击取消不创建任务；确认后开始的是服务与漏洞扫描，攻击验证仍在候选漏洞的验证窗口中明确确认。扫描完成后直接进入新任务工作台查看发现。原网段任务和拓扑记录继续保留。

例如发现 `192.168.1.113` 的 `8089/tcp` 被识别为 HTTP，可选择 `http://192.168.1.113:8089/` 建立测试任务；如果该节点已经有漏洞候选，优先直接打开该节点的漏洞验证，避免无意义重复扫描。

## 验证范围

Qt 界面回归覆盖节点／服务选择、取消创建、确认后只创建并启动一个服务范围内任务、进入新工作台、节点已有漏洞进入 F08、跨任务迟到事件被忽略、打开验证窗口不执行攻击，以及独立拓扑和无漏洞／逻辑节点的按钮状态。测试使用本机 HTTP 服务和受控数据，不代表真实靶场已完成漏洞攻击或已部署此界面。
