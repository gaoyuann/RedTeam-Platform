# 五项核心演示实施核查

本轮范围：加密狗、拓扑扫描、逐漏洞测试、载荷生成与复用、结果统计。靶场与被测软件各自走独立测试任务；暂不实现“将软件部署进靶场环境一起测”。下面的代码能力不代表现场验收通过。

## 目标清单与环境边界

本次演示靶场按用户确认的 **DVWA、Pikachu、SQLi-Labs** 推进。被测软件沿用已有部署说明中的 vulnerable-webapp、vuln-demo、exploit_me，具体版本和入口在现场核验。

仓库 `containers/labs/` 中的 DVWA、Juice Shop、WebGoat 只是可用容器配置，不代表现场部署清单；本次不新增部署 Juice Shop 或 WebGoat。用户确认的对象清单也不替代实时连通性与版本核验。

现场开始前须核实实际靶场、软件名称、版本与入口。源码地址和程序运行入口分开填写；不把源码目录服务器当作被测程序。HTTP 与 TCP 程序沿用现有运行入口模式。纯本地内存缺陷若没有进程观测接口，不能以静态告警或网络连通代替动态攻击效果。

## 本轮改动

1. 逐漏洞窗口的载荷准备请求由 15 秒延长到 130 秒，与后端模型默认 120 秒预算及独立载荷窗口保持一致。避免模型正常生成期间客户端提前报超时。等待时说明正在查库、必要时生成并校验，不展示虚构进度。
2. 载荷候选及来源提示按当前验证项的 `created_here` 显示：本次生成橙色，已有载荷蓝色。复用时保留原始 AI 来源；颜色不代表攻击成功，也不代替手动绑定。
3. 逐漏洞统计改为五张卡片和测试进度。未知值显示“—”，未登记的基线不显示零。数量来自任务级统计，与当前筛选/分页无关，尝试次数不当作漏洞数量。任务切换时清空旧统计。
4. 增加跨验证项复用回归、颜色回归和超过 15 秒的慢载荷响应回归；保留原有版本、取消、人工复核与旧流程测试。
5. 扩展源码辅助与程序任务的回归：从发现选择继续走方案保存、真实本机 HTTP 请求、证据读取、人工复核与汇总，验证普通响应成功不会自动变成漏洞成立。

## 现场演示顺序

1. 核验加密狗，扫描真实拓扑并选择目标。
2. 为靶场或软件新建逐漏洞任务，扫描后查看候选列表及覆盖错误。
3. 打开一条漏洞，选择适用方案；检查目标、前提、正常对照、输入与成功判据。
4. 展示已有载荷，或明确触发生成；预览后绑定到步骤。
5. 确认测试，展示实际证据；把工具状态与漏洞结论分开展示，必要时人工复核。
6. 新验证项复用已入库载荷，显示蓝色“已有载荷”且保留 AI 来源。
7. 按顺序测试其他就绪项，结束本轮并汇总。多次尝试不得增加已测试漏洞条目数。

涉及目标状态变化时，使用预先验证过的环境恢复方法。当前验证流程没有通用快照恢复闭环；启动/停止容器不等于恢复干净基线。调用停止状态未确认时不得开始下一轮。
