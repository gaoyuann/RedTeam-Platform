# F09 统一统计与冻结报告

## 使用流程

在任务的“结果与报告 → 统一统计”中查看原始候选记录、已归并实例、未归并记录、已执行验证实例和验证成立实例。

1. 扫描后点击“同步漏洞实例”。同步只建立本任务内的映射，不执行扫描、验证或修改原始发现。
2. 需要比例时，点击“导入基准 JSON”。服务端先校验，再预览资产和漏洞数量，经确认保存并启用不可变版本。
3. 点击验证结论条形图筛选实例，或通过严重性筛选。点击检查状态图查看对应检查项。点击实例查看原始记录、计划版本、验证尝试、判断及证据 ID。
4. 任务、关联扫描和验证均已停止时可生成报告；没有主执行 Run 的扫描任务也支持。选择报告后查看攻击测试简报，可导出 DOCX、PDF、HTML，默认 DOCX；JSON 单独保留完整冻结快照供查阅详细材料。所有格式均使用已保存数据。
5. 选择 DOCX 或 PDF 后可点击“在 WPS 中打开”。客户端每次下载所选报告到独立本机缓存文件，再启动 WPS；未安装 WPS 或启动失败时提示文件位置，可手动打开。HTML/JSON 使用“导出报告”保存。

扫描严重性只是工具标签；工具成功、完成步骤数和历史教学得分不等于漏洞成立。原有候选摘要是限量预览，新增统计以全量数据计算。

## 统计契约

结果新增 `statistics.schema_version=1`，旧 `finding_count` 的含义不变。

- `findings`：原始候选记录、已归并实例、已映射记录、未归并记录、完整性和是否待同步。
- `verifications`：实例结论分布、已执行及成立实例数、尝试总数、实际启动/未启动/启动未知次数，以及未归并记录的验证次数。
- `execution`：主执行与来源可靠的 F08 验证 Run 的步骤记录数、调用记录数；不计作漏洞数。
- `checks`：按检查项计状态；扫描工具调用单独计状态、超时、中止和原因未知数量，不把一次工具超时重复加入检查项状态。
- `assets`：观测数量及状态；基准资产至少一项适用安全检查完整完成时计入覆盖。端口识别、Web 入口探测不计作安全检查覆盖。
- `baseline`：当前基准版本、匹配关系、发现率与成立数量。每个基准漏洞最多匹配计数一次。
- `source_fingerprint`：来源版本。任务、发现、映射、覆盖、执行、判断或基准变化时失效；生成报告、分页或写入操作遇到旧指纹返回 409。

比例字段统一返回 `numerator/denominator/value/reason`。清单未知或不完整时 `denominator/value=null`，零分母时 `value=null` 且原因为“不适用”。未归并记录不计入实例数，因此存在未归并记录时实例数不是已知的最终漏洞总量。

同一次尝试人工判断优先；同一原始发现采用最近尝试，待判定的新尝试不沿用旧结论。实例下明确结论相互矛盾时显示冲突；待定和证据不足不作为否定结论。历史成立另保留。成立必须有可靠实际调用和证据归属、尝试完成并确认停止；失败、中止或停止未知不计成立。

启动依据是 F08 持久化的 `finding_verification.tool_started`，同时校验任务、原始发现、验证项、尝试、计划版本与指纹、Run 所有者/目标以及执行调用归属。明确预检失败且无调用证据计为未启动；运行中尚未落证据或旧记录缺少依据时计未知。

## 保守归并 v1

实例表和映射表由显式同步写入，读取不写数据库。稳定 ID 来自任务、规则版本和规范化身份。事务及唯一约束保证重复同步不重复建档。

- Web：工具命名空间、规则/模板/CVE 标识、URL、明确请求方法、参数名及位置。
- 网络服务：工具命名空间、规则标识、主机、端口和 TCP/UDP 协议。
- 源码：工具命名空间、规则标识、明确目标、源码版本、文件及行号；目标来自发现的 `target`，基准使用所引用资产的目标，避免不同目标上同名文件误合并。

没有跨工具规则对照表，因此不同工具不合并。缺少必要字段不推断；不使用标题相似度或 AI。Web v1 不归并含查询字符串、认证信息或片段的 URL，参数名和位置必须同时是有效字符串或同时缺省，格式异常不视为缺省。归并前重新检查发现位置是否在任务范围内；范围外记录保留在原始记录中，不形成范围内实例。旧工具输出缺少方法、规则或源码版本时会保留为未归并记录，这是保守边界，不表示没有发现。

原始记录 ID 和 F08 引用均不变；同步不会自动执行验证，也不回填或改写旧报告。

## 基准 JSON

UI 文件上限为 96 KiB，以适配既有 HTTP JSON 请求体限制。只允许声明字段，不接收密码、Cookie、令牌或认证头。示例：

```json
{
  "schema_version": 1,
  "environment_id": "lab-demo",
  "environment_version": "2026-10-20-v1",
  "assets_complete": true,
  "vulnerabilities_complete": true,
  "assets": [{"id": "web-1", "target": "http://192.0.2.2/"}],
  "vulnerabilities": [{
    "id": "known-1",
    "asset_id": "web-1",
    "source_tool": "nuclei",
    "location": {
      "rule_id": "fixture-template",
      "url": "http://192.0.2.2/login",
      "method": "GET"
    }
  }]
}
```

示例仅表示数据契约，不授权访问该地址。资产须在任务范围内，漏洞位置须同时属于任务与所引用资产。标识、规范化资产位置和漏洞匹配身份不能重复（默认端口、URL 大小写等别名不能重复计数）。基准位置按 Web／服务／源码类型校验字段和类型，拒绝嵌套对象及其他类型的无关字段；UDP 位置只能匹配主机／网段范围，不匹配 TCP 专用范围。若任务有 `environment_ref`，必须与环境 ID 一致；首次导入绑定环境 ID/版本，同一任务不能切换环境版本，应为新环境创建新任务。

若任务在开始前改变环境引用或范围，原基准不再适用时比例返回未知及原因，不继续使用旧分母。

同环境下可修订清单，每次保存新不可变版本。规范化内容相同则复用版本；再次导入已有内容可重新启用该版本。查询返回版本、导入人、时间和当前启用标记。

## API

均位于 `/api/pipelines/:id/results`，仅任务所有者和管理员可访问。

| 方法与路径 | 请求及行为 |
| --- | --- |
| GET `/` | 旧快照兼容，增加统一统计、实例、覆盖、基准和验证尝试 |
| POST `/instances/sync` | `{source_fingerprint}`；原子校验并同步映射 |
| GET `/instances` | `source_fingerprint`、`conclusion`、`severity`、`after`、`limit`；默认 100，最多 500 |
| GET `/instances/:instanceId` | 实例、原始记录和尝试/证据引用；支持来源指纹校验 |
| GET `/baselines` | 本任务基准版本及启用状态 |
| POST `/baselines` | `{source_fingerprint,content,preview?}`；`preview:true` 只校验，不保存 |
| POST `/reports` | `{source_fingerprint,run_id?,title?}`；无主 Run 时省略或传 null |
| GET `/reports/:reportId` | 读取冻结快照，兼容历史版本 |
| GET `/reports/:reportId/export` | `format=json|html|pdf|docx`；导出冻结快照，省略格式仍默认 JSON |

初次实例查询可不传指纹，以响应取得版本；后续分页必须继续使用该版本，Qt 已执行这一约束。不存在或不属于任务的实例返回 404；旧指纹、未确认停止或环境版本冲突返回 409；格式与范围错误返回 400。

报告使用 `task_trace_v2` / `schema_version=2`，新增明确任务外键，Run 可空。通用报告索引与鉴权支持该关联，旧编辑/删除/模板重导出接口不能修改 v2。相同任务、相同来源重复生成复用报告。v1 和旧报告继续读取，缺少 F09 字段显示历史未记录，不补算。

## 简明攻击测试报告与 WPS

默认 DOCX/PDF/HTML 与任务内报告详情共用简报，题为“任务攻击测试结果报告”，只含三部分：

1. **本次攻击测试概况**：任务、目标、环境/时间及简要扫描背景；分别说明实际开展的漏洞实例数、已启动尝试次数和效果目标数量。基准未知、缺少归并或旧记录不全时明确说明统计局限。
2. **逐漏洞攻击效果**：漏洞及位置、实施操作、预期效果、实际效果与关键证据、结果。相同漏洞和目标的重复尝试合并，显示最新保存结果与尝试次数；不同目标分别列出。每个已安排测试的条目均保留，不仅选取成功项或前若干项。
3. **攻击测试结论**：已经证明的具体效果、未达到的目标、证据不足及未开展原因。工具完成、HTTP 200、人工意见或历史成功不能代替本次效果结论，不从报告自动生成修复建议。

默认正文不再附全量扫描表、完整命令/输出、教学评分、MITRE 标签、修复建议或来源 JSON。少量漏洞通常为 1–2 页；条目较多按实际数量分页。关键观察按摘要显示，详细证据和完整记录保留在平台及 JSON 快照，不裁剪或改写已有报告内容。

漏洞数按已保存的实例映射去重；无法可靠归并的原始记录单独说明，不能当成已知的去重漏洞总量。实际开展以适用操作确有启动记录为依据，单纯页面访问不算其他攻击目标的开展。效果按“漏洞—对象—目标”的最新保存结果计数，与攻击漏洞数、尝试次数分开，避免一漏洞多目标或多次重试重复计数。v1 缺少历史时只说明已保存的记录范围；主 Run 有执行但无逐漏洞关联时不猜测攻击对象或效果。

历史报告的验证摘要同时读取全量扫描记录与候选预览，按尝试编号去重，不受 150 条候选预览限制；v2 完整尝试历史优先。未知目标占位值或缺少可靠目标标识时逐条列示，不把不同操作合为重试。已经执行操作但攻击适用性未知的历史记录显示未知，不能计为确定零次。漏洞名称兼容源码扫描的消息、Nuclei 名称及已保存规则标识。

报告保留实际测试地址、验证目标、判据版本、正确尝试编号和关键证据引用。历史 v1 使用保存的 `attempt_id`，v2 使用尝试记录编号；缺字段显示未记录，不从当前方案补齐。现有自动判据主要覆盖指定响应头、Cookie 属性和目录索引，不能据此宣称 SQL 注入、命令执行等其他效果成立。

证据引用区分“判定证据”和“观察/操作证据”。尚未形成判定证据时，仍保留已保存观察及操作对应的编号；观察证据不自动代表攻击目标达成。

快照导出服务只处理经过来源校验的保存内容，不查询当前执行或重新评分，也不在服务器 `data/reports/` 保存导出文件。没有主执行 Run 的扫描任务可正常导出，未保存逐漏洞攻击记录时明确说明。完整 JSON 保留全部已保存字段及扫描附录；旧的非快照报告继续使用原导出链路，既有存储报告不做迁移或重写。

任务报告读取接口对快照增加只读派生的 `presentation`：`{schema_version:1,title,sections}`。各节包含 `title`、`paragraphs` 和可选的 `headers/rows`，前端按纯文本显示，与 PDF/DOCX/HTML 共用同一内容。该字段由冻结内容生成，不修改来源指纹；旧响应缺少该字段时前端提示刷新或更新后端，不使用当前任务数据拼接历史报告。

通用入口 `/api/reports/:reportId/export` 对快照报告同样支持四种格式，省略格式仍默认 DOCX；两个入口沿用原有权限和来源校验。格式不支持返回 400，超出 16 MiB 返回 413；PDF 中文字体不可用或渲染失败明确返回错误，不生成截短或中文损坏的替代文件。导出请求审计只在文件生成成功后记录，不表示客户端已保存或 WPS 已打开。

PDF 完整嵌入项目自带的中文字体，避免字体子集缺字，并关闭会破坏文字复制映射的本地化替代字形。文件约增加至 6 MiB，仍执行 16 MiB 限额。此前已下载的缺字 PDF 需要从原报告重新导出；无需重新运行测试或生成新的来源快照。

前端下载超时为 30 秒，文件校验和原子保存成功后才启动 WPS。切换任务、所选报告或格式后，旧请求不能继续写文件或打开外部程序。WPS 文件保留于独立本机缓存，不复用可能被用户编辑的历史导出文件。

导出结果单独显示，包含失败原因或保存位置，可复制且不被任务状态轮询覆盖；开始新导出、切换报告、格式或任务时清除。超出 16 MiB、字体缺失和权限错误显示具体原因，异常响应正文不会作为报告保存。

## 验证与交付边界

新增隔离内存数据库测试覆盖全量计数、归并幂等、参数/版本差异、基准校验、比例未知、验证历史/冲突、伪造归属、停止条件、纯扫描报告、权限、分页及历史报告。

```sh
cd backend
npm test
```

Qt 沿用 Qt5 Widgets 与既有编译器，独立构建目录：

```sh
cmake -S . -B build-f09 -DBUILD_UI_CHECKS=ON
cmake --build build-f09 --parallel 4
ctest --test-dir build-f09 --output-on-failure
cmake -S frontend/tests/finding-verification -B build-f09/finding-verification
cmake --build build-f09/finding-verification --parallel 4
ctest --test-dir build-f09/finding-verification --output-on-failure
```

迁移 `035_task_statistics.js` 为加法迁移，开发验证仅运行隔离测试库。实际运行库迁移、远端部署和实设备验收需另行安排；未做实际扫描、攻击或环境恢复。补齐 PDF/DOCX 快照导出不新增数据库迁移，不改变报告生成条件。

回退时停用新增入口并保留加法表及已保存数据；不删除原始发现、基准或历史报告。运行中尚未持久化证据的启动情况、定位不足的旧发现、跨工具同义规则与大规模任务的聚合性能仍有明确限制。

## 二次审查回归

报告停止检查覆盖全部关联扫描和验证 Run，不受结果显示范围过滤影响；未停止、丢失关联、仍运行的检查项会阻止生成。无效证据归属的判断详情不再输出原始判断和证据 ID。统计列表读取失败后，同一来源指纹也可以刷新重试；任务来源读取失败时禁用统计区操作，恢复后重新读取。

任务已有实例、基准或冻结报告引用，或扫描发现已被实例引用时，旧删除接口返回 409 并说明保留来源，不触发数据库约束 500，也不级联删除证据。
