# 通用 ReAct 扫描调度纠正

## 使用行为

新建任务由后端为运行态配置写入 `scan_orchestrator: {version:1, mode:"react"}`。Web、综合、主机/网络目标不再需要选择“AI SQL 检测”。Qt 的完整配置与快速任务都使用同一个后端创建入口。保留人工确认门槛；扫描调度不会直接执行后续利用。

既有源码目录、CScan agent、source_assisted 或指定源码连接的任务保留专项流程。未带新调度标记的历史任务不重新解释；既有 react_sqli 任务保留其登录与结果行为。用户希望重测旧综合任务时，应创建新任务，不在历史证据上改写模式。

## 当前已接入能力和真实边界

| 能力 | 输入与行为 | 不代表什么 |
|---|---|---|
| port_scan | 授权主机/网段/端口的既有 nmap 服务观察 | 开端口不等于漏洞；不自动扩大邻接网络 |
| app_discovery | 既有受控 HTTP 探测与入口观察 | HTTP 可达不等于可利用 |
| web_scan | 既有 Nikto 检查，范围不支持时拒绝 | 每条输出不自动成为确认漏洞 |
| api_fuzz | 既有 Arjun/ffuf 参数与路径发现 | 零命中不能当安全结论 |
| web_parameter_scan | 从实际匿名页面发现 GET 表单，受限 SQL BEU 检测 | 不枚举业务数据，不自动登录，不支持动态令牌/POST/JS 执行 |

新调度目前支持匿名 HTTP 会话，能够处理不带 DVWA 标记的普通 HTML。`anonymousWebSession` 不携带浏览器 Cookie、不自动接受登录秘密、不设置靶场等级。新通用任务若提交 authentication 会明确拒绝，避免静默忽略。原 DVWA 登录仅供历史专用模式；通用表单登录、角色会话、Token、POST/JSON 参数检查和浏览器动态入口仍需要后续适配。

非 HTTP 服务会记录已识别端口和服务；尚未接入专项适配器时，在覆盖中标为 unsupported。当前未把 hydra、凭据提取、横向移动、漏洞利用或云平台工具直接暴露给扫描模型。此文档不宣称“所有靶场、所有漏洞类型均已支持”。统一默认调度和能力覆盖是两项不同交付。

## 调度与证据

`scanAgent.js` 根据当前 `task_checks` 的可派发记录构造候选，模型只能选择 check_id 并引用 source_record_id。模型不能生成命令、任意 URL、扩展参数或越过排除范围。服务端再次核对归属、状态、范围和能力，然后调用现有 executeScan。

每轮把检查状态、记录 ID/类型和覆盖缺口反馈给模型。观察到的新入口形成后续候选，模型选择实际改变执行顺序。模型失败、无效动作或停止未知时明确结束，不静默回落到固定扫描队列。

任务级过程保存在一个 `react_scan` 子记录中（scan_agent_step/scan_agent_summary）；实际检查各有独立 scan_task_id、tool_run_id 和证据。现有 results?view=scans 返回的过程区同时包含任务级 ReAct 与参数检查过程。摘要说明派发次数和覆盖状态，尚未检查和认证条件不足不隐去。

默认 24 轮决策、16 项检查、单模型 30 秒、任务调度总时限 10 分钟；工具沿用其有限超时。重试沿用新任务标识及幂等 request_id，新增 `/api/pipelines/:id/retry-scan`，旧 retry-web-scan 路由保留兼容。ReAct 子检查不能通过独立扫描重试入口脱离父任务重跑。

取消传递给模型和正在执行的子扫描，并等待工具收束；工具停止未知时禁止继续派发及同目标重试。重启不重放新调度任务，已有恢复逻辑将其审计子记录和受控检查标为中断，工具停止未知保持锁定。

## 结果可信度修正

Nikto OSVDB 路径去掉输出分隔用的末尾冒号；普通登录入口、Apache 默认文件及 X-XSS-Protection 缺失提示归入信息记录。历史库记录不回写。

扫描后分析明确要求本次 record ID 来源，风险项无有效 evidence_ids 则不收录；保留项标记 unverified。证据引用存在不等于模型语义必然正确：攻击面、策略及风险解释仍需审阅，不能当作检测或利用成功。

## 验证与部署

新增调度/API/匿名会话测试覆盖真实模型选择接口的受控夹具、取消、无效动作、来源和范围、工具停止未知、非 HTTP 未支持、父任务默认模式及重试幂等；不冒充真实靶场验收。旧源码任务回归保持。

本轮不启动真实扫描、不迁移业务库、不重启现有服务、不提交或部署。实际部署前需载入新后端与最新 Qt，并在明确目标范围内重新验收；不能将已有 DVWA 专用验收直接继承为通用引擎全部通过。

## 临时会话适配增量（2026-10-23）

通用 HTTP/HTTPS 任务启动时可选择匿名、Cookie 或 Bearer Token。API 的 `authentication` 为 `{type:"cookie"|"bearer",value:"本次临时值"}`，只允许任务所有者提供；任务创建/更新仍不接受认证值。凭据仅保存在进程内存，取消、扫描结束或超时清理，重启后不可恢复，重试须重新提供；配置、审计、模型上下文和结果不保存会话值。

会话绑定原始 HTTP/HTTPS 协议、主机、端口和应用路径。只向作用域内受控页面请求及 SQL 检测调用传递；外部跳转、父目录跳转、401/403、密码登录表单阻断检查。不会自动接受新 Cookie、猜测账号、续期 Token 或修改安全等级。状态仅表示使用了用户提供的会话，不保证角色已被应用正确授予。

当前携带会话的能力为 `web_parameter_scan`：受控页面发现及 GET 参数 BEU 检测；Cookie 和 Authorization 会传入实际工具请求。其他尚未适配的扫描工具在覆盖中标为 missing_condition，不匿名回退。匿名任务原有通用能力清单保持不变。工具进程参数中会包含临时会话，主机进程/容器管理权限须限于可信人员；诊断输出会整体隐藏 `--headers` 和 `--cookie` 参数。

前文“新任务提交 authentication 会拒绝”的行为已由本增量替代：格式或范围无效时拒绝，合法值则按上述受控适配执行。IP/主机名目标需先明确 HTTP/HTTPS 应用 URL 才能提供会话。通用表单自动登录、POST/JSON 参数检查和浏览器动态入口仍未完成，不应将本增量当作这些能力已交付。

## 审查问题修复（2026-10-23）

- 后续分析入口不再仅凭检查的 completed/partial 放行。HTTP 内建观察须有成功响应证据；GET SQL 检查须有确认启动次数及完整阳性/阴性报告；外部工具须有正常退出和停止确认。已派发检查存在不可用证据时，本轮保留结果但不自动进入分析/预案。`usable_checks` / `unusable_checks` 记录该判定，未派发/未支持仍保留覆盖缺口。
- 同目标执行锁沿用保守主机粒度，并增加 IPv4 CIDR 双向包含/重叠匹配；不同端口或路径不能绕过同资产锁。该判断不做 DNS 解析，不保证识别域名别名与 IP 的等价关系。
- created 阶段跨源码/运行态模式编辑会重新计算调度标记；源码模式去除 ReAct 标记，切回运行态重新选择默认调度。已启动任务仍冻结。启动接口和引擎同时拒绝矛盾模式，历史记录不会批量回写。
- AI 分析先归一化英文/驼峰/中文字段别名，再校验对象数组和本任务证据引用。非数组或无效条目返回可控错误；缺失字段、被剔除的无证据风险给出警告，不再悄悄清空。保留的风险仍为 unverified，引用存在不代表语义已证实。

## 统一能力判定与预算（2026-10-23）

能力目录和判定集中在 `scanCapabilityContract.js`。每次派发完成或中断都会保存 `scan_capability_assessment`，与子扫描 ID 关联，并进入结果过程区：

| 字段 | 含义 |
|---|---|
| observation_success | 取得成功 HTTP 响应、主机/端口或 API 观察；不等于漏洞存在 |
| detection_executed | 仅检测类能力使用；true 已确认启动，false 明确未启动，null 未知或不适用 |
| detection_complete | 检测类能力是否满足完整报告/停止条件；发现类能力为 null |
| operation_complete | 此能力全部必要步骤完成，供调度和覆盖判定使用 |
| coverage_incomplete / gaps | 本项不足及原因；不包含未派发能力，后者仍在 task_checks 中 |
| usable_for_analysis | 是否达到后续分析的证据门槛，不是“漏洞确认” |

端口/HTTP/API 属于观察能力，Nikto/GET SQL 属于检测能力。HTTP 内建观察不要求外部进程；API 发现要求 Arjun 与 ffuf 均完成，不能用单个成功掩盖另一个失败。外部检测要求实际启动、正常退出、停止确认及完整解析。SQL 要求子摘要完整且所有本次参数报告有效，不再以任一完整报告代表所有参数完成。无命中但完整结束与未执行/失败分开。停止未知优先，旧数据没有启动依据时保持 unknown。

全任务使用一个运行期预算对象，经调度器传到执行器及 Web 子调度，不写入客户端可任意扩大预算的参数：默认模型决策 24、检查派发 16、受控页面请求 60、工具调用尝试 24、SQL 尝试 5、单模型 30 秒、单工具最长 120 秒、总调度 10 分钟。子能力仍保留自身更小限制。所有计数按尝试扣除，不因启动失败或超时退还。实际工具启动/检测完成由证据另计，不能混用。

页面请求包括受控 fetch 和内建 target-request；工具尝试包括运行器调用（含内建请求预检）。SQL 同时占工具和 SQL 额度。sqlmap/Nikto/ffuf 等工具内部 HTTP 请求数不在平台页面计数中，不能把 60 页当作所有扫描网络包的硬上限。剩余总时长限制模型/工具超时，取消仍等待有界停止，不以预算耗尽代替停止确认。

摘要 `budget` 保存 limits、used、remaining、exhausted 和 elapsed_ms；Qt 显示各项使用/额度。预算对象仅存在当前进程，不在重启后恢复或重放；中断历史依旧显示未知。旧摘要没有预算字段时不虚构零消耗。

### 预算与证据边界修复

多维资源采用 `consumeMany` 一次预检、整体扣除：SQL 同时占用 SQL/工具额度，内建请求预检同时占用工具/页面额度。任一维不足时不扣其他维；真正派发后的失败不退费。超时计算先于运行记录创建，派发前预算拒绝不再产生“停止未确认”锁；已有外部运行记录若在派发前被预算拒绝，会标记明确未启动且停止确认。

父模型读取共享 remaining；子模型读取共享与局部剩余额度的较小值，不再用局部轮次数冒充任务剩余额度。

检测类完成要求明确的 parser_coverage_known=true。SQL 报告必须以 tool_run_id 与本次每个 sqlmap 运行一一对应；运行缺失、超时、重复报告、未知解析或摘要与运行数量矛盾时均不算完成。观察类能力保留自身协议语义，不机械要求 Nmap/内建 HTTP 具有相同解析字段。

## 第 1 批 POST／JSON 与认证请求适配

启动接口可额外提交 `post_requests`（最多 5 条，仅运行期内存，不进入任务配置）。Qt 的“本次 Web 会话”窗口提供可选 JSON 模板输入，支持匿名、Cookie 或 Bearer。每项示例：

```json
{
  "url": "http://127.0.0.1:18081/lookup-json",
  "encoding": "json",
  "fields": {"id": "1", "case": "negative"},
  "parameters": ["id"],
  "read_only_confirmed": true
}
```

该 URL 只是已授权本机验收示例，服务不会自动启动。实际使用须填写本任务范围内明确授权的查询端点。encoding 为 form 或 json；字段只支持非空短字符串的平面对象，拒绝凭据/动态令牌字段、嵌套对象、重复检测参数、未知属性和范围外 URL。声明只读是用户对目标行为的确认，软件无法仅凭 HTTP 方法证明服务端没有副作用。

POST 不从页面自动升级为可执行动作；必须由任务所有者在启动时提供完整模板。模板元数据标为 declared，仅保存 URL、方法、字段名和来源，不存请求体。模型只选择模板编号和已声明参数，不生成请求体。Cookie/Bearer 与 POST 请求分别校验作用域；预检遇 POST 跳转直接拒绝，不向新地址重放。取消、任务结束清除模板，重试重新输入。

SQL 工具沿用 BEU、level 1、risk 1、单线程、不跟随跳转；表单编码或 JSON 通过明确 POST body 和 Content-Type 发送。结果方法/参数位置为 POST/body，使用 web-post-sqli-v1，不再套用 GET 标签。判断报告时核对 POST 或 JSON 参数标记，不能把 GET 报告算作 POST 阳性。共享预算和能力完成契约不变。

此批尚不包含自动表单登录、令牌刷新、动态 CSRF、嵌套 JSON、上传、PUT/PATCH/DELETE 和浏览器动态入口。后续批次分别实现并另行受控验收，不能把本批成功推广为这些能力已支持。

### POST 模板边界补充

POST 模板 URL 必须是非空、明确的绝对 HTTP/HTTPS 字符串，拒绝空白、缺失、非字符串、相对地址、查询、片段和 URL 内凭据；校验发生在 URL 标准化之前，不自动补成 `/undefined` 或截断片段。

本次模板字段值及常见 URL/表单编码形式纳入运行期脱敏。响应反射出的链接若在路径或参数身份中包含受保护值，会被跳过，不持久化为可执行入口、不传给模型，更不会向替换后的虚构地址发请求。检测使用私有原始正文；生成的证据 ID、哈希及系统状态保留，避免普通值如 `1` 破坏证据归属。结束时释放模板副本和脱敏值集合。脱敏不回写历史记录。
