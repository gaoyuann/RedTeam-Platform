# 扫描驱动目标识别实施计划

## 目标

用户只提供目标地址和授权范围，不指定靶场名称。平台以扫描证据识别应用，匹配、预检和执行复用目标画像；认证信息由登录步骤生成，不要求提前提供 Cookie。

## 实施顺序

1. 修正工具级目标规范化：端口扫描使用主机和端口，HTTP 工具使用 URL；根据退出码、超时和语义错误记录真实状态。
2. 接入应用发现：HTTP 标题、应用特征资源和 WhatWeb/httpx 技术指纹组合识别；移除本机 IP 即 DVWA 的假设。
3. 贯通画像：记录传输形态、应用名称、置信度、证据、根路径和扫描时间。扫描推荐、pipeline、预检及执行共享同一来源。
4. 拆分变量检查：静态检查验证变量来源和先后依赖；逐步执行检查真实认证会话。无登录生产者、顺序错误或登录失败时禁止执行依赖步骤。
5. 验证及部署：使用隔离数据库和 HTTP 仿真验证，完成远程只读指纹验证后再安排生产部署，不自动运行主动漏洞测试。

## 验收场景

- `http://192.168.1.111:4280` 能通过应用证据识别 DVWA，不需要主机白名单。
- 普通 PHP 网站、仅有 PHPSESSID 或 login.php 的网站不误判为 DVWA。
- HTTPS、非标准端口、子目录部署保留正确协议和应用路径。
- Nmap 不接收完整 URL；输入错误和工具失败不再显示全部扫描完成。
- 未知目标不匹配 DVWA 专用 Playbook；LLM 结论不能替代指纹证据。
- 登录前允许声明后续生成的会话；登录失败、缺少生产者、消费顺序错误会阻断依赖步骤。
- Cookie 不使用占位值、不写入公开运行画像；认证重定向不允许越出指定目标。

## 部署约束

保留当前未提交改动；数据库迁移须先备份。当前开发机无法访问靶场时，通过服务器进行只读 GET 指纹验证，不把本地模拟结果当作服务器端到端验收。

## 已实现

- `targetDiscovery.js` 统一地址规范化和证据画像；HTTP 探测限制 8 秒、64 KiB 响应、5 次同源重定向。DVWA 需专用技术插件，或页面标题与产品资源/正文相互佐证，PHP、Cookie 和标题单独出现不成立。
- pipeline 对 Web 目标执行端口扫描、应用发现、网站扫描。分析、AI 生成、推荐、预检和执行读取真实画像；AI 生成接收整组扫描，而非仅第一条端口扫描。未知目标不接受模型虚构的 DVWA 类型。
- 最新同目标应用观测覆盖旧结果，缓存保留 30 分钟；兼容 SQLite UTC 时间。保留 HTTPS、非标准端口及子目录，移除 localhost/容器 IP 的 DVWA 强制映射。
- 新增步骤输入/输出契约。预检允许先登录后消费 Cookie；执行只使用已验证登录产生的会话，缺失、登录失败、顺序错误及静态载荷注入都会阻断依赖步骤。Playbook 的硬编码地址不能覆盖目标画像。
- 扫描全部失败为 `FAILED`，成功与失败混合为 `PARTIAL`，逐工具保存失败原因并在客户端显示。普通网站扫描不盲目调用 SQLMap，仅显式提供同目标注入端点时调用。
- 数据库迁移 `020_scan_target_profile.js` 增加扫描画像、步骤契约及 `PARTIAL` 状态，回填现有 Golden DVWA 登录契约；兼容重建扫描任务表时的索引、触发器和外键。

## 修改复查（2026-10-08）

本次重新沿扫描、画像、预检、生成、执行和客户端列表检查，发现此前边界验证不充分，已修正以下问题：

1. **应用根路径不稳定**：无尾斜杠的子目录会被截断；后来的主站技术指纹可能覆盖子目录画像；直接输入漏洞页面时，漏洞目录被误当作应用根目录。现在保留目录路径，按同源、应用范围和证据强度选择画像，登录页及漏洞页回到正确应用根目录。兼容输入空格和协议大小写。
2. **失败重扫复用旧画像**：此前只查询成功任务，新的失败或运行中应用发现不能撤销旧指纹。现在最新应用发现优先，即使失败或运行中也不回退旧应用证据；同秒任务按任务 ID 排序，并拒绝过期或未来时间。显式指定历史任务时仍按指定任务范围读取。
3. **会话依赖漏检及上下文不一致**：SQLMap 使用字面 URL 时可能通过预检，但执行需要真实会话；载荷变量还可能覆盖画像中的目标地址。现在把 DVWA SQLMap 的会话作为隐式依赖，Cookie 消费需要已验证会话，重新登录清除旧输出。编译和校验采用一致的目标变量保护规则，仍允许明确配置用户名和密码。
4. **发现结果与应用兼容性遗漏**：WhatWeb 未保存 HTTP 状态，错误页面的插件结果可能参与识别；空输出可能误算成功。现在保存状态并排除错误页面，空发现结果记录失败。应用适配器保留 HTTPS、端口和路径，通用 Web Playbook 兼容已识别的 Web/API/SPA 类型，但不能借此升级为 DVWA；云目标提示不被通用 HTTP 探测覆盖。
5. **契约保存与 AI 生成一致性不足**：非法契约 JSON 可在主记录插入后抛错，留下不完整 Playbook。现在接口先校验契约，主记录和步骤原子保存；生成结果校验结构、变量依赖及生产者顺序，保存配置变量，正确保留应用类型。生成方案不完整时返回明确错误，pipeline 可回退到已有 Playbook。
6. **客户端遗漏应用发现任务**：新增的 `app_discovery` 未映射到扫描表。现在归入网站扫描列表，提供中文类型提示，纳入计数、选中状态恢复和运行轮询。
