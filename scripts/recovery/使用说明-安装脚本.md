# RedTeam-Platform 服务端恢复入口

此脚本按 2026-10-30 在 .200 实际核对的 **12-RedTeam-Platform** 备份编写。只新增恢复入口，不修改备份归档。13-CScan-20261029 是本项目专用代码扫描服务，独立恢复脚本已有；不恢复其他 PentAGI/PentAGI-V3 服务。

## 在新服务器操作

需要 Ubuntu 24.04 x86_64（13号安装器的明确要求）、Python 3.12、systemd、Docker Engine 和 Compose。保留 aistation 用户及 /home/aistation，且该用户能访问 Docker。脚本检查这些依赖，不自动升级操作系统、安装系统依赖或改变用户组。Docker 数据盘还需容纳展开后的工具/CScan镜像；不能仅按压缩包大小安排空间。

在新服务器登录用户的目录执行以下命令，首次连接需核对 .200 的 SSH 指纹：

```bash
mkdir -p ~/redteam-recovery
scp -r user3@192.168.1.200:/home/user3/桌面/服务器备份/aistation2-restore/12-RedTeam-Platform ~/redteam-recovery/
scp -r user3@192.168.1.200:/home/user3/桌面/服务器备份/aistation2-restore/13-CScan-20261029 ~/redteam-recovery/
cd ~/redteam-recovery/12-RedTeam-Platform
bash install.sh
sudo bash install.sh --apply --with-cscan
```

`bash install.sh` 默认只检查备份校验和。`--apply --with-cscan` 恢复主后端并调用13号安装器。若CScan已经恢复且验收通过，使用 `sudo bash install.sh --apply`，不要重复导入数据库。历史worker不自动重新执行；如确有恢复需求，遵循13号说明另行验收。

## 行为与冲突处理

- 先验证备份，再检查架构、用户、Docker、端口和目标文件是否冲突。已有 `/opt/RedTeam-Platform` 或后端服务单元时停止；不能用删除数据或强制覆盖来绕过。
- 归档先在 `/var/tmp/redteam-restore-*` 的私有目录安全解压，核验SQLite副本、Node哈希、原生依赖与服务启动路径，再安装。
- 恢复主项目、正式库及四份历史SQLite快照、原Node版本、11个rt工具镜像和后端systemd单元；启动健康检查成功后设置开机启动。原Node系统路径不会被替换。
- 备份原件不删除。失败不自动删除已恢复目录、镜像或CScan；健康检查失败则停止本次启动的后端。暂存目录保留用于排查，不能无检查地重复安装。
- SSH、Cloudflare、自动更新、网络配置不自动恢复，避免旧认证/地址覆盖新机。其配置仍在备份中。脚本不会自动恢复旧扫描进程。
- 本地健康检查不等于全功能验收。还需在 .112 检查连接、登录、历史任务/报告、工具执行、CScan及外部模型连接。

## 验证范围

脚本需通过语法和拒绝路径/冲突的测试，并对实际备份执行只读校验与暂存恢复检查。未在重装后的真实服务器执行安装，不宣称全栈恢复演练通过。
