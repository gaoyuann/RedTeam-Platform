# 演示流程分析（验收 6 点 × AI 驱动渗透流程）

> 记录时间：2026-09-27
> 背景：缕清验收 6 个功能点在真实渗透测试流程中的位置，为演示动线提供依据。
> **核心结论：6 个验收点是 AI 自主流程的观测窗口，不是人的操作步骤。**

---

## 一、最关键的认知转变

验收 6 个点不是平铺的 6 件人事，而是 **AI 自主渗透流程上的 6 个观测窗口**。演示的正确姿态是"人输入目标 IP，AI 自己走完 6 个点，人在关键节点确认"，不是"人去操作 6 个功能"。

平台后端已有 AI 自主串联能力（[pipelineEngine.js](../backend/src/services/pipelineEngine.js) 的 `scan→analyze→generate→execute` 四阶段编排），演示应以此为主线，而非管理员分模块手动操作。

---

## 二、① 和 ② 的区别（被测对象粒度不同）

两个点看似都在"攻击演示"，但被测对象的粒度不同，对应渗透测试里两个不同的攻击面：

| | ① 被测软件端 | ② 目标靶机端 |
|---|---|---|
| **被测对象** | 一个软件系统 / 应用（有源代码的那套系统本身） | 一台靶机（操作系统 + 部署的服务栈 + 运行的应用） |
| **测试视角** | 应用层 / 代码层（白盒或灰盒） | 主机层 / 网络层（黑盒） |
| **典型漏洞** | SQL 注入、XSS、文件上传、反序列化、越权、SSRF | 弱口令、服务漏洞（SMB/RMI/SSH）、配置缺陷、内核提权 |
| **典型工具** | nuclei、sqlmap、nikto、ffuf、whatweb | nmap、hydra、evil-winrm、metasploit 类 CVE 利用 |
| **攻击终点** | 演示该漏洞可被利用（拿到数据 / 篡改页面 / 执行命令） | 攻陷靶机（拿到 shell / 持久控制权） |
| **验收明确要求的流程** | 扫描 → 漏洞列表 → **逐一**攻击演示 | 攻击演示（攻陷靶机） |

一句话：**①是"对这个软件的漏洞逐个打给你看"，②是"把这台靶机打穿给你看"。** 前者强调漏洞覆盖度（逐一），后者强调攻击链贯通度（打穿）。

演示目标建议：
- ① 的被测软件 → **DVWA**（172.17.0.2，Web 应用，有 SQLi/XSS/文件上传等应用层漏洞，适合"逐一攻击演示"）
- ② 的目标靶机 → **一台多服务靶机**（如 Metasploitable 或自建靶机，开放 21/22/80/445/3306 等多个可利用服务，适合"打穿拿 shell"）

## 三、平台已有的 AI 引擎盘点

| 文件 | 在 AI 流程里的角色 |
|------|------------------|
| [pipelineEngine.js](../backend/src/services/pipelineEngine.js) | **总编排**：scan→analyze→generate→execute 四阶段串联，WebSocket 实时推送 |
| [reactEngine.js](../backend/src/services/reactEngine.js) | **执行阶段大脑**：每步执行后调 LLM，输出 continue/adjust/insert/parallel/stop 决策 |
| [knowledgeEnricher.js](../backend/src/services/knowledgeEnricher.js) | **给 LLM 喂知识**：把 MITRE 技术、OWASP Top10 注入 ReAct prompt |

| [preflightGate.js](../backend/src/services/preflightGate.js) | **执行前校验**：目标合法性、容器引擎、模板变量 |

## 四、AI 驱动流程图 + 人机边界

```
人输入目标 IP  ←  全程唯一的人工输入
     │
     ▼
┌─────────────── AI 自主编排（pipelineEngine）────────────────┐
│                                                            │
│  ⑤ 拓扑探测 (nmap)                                          │
│       │                                                     │
│       ▼  LLM 解析 → 生成拓扑结构 + 标注潜在攻击面            │
│                                                            │
│  扫描 (nuclei/sqlmap/hydra…，按目标自适应选工具)             │
│       │                                                     │
│       ▼  LLM 分析扫描结果 → 产出漏洞列表 (①要的"列表")       │
│                                                            │
│  ┌──── 人工确认点 ────┐  ← 扫描→攻击 转换                    │
│  │ 人看一眼漏洞列表    │     全程唯一需要人拍板的节点          │
│  │ 确认开始攻击        │     （兼顾可控性，不是手动操作）      │
│  └────────────────────┘                                    │
│       │                                                     │
│       ▼  LLM 生成攻击方案 (Playbook)                         │
│                                                            │
│  ①② 攻击执行 (ReAct 引擎，逐漏洞/逐入口)                     │
│   · 每个漏洞：LLM 选 payload (③ HexStrike 规则 / LLM 定制)   │
│   · 每步执行后：LLM 观察→思考→行动                           │
│     - continue / adjust(改参重试) / insert(插新步骤)         │
│     - parallel(并行插) / stop(提前终止)                     │
│   · 失败自动 pivot：这条路径打不通，AI 自己换方向             │
│                                                            │
│  ④ 结果统计 + 报告生成                                       │
│   · Score V2 规则评分 + MITRE 覆盖率                        │
│   · LLM 生成报告文字部分                                     │
│                                                            │
└────────────────────────────────────────────────────────────┘
     │
     ▼
人看报告  ←  全程第二个人工动作
```

**人机边界**（"智能化"的真正含义）：

| 人做的 | AI 做的 |
|--------|---------|
| 输入目标 IP | 拓扑绘制 + 攻击面标注 |
| 扫描→攻击转换确认（看一眼漏洞列表） | 扫描结果分析 + 漏洞列表生成 |
| 看报告 | 攻击方案生成 + payload 生成 + 自适应执行 + 报告生成 |

人全程只动手 3 次，剩下全是 AI 自主。

## 五、大模型在 6 个验收点的具体作用

| 验收点 | 没有AI时人要做什么 | 大模型接管后 | 代码位置 |
|--------|------------------|------------|---------|
| ⑤ 拓扑 | 人看 nmap XML，脑补拓扑 | LLM 解析结果生成拓扑结构 + 推断 OS/服务/攻击面标注 | pipelineEngine + 拓扑生成 |
| ① 扫描+列表 | 人跑扫描，人整理漏洞表 | LLM 分析扫描结果，结构化漏洞列表 + 严重度排序 + 可利用性判断 | scanAnalyzer.js |
| ② 靶机扫描 | 人挑入口，人想攻击链 | LLM 推荐可串成链的入口 + 生成攻击方案 | pipelineEngine STEP_GENERATE |
| ③ 载荷生成 | 人查 payload 库，人改 payload | **两种方式都是 AI 选**：规则能覆盖用 HexStrike，需绕过滤用 LLM 定制 | reactEngine + llmClient |
| ①② 攻击执行 | 人按脚本一步步跑，失败就卡住 | ReAct 每步 LLM 决策，失败自动 pivot，动态插步/改参 | reactEngine.js |
| ④ 结果统计 | 人写报告 | 规则评分 + LLM 生成报告文字 + MITRE 覆盖分析 | Score V2 + 报告生成 |

**③ 不是独立步骤，是 ReAct 执行时"造弹药"的动作**。AI 自己判断规则 payload 够不够，不够就让 LLM 生成定制。演示时嵌在攻击执行里口述即可，不单独演示。

## 七、AI 驱动演示动线

**【0. 开门】⑥ 加密锁**
插入加密狗 → 平台校验锁 → 通过进入主界面；拔锁后关键功能受限。（软件能用前提，单独演示一次。）

**【1. 人输入目标 IP】** — 全程唯一人工输入
输入目标网段（如 172.17.0.0/24），后续全由 AI 自主。

**【2. ⑤ 拓扑探测】AI 自主**
nmap 主机发现 → LLM 解析生成拓扑图 + 标注攻击面 → 拓扑上看到两台目标：DVWA（①）+ 多服务靶机（②）。

**【3. 扫描】AI 自主**
- 对 DVWA 跑 Web 漏洞扫描（nuclei/sqlmap/nikto）→ LLM 分析产出**漏洞列表**（① 要的"列表"）
- 对靶机跑端口/服务/弱口令扫描 → LLM 推荐可串成链的入口

**【4. 人工确认点】** — 全程唯一人工拍板
人看一眼漏洞列表，确认开始攻击。（兼顾可控性，不是手动操作。）

**【5. ①② 攻击执行 + ③ 载荷生成】AI 自主（ReAct 引擎）**
- ① 对漏洞列表**逐一**攻击：每个漏洞 LLM 选 payload（HexStrike 规则 / LLM 定制）→ 执行 → 每步 LLM 观察-思考-行动 → 失败自动 pivot
- ② 串成攻击链攻陷靶机：vsftpd 后门 / SSH 弱口令 / Samba RCE → 拿 shell → 提权 → 持久化

**【6. ④ 结果统计】AI 自主**
Score V2 评分 + MITRE 覆盖率 + 证据表 + LLM 生成报告（DOCX/PDF/HTML）。

**【7. 人看报告】** — 全程第二个人工动作

## 八、演示姿态转变

| 错误姿态 | 正确姿态 |
|---------|---------|
| 人操作 6 个功能点，像功能巡检 | 人输入 IP，AI 自主走完 6 个点 |
| 管理员分模块视角（拓扑页/扫描页/攻击页） | pipeline 驱动的一键视角（学生端"快速测试"形态） |
| 6 个验收点 = 6 个操作步骤 | 6 个验收点 = AI 自主流程的 6 个观测窗口 |
| 演示"我们会做这些功能" | 演示"AI 能自己做完这些，人只确认" |

**演示主力用 pipeline 驱动的动线**（学生端"一键快速测试"形态），6 个验收点标注在对应阶段上。管理员分模块视角作为"专业用户可随时介入手动干预"的补充，不是主线。

## 九、当前真实差距

1. **AI 自主串联已通**：pipelineEngine 的 scan→analyze→generate→execute 可工作，学生端一键测试能跑通。
2. **ReAct 自适应已实现**：每步 LLM 决策、失败 pivot、动态插步都有。
3. **但管理员界面还是三个独立模块**（拓扑/扫描/攻击分页），admin 界面演示时显得割裂——这是文档 P0 优化"三阶段合并为统一工作台"要解决的事。
4. **演示建议**：验收时**用学生端一键形态做主线**（体现 AI 自主），**用 admin 形态做辅线**（体现人可干预）。别只用 admin 分模块演示，那样 AI 的存在感被界面切没了。

## 十、要跟老师对齐的认知

1. **① 和 ② 不是两套独立功能，是同一套 AI 流程换目标。** 演示时用两个不同目标分别走一遍即可。

2. **③ 是 ①② 的子环节，不是独立步骤。** 载荷生成嵌在攻击执行里，AI 自己选 HexStrike 规则还是 LLM 定制。演示时口述即可，不单独演示。

3. **⑤ 拓扑探测是流程起点。** 真实流程是"先看见目标，再打目标"。P0 优化"三阶段合并为统一工作台"正是此意——拓扑→扫描→攻击一次目标输入贯穿到底。

4. **⑥ 加密锁是平台自身的授权机制，和渗透测试业务逻辑无关。** 单独演示一次（插锁/拔锁）即可。目前是未实现的壳，需规建议可替代为"软件许可证验证"——需跟老师确认是否接受软许可替代硬件狗。

5. **① 的"逐一"是关键词。** 扫描出 N 个漏洞，N 个都要演示攻击，哪怕打不通也要演示"尝试攻击→未成功"。这影响演示时长和报告粒度，提前要有数。
