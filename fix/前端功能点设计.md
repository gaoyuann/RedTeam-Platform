# 前端功能点设计（任务驱动重构）

> 记录时间：2026-09-27
> 背景：当前前端功能联系太分散，任务中心定位有问题。按 AI 驱动测试流程重新组织前端功能点。
> 角色说明：当前仅 admin / user 两个角色，演示只用 admin，暂不深入角色权限设计。
> 状态：**仅设计，未改代码。**

---

## 一、当前前端的问题诊断

当前 admin 导航 7 项：

```
任务中心 │ 漏洞利用想定与预案 │ 网络拓扑探测与绘制 │ 脆弱性扫描 │ 漏洞攻击测试 │ 测试评估 │ 系统管理
```

问题不在某个页面做得烂，而在**组织方式错了**——把"流程的各阶段"当成"平级独立模块"摆上导航栏：

1. **流程类模块和任务中心割裂**：任务中心跑的 pipeline（scan→analyze→generate→execute）和拓扑页/扫描页/攻击页/评估页是各跑各的，不共享上下文。任务中心跑完，想看拓扑要跳到拓扑页，拓扑页还不知道你在测哪个目标。
2. **同一目标重复输入**：拓扑页输一次 IP，扫描页输一次，攻击页又输一次——这是 P0 说的"操作割裂"。
3. **任务中心被当成普通模块**：它和其他 6 项平级，但它其实是主入口，应该吃掉流程类模块。
4. **Playbook/载荷被当成独立功能**：它们是流程里的产物/子动作，不该占一级导航。
5. **导航太宽**：7 个一级，流程类占 4 个，管理类散在两端，用户进来不知道从哪开始。

本质：**当前是"功能结构图视角"（把需规的模块平铺），不是"使用流程视角"（以任务为主线）**。

---

## 二、设计原则

1. **任务是主线**：一切围绕"一个测试任务从创建到报告"，不是"打开某个工具页"
2. **阶段是 Tab，不是导航项**：拓扑/扫描/攻击/评估是同一任务的 4 个阶段视图，共享目标上下文，数据自动传递
3. **AI 自主有落地视图**：ReAct 思考链、阶段进度、人工确认门都在任务工作台里，不跳页
4. **管理类归一边**：系统管理/资源部署/加密锁/知识库不干扰流程主线
5. **7 → 3**：一级导航砍到 3 个，流程类全合并进"测试任务"

## 三、新的前端功能点设计

### 一级导航：3 项

```
测试任务  │  预案与知识库  │  系统管理
```

---

### ① 测试任务（主入口，吸收原 任务中心+拓扑+扫描+攻击+评估）

布局：左侧任务列表 + 右侧任务工作台

| 二级功能点 | 说明 | 验收点 |
|-----------|------|--------|
| 1.1 任务列表 | 新建/进行中/历史/归档，单击进工作台 | — |
| 1.2 新建任务 | 输入目标 IP/网段 + 选被测类型（软件端①/靶机端②）+ 是否需人工确认 | — |
| 1.3 阶段① 拓扑视图 | nmap 结果 + 拓扑图 + 资产清单 + AI 标注攻击面 | ⑤ |
| 1.4 阶段② 扫描视图 | 漏洞列表（严重度/位置/CVE/可利用性）+ AI 排序 | ①② 扫描 |
| 1.5 人工确认门 | 扫描完→人看漏洞列表→确认开始攻击（全程唯一人工拍板点） | — |
| 1.6 阶段③ 攻击视图 | 逐漏洞攻击进度 + **载荷来源标注**（HexStrike/LLM）+ ReAct 思考链 + 失败 pivot 记录 | ①② 攻击 + ③ |
| 1.7 阶段④ 评估视图 | Score V2 评分 + MITRE 覆盖 + 证据表 + 报告导出 | ④ |
| 1.8 实时活动日志 | WebSocket 推送，贯穿所有阶段 | — |

**关键**：1.3~1.7 是同一任务的 4 个 Tab，**共享目标上下文，阶段间数据自动传递**（拓扑发现的主机 → 扫描目标 → 攻击目标，不用重输）。6 个验收点全在这一个一级导航里串完，不跳页。

### ② 预案与知识库（辅助，原 Playbook 页 + 知识图谱 + 载荷库）

| 二级功能点 | 说明 | 来源 |
|-----------|------|------|
| 2.1 Playbook 库 | 列表/详情/编辑/删除，按基线分组 | 原"漏洞利用想定与预案" |
| 2.2 AI 生成预案 | 独立生成入口（不依赖任务，给专业用户） | 原 PlaybookPage 的 AI 生成 |

| 2.4 载荷样本库 | HexStrike 载荷库浏览 | 原 PayloadPage |

**定位**：这是"弹药库"，不是流程主线。平时不用，要查/改预案时才进。

## 五、6 个验收点在新结构的落点

```
测试任务
 ├─ 1.3 拓扑视图        ← ⑤
 ├─ 1.4 扫描视图        ← ①② 的扫描
 ├─ 1.6 攻击视图        ← ①② 的攻击 + ③（载荷来源标注）
 └─ 1.7 评估视图        ← ④

 └─ 3.3 加密锁验证      ← ⑥
```

演示动线：进"测试任务"→ 新建任务输 IP → AI 自动跑（拓扑→扫描→确认→攻击→评估）→ 全在一个工作台里看完 → 导出报告。**6 个点一条线，零跳页。**

## 六、任务工作台内部结构（核心，展开）

```
┌─ 测试任务 ──────────────────────────────────────────────┐
│ ┌─ 任务列表 ──┐  ┌─ 任务工作台 ────────────────────────┐│
│ │ ＋新建任务   │  │ 目标: 172.17.0.2  状态: 攻击中       ││
│ │ ─────────── │  │ 类型: 软件端①  创建: 09-27 14:30    ││
│ │ ▸ DVWA测试  │  │ ──────────────────────────────────  ││
│ │   靶机攻陷  │  │ [拓扑] [扫描] [攻击] [评估]  ← 阶段Tab││
│ │   历史任务  │  │ ──────────────────────────────────  ││
│ │   ...       │  │                                     ││
│ │             │  │  （当前阶段内容区）                  ││
│ │             │  │                                     ││
│ │             │  │ ──────────────────────────────────  ││
│ │             │  │ 实时活动日志 (WebSocket)             ││
│ └─────────────┘  └─────────────────────────────────────┘│
└─────────────────────────────────────────────────────────┘
```

- 顶部：目标信息 + 状态 + 类型（软件端①/靶机端②）
- 中部：4 个阶段 Tab，数据随任务推进自动填充，阶段间不重输目标
- 底部：实时活动日志贯穿所有阶段
